# Ручная проверка админки на настоящем бэкенде

- **Дата:** 2026-10-07 (программа 032, срез S4; заменяет ручную проверку на mock-сценариях из 022 `T2206`).
- **Статус:** действующий чек-лист. Автоматическая часть — `admin-ui/e2e/` через `scripts/verify_admin_e2e.ps1`; этот документ покрывает то, что глазами проверяет человек.

У админки нет mock-режима: все экраны читают настоящий API. Отказ сервера, описанный в контракте, — **ожидаемый результат** проверки, а не дефект: в таблице он стоит в колонке «Ожидаемо» наравне с успехом.

## Подготовка

1. Поднять бэкенд с засеянной базой: `.\scripts\run_local.ps1 -Action start` (пустая база сеется рецептом сообщества; вручную — `scripts/seed_db.py --source recipe --community riverside-town-50` на пустую базу `geov0_dev_<slug>`).
2. Админку — `npm --prefix admin-ui run dev` с `VITE_API_BASE_URL=http://127.0.0.1:18000` (по умолчанию в dev) и `VITE_ADMIN_TOKEN`, равным `ADMIN_TOKEN` бэкенда; без `VITE_ADMIN_TOKEN` dev-сервер берёт dev-токен бэкенда по умолчанию.
3. **Устаревший сохранённый токен.** Токен из `localStorage` (`admin-ui.adminToken`) используется, только если `VITE_ADMIN_TOKEN` не задан. Если бэкенд перезапущен с другим `ADMIN_TOKEN`, каждый экран показывает ошибку 403 с подсказкой про токен. Восстановление: в DevTools `localStorage.removeItem('admin-ui.adminToken')` и перезагрузка, либо задать `VITE_ADMIN_TOKEN` и перезапустить dev-сервер. Сборка для production без токена отказывает любой админский запрос ошибкой 401 `ADMIN_TOKEN_MISSING` ещё до отправки.

## Состояния, которых нет в сиде

Сид не содержит закрытой линии и неактивного эквивалента (032, «Не входит в S4»). Их получают операцией:

- **Закрытая линия доверия** — в Simulator UI в режиме real: Interact → действие закрытия линии доверия над выбранным ребром (кредитор закрывает свою линию). После этого линия видна в Trustlines с фильтром статуса `closed`.
- **Неактивный эквивалент** — в админке: Equivalents → «Деактивировать» с причиной. Обратное действие — «Активировать».

## Чек-лист по экранам

| Экран | Действие | Ожидаемо |
|---|---|---|
| Dashboard | открыть | счётчики участников и последние записи аудита из базы; карточки без ошибок |
| Liquidity | открыть, выбрать эквивалент | суммы только внутри выбранного эквивалента; без эквивалента денежных сумм нет (028 F-028-37) |
| Integrity | открыть; «Проверить» | статус по каждому эквиваленту; `zero_sum` — «не проверяется» (014 `T1402`); после проверки статус перечитывается |
| Incidents | открыть | пустой список — так сервер отвечает с программы 019, это не ошибка загрузки |
| Trustlines | фильтры по эквиваленту, кредитору, должнику, статусу | фильтры точные: часть PID или код в нижнем регистре дают пустой список; статус вне `active`/`closed` — отказ 422 |
| Graph | открыть, сменить эквивалент, открыть узел и ребро | граф сида; карточка узла и ребра открываются и с клавиатуры |
| Participants | поиск, фильтры; «Заморозить» и «Разморозить» с причиной | поиск без учёта регистра; после заморозки статус `suspended` и кнопка «Разморозить»; запись в Audit Log |
| Config | изменить ключ и сохранить; вернуть значение | «Сохранено (1 ключ)», значение перечитано; запись `admin.config.patch` в Audit Log. Ключи, читаемые только при старте, не предлагаются (029 F-029-4) |
| Config | открыть `/feature-flags` | переход на Config: флаги — ключи конфигурации |
| Audit Log | поиск, фильтр действия | записи новее — выше |
| Equivalents | создать, изменить описание, деактивировать, удалить неиспользуемый | каждое действие — запись аудита; удаление активного эквивалента — отказ 409 «Deactivate equivalent before delete»; используемого — 409 «Equivalent is in use» со счётчиками |
| Equivalents | создать эквивалент с существующим кодом | отказ 409 `code_exists` после исправления 032 A-2 (срез S1); до него — 500, известная находка |
| любой | остановить бэкенд и обновить экран | ошибка загрузки с текстом сетевой ошибки, а не пустая таблица; в шапке — статус здоровья «ошибка» |

## Что этот чек-лист не покрывает

Он не проверяет денежную семантику — её держат backend-тесты; и не заменяет `admin-ui/e2e/`, где редкие ответы (500, 403, 401, пустой список, `warning`/`critical` целостности, медленный ответ) подставляются через `page.route`.
