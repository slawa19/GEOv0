# GEO Simulator Frontend — QA-стенд: что он видит и чего не видит

Статус: Stable
Область: simulator/frontend
Последнее обновление: 2026-10-19

Стенд — второй набор браузерных проверок Simulator UI v2 (программа [038](../../../../../specs/038-simulator-ui-qa-stand/spec.md)). Он гоняет продукт **так, как его видит пользователь**: без тест-режима, с анимацией, физикой, перетаскиванием и сном цикла рендера. Стенд снимков (`e2e/*.spec.ts`, `VITE_TEST_MODE=1`) всё это выключает и поэтому остаётся отдельным; стенд его не заменяет и его снимки не трогает.

Документ описывает границы инструмента. Зелёный прогон стенда говорит только о том, что перечислено в разделе 3; обо всём из раздела 5 его молчание не говорит ничего (AGENTS.md §12).

## 1. Чем стенд отличается от браузера пользователя

Отличий ровно четыре, других нет и продуктовых веток «я под стендом» нет:

1. Vite dev-сервер — ради dev-хука `window.__geoSim` (read-only геттеры раскладки, камеры, состояния FX).
2. Бэкенд целиком подменён на `page.route`; поток событий — незакрывающийся SSE-поток, в который тест пишет кадры. Каждый байт проходит продуктовые парсер, нормализатор и pipeline.
3. `page.clock` — в детерминированных проверках время (таймеры, `requestAnimationFrame`, `performance.now`) шагает по команде теста. CSS-анимации меток ставятся на те же часы отдельно.
4. Chromium запущен без GPU (`--disable-gpu`, `--disable-accelerated-2d-canvas`, `--disable-gpu-compositing`) и без признака автоматизации (`--disable-blink-features=AutomationControlled`): под `navigator.webdriver = true` продукт прячет искры под базовую канву и выключает hover рёбер.

Стенд сам отказывается идти, если в странице `__geoSim.isTestMode !== false` или `navigator.webdriver !== false` (`simulator-ui/v2/e2e/qa/stand.ts`, `assertUserMode`).

## 2. Команды

Все — из корня репозитория. Порт задаётся `PW_E2E_PORT` (не 24731–24738: они заняты CI), каталог вывода — `GEO_SIMULATOR_PLAYWRIGHT_OUTPUT_DIR` (по умолчанию `.local-run/playwright/simulator/qa`).

| Что нужно | Команда |
|---|---|
| Обязательное подмножество, как в CI, со счётом и HTML-отчётом | `npm --prefix simulator-ui/v2 run test:e2e:qa:gate` |
| Весь функциональный стенд: плюс галерея обеих тем и остальные viewport, с HTML-отчётом | `npm --prefix simulator-ui/v2 run test:e2e:qa:report` |
| Срез при отладке — **debug-only, не гейт** | `npm --prefix simulator-ui/v2 run test:e2e:qa -- --grep "<часть имени>"` |
| Видео для человека (луч, выцветание, перетаскивание) и кадры пустого экрана; не проверка продукта | `npm --prefix simulator-ui/v2 run test:e2e:qa:video` |
| Гарды проводки стенда | `.\scripts\verify_local.ps1 -TaskSlug <slug> -ToolingOnly -ToolingPartition portable` |

**Про срез при отладке (с 2026-10-12, программа 039, срез A).** `test:e2e:qa` — это режим `debug` того же раннера `e2e/qa/run-stand.mjs`, а не голый `playwright test`, как было раньше: тогда прогон никем не судился, а его «N passed» читался как результат стенда. Список аргументов после `--` **закрытый** (`debugArgProblems` в `e2e/qa/run-verdict.mjs`): фильтры по имени файла, `--grep`/`-g`, `--grep-invert`, `--repeat-each`, `--workers`/`-j`, `--max-failures`, `--timeout`, `--trace`, `--headed`, `--debug`, `-x`, `--list`, `--pass-with-no-tests`, `--last-failed`. Всё остальное отвергается до запуска — в том числе отдельный `--` (терминатор опций), `--config`/`-c`, `--project`, `--reporter`, `--output`, `--retries`, `--shard`, `--update-snapshots`: срез всегда из считаемого проекта `qa-stand`, по конфигу стенда и в собственные файлы. Первая форма режима (отвергались только `--project` и `--config`) обходилась: `debug --reporter=json,html -- console-guard` исполнял тест обычного стенда снимков по `playwright.config.ts`, завершался с кодом 0 и затирал HTML-отчёт последнего прогона гейта (воспроизведено 2026-10-12 по внешнему ревью `0d0deae3`). Собственные опции стенда теперь стоят в командной строке первыми во всех режимах. Первая и последняя строка прогона начинаются с `run-stand [debug]: DEBUG-ONLY, NOT A GATE`; число исполненных тестов ни с чем не сравнивается, слова `recorded` в итоговой строке нет, HTML-отчёт не пишется, JSON-результат лежит в `<каталог вывода>-debug-result.json`, переменные HTML-репортёра указывают на `<каталог вывода>-debug-report` — результат и отчёт считаемого прогона срезом не затираются. Код выхода ненулевой при упавшем тесте, при фильтре, не выбравшем ни одного теста (в том числе с `--pass-with-no-tests` и с `--list`), при skip и при flaky. Зелёный срез доказывает только себя: **результатом стенда считается только строка `run-stand [gate]: … recorded N` или `run-stand [full]: … recorded N`** (AGENTS.md §5: debug path не заменяет canonical). Считаемые входы фильтр не принимают — `test:e2e:qa:gate -- --grep …` отказывает до запуска. Чтобы только перечислить тесты без запуска: `npx playwright test --config=e2e/playwright.qa.config.ts --project=qa-stand --list` из `simulator-ui/v2`.

## 3. Что стенд проверяет

### 3.1 Движение и взаимодействие (срезы S0–S1)

Положение луча во времени по пикселям fx-канвы и по скриншоту композиции; порядок рёбер; отсутствие свечения вне маршрута; время жизни меток на одних часах с JS; перенос узла на дельту мыши, делённую на zoom, закрепление в физике и подавление клика после перетаскивания; ноль отрисовок в покое и пробуждение событием; пустые канвы после отказа загрузки другого источника.

### 3.2 Окна и меню (срез S2)

Запись — то, что открывает пользователь, а не тип каталога: один тип `wm-interact-window` — это три окна действий и окно с отказом клиринга (`clearing-refused`); тип `hud-dropdown` с 048 S2 не имеет экземпляров (прежние четыре меню — «Advanced» и «Dev Tools» 043 S3, «Artifacts» 048 S1, «Admin ▾» 048 S2 — удалены).

Что делается с каждой записью:

- **в каждой из двух тем приложения — `saas` (по умолчанию) и `hud`, 1366×768** — связь с каталогом, прямоугольник против viewport, размер элементов управления (не меньше 24×24 CSS px), axe (WCAG 2.1 A/AA) и объявленные политики;
- **в тех же двух темах, 1920×1080 и ресайз до 1024×640** — прямоугольник против viewport. Для меню панелей и списков `OverlaySelect` (их место считает скрипт в момент открытия, проверка стоит около секунды) это часть обязательного теста; для окон менеджера и поверхностей, поставленных одним CSS, — отдельный тест с меткой `@extended`: после каждого ресайза граф раскладывается заново, и на окно уходит несколько секунд, а у обязательного шага бюджет времени;
- **в тех же двух темах** — кадр на установившемся графе и axe, метка `@extended`: это галерея для человека.

Темы `shadcn` и `library` заморожены (решение владельца Р1; программа 039, срез B, решение 6): их токены в таблице стилей остались, но приложение их не предлагает, и матрица их не проходит (с 2026-10-16; до этой даты обязательный тест матрицы шёл в `hud`, а галерея — в четырёх темах). Тесты-контрпроверки и политика «карточка из навигатора: Escape возвращает фокус на «Открыть участника»» по-прежнему идут в `hud`. Тесты политик меню `Admin` («при загрузке прогонов Escape и Tab») и «карточка поверх открытого меню» удалены 048 S2 вместе с меню — удалён контракт, открывать нечего; политика клавиатуры меню остаётся в модульном `useHudDropdownFocus.test.ts`, а скан экземпляров по-прежнему краснеет на меню без записи (контрпроверка «пятое меню» — `counter-check: injected surfaces`).

**Связь с каталогом — в обе стороны.** Каждый ключ `src/ui-kit/overlaySurfaceCatalog.ts` представлен в матрице или поимённо исключён с причиной и датой (`EXCLUDED_FROM_MATRIX`; сейчас в нём одна запись — `hud-dropdown`, 2026-10-19: экземпляров не осталось). Обратно: всё, что лежит поверх сцены — дочерние элементы `.root`, телепортированное в `body`, оболочки окон, выпадающие поверхности — должно узнаваться таблицей `SURFACE_DOM` под ключом, который в каталоге есть. Новая поверхность без записи каталога и запись, удалённая из каталога, дают красный.

**Экземпляры.** Тип в каталоге — ещё не запись матрицы: новое меню было бы `hud-dropdown`, как и прежние четыре. Поэтому в каждом обязательном тесте матрицы все меню панелей (`details.ds-ov-details`, открытые и закрытые), все окна менеджера и все списки `OverlaySelect` в DOM сверяются с записями матрицы; три списка без собственной записи названы в `SELECTS_WITHOUT_ENTRY`.

**Граница обратной проверки.** Произвольный потомок уже названного контейнера (поповер внутри верхней или нижней панели) считается частью этой поверхности и не замечается — проверено инъекцией, держится тестом `counter-check: injected surfaces`. Новая поверхность, смонтированная внутри панелей, обязана получить запись каталога и матрицы по ревью; ближайший потребитель — поверхность тура 034 S9 (легенда 039 B уже стоит внутри нижней полосы и входит в её записи).

### 3.3 Цвета данных и легенда (039, срез B, часть 1)

`e2e/qa/data-colours.qa.ts`, четыре теста обязательного подмножества, настоящие часы:

1. пять токенов `--ds-data-*` дают **одно** значение под каждой темой — переключением через переключатель и атрибутом для каждого идентификатора темы; контрпроверка — токен, который темы переопределяют, читается разным;
2. легенда называет то, что есть в сцене, в фиксированном порядке, образцы — в разрешённых цветах токенов; в сцене без хаба пункта «hub» (EN; «хаб» в русском интерфейсе) нет; строка легенды лежит внутри измеряемой нижней полосы, и опубликованная высота полосы её включает;
3. живое переключение темы само вызывает перерисовку (счётчик проходов растёт без подталкивания), и базовая канва побайтно одинакова между `saas` и `hud`; имя участника красится текстом темы;
4. канва, легенда и карточка узла читают одну палитру: токен, изменённый под работающим приложением, после следующего разрешения цветов меняет все три — и только узлы этой роли.

Чего эти тесты не видят: сравнивается базовая канва, не страница; знак в узле попиксельно не судится (его рисунок — `src/render/nodePainter.test.ts`); хороши ли сами значения цветов (контраст посчитан в [visual-language.md](visual-language.md), не измерен на кадре); пустая сцена без легенды держится на уровне компонента (`SimulatorAppRoot.interact.test.ts`).

### 3.3a Какая тема показана (039, срез B, часть 3)

`e2e/qa/themes.qa.ts`, три теста обязательного подмножества, настоящие часы:

1. первое посещение без сохранённого выбора и без `?theme=` показывает `saas` и ничего не записывает ни в хранилище, ни в адрес; переключатель предлагает ровно `saas` и `hud`;
2. сохранённый `shadcn` и `?theme=library` дают `saas`: хранилище переписано на `saas`, параметр адреса заменён на `saas`, остальные параметры целы, событие `load` одно (без перезагрузки);
3. `?theme=hud` побеждает сохранённый `saas` и хранилище не трогает; назад/вперёд: запись адреса с параметром показывает его тему, запись без параметра — сохранённый выбор, и после такого переключения палитра данных разрешается заново (образец легенды принимает токен, изменённый до перехода) и канва перерисовывается; переключение записывает `hud` в хранилище и в адрес, а `saas` — в хранилище, убирая параметр.

Чего эти тесты не видят: перезагрузку страницы (`boot()` очищает хранилище при каждой навигации — перезагрузка как первое чтение хранилища проверяется модульным тестом `src/composables/useUiTheme.test.ts`, там же все сочетания по одному); что разовая перезапись не затирает выбор, сделанный в другой вкладке между чтениями.

### 3.3b Долг «было → стало» после клиринга (039, срез D и D-fix, 2026-10-19)

`e2e/qa/debt-before-after.qa.ts`: по два теста на каждый язык интерфейса (`ru`, `en`), оба в обязательном подмножестве (меток `@extended` нет), настоящие часы, настоящие SSE-читатель, pipeline и панель:

1. фраза «клиринг: было X → стало Y» (EN: «clearing: was X → became Y») называет сумму долга сразу до клиринга и сразу после, а не «до платежа» и не «стало + погашено»; платёж пару не создаёт, не заменяет и не снимает; кадр состояния её сохраняет; клиринг, ничего не изменивший, её снимает;
2. **фраза помещается** (D-fix; закрывает §15 Codex P2 «стенд проверял, что число видно, а не что оно помещается»): фраза и обе цифры целиком в viewport и **не лежат ни на одном соседе** — другой панели, кнопке, поле, рамке легенды и её пункте, блоку «Последние действия»; нижняя полоса при этом не сдвигается и не меняет размер. Идёт на 100-узловой сцене, в обеих темах, с «Подробнее» выключенным и включённым, при 1366×768 и 1024×640; красный называет, на чём лежит фраза.

Чего эти тесты не видят: дебаунс полосы на поддельных часах, смену эквивалента, перезагрузку, неизвестный долг и точные суммы за пределами double — это уровень модульных тестов (`src/composables/debtChange.p039d.test.ts`); живой бэкенд. ## 4. Как читать HTML-отчёт

`test:e2e:qa:gate` и `test:e2e:qa:report` пишут штатный отчёт Playwright в `<каталог вывода>-report`; открыть — `npx playwright show-report <путь>` из `simulator-ui/v2`. В CI отчёт обязательного шага загружается артефактом `simulator-qa-stand-report` при любом исходе шага — зелёном, красном и по таймауту (с 2026-10-12; до этого только при падении); загрузка **пытается** выполниться всегда, но гарантии отчёта не даёт: если шаг оборван до того, как Playwright записал отчёт, артефакта не будет, и загрузка завершится успешно без него, отчёт job по расписанию `simulator-qa-stand` — артефактом `simulator-qa-stand-report-all-themes` всегда. **С 2026-10-12 (программа 039, срез A) в этом одном артефакте три каталога:** `simulator-qa-stand-report` — HTML-отчёт стенда, галерея кадров во вложениях; `simulator-qa-video-report` — HTML-отчёт прогона видео (`e2e/qa/owner.qavideo.ts`), ролики встроены в него; `simulator-qa-video` — сырой вывод того же прогона, по каталогу на тест, в каждом `video.webm` (три ролика: луч по маршруту из трёх рёбер, выцветание меток суммы, перетаскивание узла; четвёртый каталог — кадры пустого экрана). Загрузка пытается выполниться при любом исходе, но состава не гарантирует: шаг, оборванный до записи отчёта, оставит свою часть пустой. Что ролики записаны, видно в логе шага «Record the videos for the owner» (`4 passed`) и в самом артефакте; гард видит только форму job.

- Тесты матрицы называются `matrix [<тема>] <запись>: …`. Фильтр по `matrix [saas]` даёт все окна одной темы.
- Галерея — тесты `matrix [<тема>] <запись>: frame and axe`, вложение `gallery-<запись>-<тема>-1366x768.png`. Кадры обязательных тестов (`<запись>-<тема>-1366x768.png`, `…-1920x1080`, `…-resized-1024x640`) сняты без ожидания раскладки графа: линии доверия на них могут быть ещё не дорисованы, они нужны для разбора падения, а не для просмотра.
- Аннотация `038-S2` у теста — строка JSON с измерениями: прямоугольники, найденное, узлы axe и то, что axe оставил нерешённым (`axeIncomplete`).
- Тест `measurement: what lies under the HUD …` — доля экрана под HUD и узлы под ним при 1366×768 и 1280×720; это измерение для владельца, а не проверка.
- Тест `reproducer (BACKLOG 037-4 …)` помечен ожидаемо красным: это записанный дефект вне поверхности 038. Когда его починят, тест позеленеет и аннотация сама уронит прогон — её надо снять.

## 5. Чего стенд НЕ видит

Общее:

- **Вкус.** Красиво ли, читается ли, естественна ли кривая движения — судит человек по кадрам и видео. Стенд меряет, где и когда что-то закрашено, а не как это выглядит.
- **Контраст.** Над канвой axe не может вычислить фон и оставляет `color-contrast` в `incomplete` — десятки узлов на страницу. В числа `AXE_BASELINE` попадают только случаи, которые axe смог решить. Это слепая зона, а не ноль нарушений; отдельного механизма нет.
- **Настоящий GPU-драйвер, Firefox, WebKit, тач.** Единственный движок — Chromium без GPU на настольном viewport.
- **Живой бэкенд.** Ответы подставлены. Приёмка на живом бэкенде остаётся ручным шагом владельца.
- **Состав за числом.** `EXPECTED` считает тесты: замена одного теста другим под тем же числом проходит.
- **Вердикт раннера** (`e2e/qa/run-verdict.mjs`) отказывает при несовпадении счёта, нуле тестов, skip, flaky (повторы у стенда выключены) и — в обязательном подмножестве — при тесте под `test.fail`. Логику держит `run-verdict.selfcheck.mjs` на придуманных прогонах; он не запускает Playwright и не доказывает, что JSON-отчёт установленной версии имеет ту же форму.
- **Отсутствие GPU.** `boot()` отказывает, если продукт на корне пишет `data-gpu="1"`. Это вердикт самого продукта (WebGL-рендерер), а не измерение: браузер с GPU, который продукт принял бы за программный, прошёл бы.
- **Время обязательного шага.** С 2026-10-12 у шага свой `timeout-minutes: 15` (job — 30): зависший браузер роняет именно этот шаг и оставляет время на загрузку отчёта. Ориентир спеки 038 «не больше 5 минут добавленного времени» с переносом бюджетов в гейт превышен: 269–286 с на CI при 68 тестах, плюс около 85 с бюджетов (по меткам времени run 38200925497) и три новых теста; локально гейт из 80 тестов — около 330 с. С 2026-10-16 (039, срез B, часть 3: обязательная матрица окон и в `saas`) гейт — 114 тестов, локально 465 с в одном прогоне (Windows, один воркер); на CI не измерено. Что таймаут шага действительно роняет job, а шаг загрузки с `always()` не делает его зелёным, — поведение GitHub Actions; гардом и локально оно не исполняется.
- **Перенос чисел между машинами.** Пиксели, шрифты и времена сняты на одной платформе; совпадение на другой не обещано.

Доставка событий: `pushEvent` (один кадр) и `pushFrames` (пачка, для нагрузки бюджетов) возвращаются, когда цикл чтения продукта запросил следующий кусок потока после нашего — то есть обработчик кадра отработал (и для дубликата, и для отвергнутого события). Ожидание ограничено 15 секундами; `pushFrames` отказывает, если принято не столько кадров, сколько отправлено (`taken === pushed`). С 2026-10-12 (программа 039, срез A) исходов три, и «принят» — только первый:

- `read` — цикл чтения продукта вернулся за следующим куском: обработчик этого кадра завершился;
- `closed` — кусок отдан продукту, и соединение закрылось раньше, чем цикл вернулся: доставлено, обработка не показана;
- `unread` — соединение закрылось, пока кусок лежал в потоке: продукт его не получал.

До этой правки закрытое соединение подтверждало все свои кадры, прочитанные и нет, а помощник бюджетов подтверждения не ждал вовсе. Отдельно стенд слушает строку, которой продукт сообщает о перехваченном исключении обработчика (`api/sse.ts`), и отказывает в такой доставке: цикл чтения после исключения идёт дальше, и одно чтение назвало бы кадр принятым.

**Граница: что доказывает «принят».** Доказано: байты прошли через `fetch`-reader и SSE-парсер продукта, обработчик вызван для каждого сообщения куска и вернул управление. **Не доказано, что событие применено к состоянию:** обработчик может вернуться, не применив (событие другого рана или эквивалента, повтор `event_id`, сообщение, лишь положенное в буфер восстановления, эффект, срезанный ограничителем частоты), а эффекты на таймерах и кадрах анимации ещё не наступили. Изменение состояния утверждает сам тест. Не видно: обработку, которая стала бы асинхронной после возврата цикла к чтению; кадр, разбитый на несколько кусков. Исход `closed` тестом не исполнен (нужен обработчик, закрывающий собственное соединение); строка об исключении в тесте подложена, а не вызвана настоящим исключением.

Фаза часов: `boot()` ставит подменённые часы на паузу на фиксированной фазе сетки кадров 16 мс (`CLOCK_PHASE_MS = 0` в `e2e/qa/stand.ts` — фаза, на которой граница кадра совпадает с границей времени жизни). Раньше фаза была случайной, и тест R4 «искра на каждом из 75 кадров» (75 × 16 = 1200 мс, ровно жизнь луча) краснел на одной фазе из шестнадцати — это и была причина красного обязательного шага на CI (run 38152711087); ожидание доставки в `pushEvent` закрыло другую гонку, не эту. R4 теперь судит кадр по времени его отрисовки относительно срока жизни луча. Переменная `QA_STAND_CLOCK_PHASE_MS` (0–15) запускает стенд на другой фазе — инструмент диагностики; полный стенд проверен на фазах 0 и 8. Не видно: чувствительность к фазам, на которых стенд не запускали.

Движение (границы оракула S1; остатки — [BACKLOG](../../../../../specs/BACKLOG.md), пункт 038-1):

- цвет, форма и easing луча; кадры между снятыми скриншотами;
- вспышка узла получателя — её держит только юнит-тест;
- зона 46 px у каждого узла маршрута и точка пересечения двух рёбер;
- порядок рёбер (свойство 4) с 2026-10-12 (программа 039, срез A) судится по **интервалам свечения** ног, а не по числу общих кадров: интервал ноги — от первого закрашенного кадра до последнего, с дырами; первый кадр следующей ноги не раньше последнего кадра предыдущей (общих кадров интервалов — не больше `HANDOFF_FRAMES` = 1, `e2e/qa/oracle.ts`, `legOrder`), нога без единого закрашенного кадра — отказ. Допуск в один кадр — зерно оракула (один зонд на кадр); от длительности ноги и маршрута правило не зависит, оно сравнивает номера кадров. Прежнее правило пропускало ноги, светящиеся в чередующиеся кадры, и ногу, закрашенную внутри тёмной дыры предыдущей (`leg-order.qa.ts`). Правило порядка само **не судит** длину тёмного промежутка между ногами и перекрытие жизней ног при неперекрытых закрашенных интервалах. С 2026-10-18 (программа 039, срез C) эти части держат другие тесты: угасания внутри ноги больше нет (луч гаснет только у получателя, за 360 мс после прихода), и `motion-c.qa.ts` судит **передачу** (HANDOFF: тёмных кадров между ногами не больше, чем нужно голове луча, чтобы выйти из неоцениваемой зоны 46 px узла, плюс кадр зерна — граница выводится из геометрии и расписания ноги, а не из увиденных кадров), **темп** (PACE: ноги не короче 450 мс, одна скорость, ноги идут встык — без зазора и без перекрытия по расписанию FX-состояния) и **читаемость без GPU** (READABLE: луч закрашен в большинстве кадров своей ноги и с телом, а не точкой). Строго порядок по-прежнему держит и тест FX-состояния (одна живая искра), а он не видит ошибку отрисовки при верном состоянии;
- «видно на композиции» — это отличие скриншота от снимка до события: панель, появившаяся после снимка, была бы принята за луч;
- новая панель внутри уже названных контейнеров HUD исключается из проверки видимости молча, пока перекрывает менее 40 % ребра;
- маршруты длиннее 6 рёбер рисуются со спрямлением — это записанная деградация, не проверяемая стендом;
- **хорда (2026-10-12, программа 039, срез A).** Платёж, нарисованный одним лучом «отправитель → получатель», свойство 3 видит только там, где хорда выходит из коридоров маршрута. Поэтому `pickRingRoute` **отказывается** отдавать открытый маршрут из двух и более рёбер, если на хорде нет сплошного участка длиной не меньше 0.15 хорды (`MOTION_LIMITS.maxStepPerFrame` — наибольший шаг головы луча за кадр, который оракул принимает), каждая точка которого дальше `2 × CORRIDOR_PX` = 10 px от оси каждого ребра маршрута и дальше 46 px от каждого его узла. Отказ — свойство расклада, а не продукта. Замкнутый маршрут (шесть ног кольца из шести: отправитель и получатель — один узел) хорды не имеет и не судится; маршрут из одного ребра сам является своей хордой. Мера — участок, а не середина хорды: хорда, пересекающая ногу маршрута в своей середине, от маршрута отличима. Красный случай держит `chord.qa.ts` на открытом маршруте из шести ног по семи узлам (`OPEN_ROUTE`): луч по ногам свойством 3 принят, тот же платёж одним лучом — отвергнут. Не видно: «срезка» одного узла длинного маршрута (это не хорда «отправитель → получатель»); луч на хорде, шагающий дальше 0.15 хорды за кадр; на открытом маршруте свойства 1, 2, 4 и 5 не судятся.

- **Промежуточные кадры.** Прямоугольник снимается, когда окно перестало двигаться; скачок при росте содержимого не виден.
- **Размер целей** — только для включённых элементов управления, в `saas` и `hud`.
- **Темы `shadcn` и `library`** (заморожены, токены сохранены) стенд не проходит вовсе: ни кадра, ни axe, ни геометрии. Атрибутом их ставит только тест 1 раздела 3.3 — проверка, что токены данных у них те же.
- **Гарды проводки** (`tooling-tests/portable/test_p038_qa_stand_gate.py`) читают текст четырёх файлов и файлов считаемого проекта (с 2026-10-12: `test:e2e:qa` — режим `debug` раннера, и ни один скрипт `package.json` не запускает считаемый проект мимо раннера; прямой вызов `npx playwright test --config=e2e/playwright.qa.config.ts` из оболочки гард не видит и не может — это по-прежнему несчитаемый прогон; у шага гейта есть свой `timeout-minutes` меньше таймаута job; отчёт шага загружается при `always()`; ни один `*.qa.ts` не использует окно настенных часов `perf-measure.ts` — рукописный порог по `performance.now()` гард не видит): они не доказывают, что шаг CI действительно исполнил тесты, — это видно в логе шага по строке `run-stand [gate]: ran N …, skipped 0, recorded N`.
- Те же гарды не замечают (выжило в adversarial-проходе): `continue-on-error` на уровне job или выражением; `shell`; `needs` на job по расписанию; `paths-ignore` и другие ограничения триггера; пустой список флагов браузера. Прямое `|| true`, дописанное к `run` обязательного шага, гард **замечает** (поправка 2026-10-11 по внешнему ревью S2; прежний текст называл и его слепой зоной): он сравнивает нормализованную команду шага целиком и требует ровно одно совпадение (`_runs` и проверка числа шагов в том же файле), поэтому шаг с изменённой командой перестаёт считаться шагом гейта.

## 6. Производительность без GPU

Срез S3. Политика и принятые числа — в [`performance-and-quality-policy.md`](performance-and-quality-policy.md). Проверок два рода, и смешивать их нельзя: счётчики на подменённых часах живут в считаемом проекте `qa-stand`, настенные часы — в проекте `qa-perf` (файлы `*.qaperf.ts`).

**Дискретные бюджеты** — `e2e/qa/budgets.ts`, тесты `budgets.qa.ts` и `no-gpu-effects.qa.ts`. **С 2026-10-12 (программа 039, срез A, R14) это члены проекта `qa-stand` без метки `@extended`: шесть бюджетных тестов и две их контрпроверки исполняет обязательный гейт** (до этого их собирал только `qa-perf` по расписанию, и на PR они не шли). Это счётчики на подменённых часах, двусторонний храповик (точное равенство: хуже — регрессия, лучше — записать константу датированной строкой). Время кадра, fps и heap в `budgets.ts` и в `qa-stand` не попадают: это свойство машины. Держат:

- число **проходов** цикла рендера (на один платёж из сна, за период нагрузки, в покое) и отдельно **объём рисования** — число рисующих вызовов Canvas 2D, константы `DRAW_COMMANDS_*`;
- лимиты частиц и меток, бюджет эффектов при устойчиво низкой частоте;
- остаток после потока событий (ничего живого, цикл снова спит);
- тёплый кэш glow-спрайтов;
- перечень элементов с CSS `filter` и `backdrop-filter` без GPU в шести состояниях (нагрузка; подписи «выбранного и соседей» (`labelsLod = neighbors`; выбора в интерфейсе нет с 048 S2, значение читается из `geo.sim.labelsLod`) с выбранным хабом; карточка узла; тултип ребра; панель платежа; перетаскиваемый узел).

Счёт не зависит от фазы часов: бюджетные тесты перед замером шагают на границу кадра (`stepToFrameBoundary` в `stand.ts`).

**Время кадра** — `frame.qaperf.ts`, `frame-breakdown.qaperf.ts`. Диагностика одной машины на настенных часах: частота проходов, p95 кадра, JS-работа за кадр, рост heap, разбор кадра трассой. Порогов нет; тест падает только на пустом измерении (нет проходов продукта, нагрузка подана не целиком, продукт принял не все отправленные события, метки не анимируются). Итог пишется в `qa-perf-summary-<dev|preview>.json` выходного каталога.

Команды:

| Что | Команда |
|---|---|
| Перф-проект на dev-сервере (только настенные часы) | `npm --prefix simulator-ui/v2 run test:e2e:qa:perf` |
| То же на production-сборке, **плюс бюджеты** | `$env:QA_STAND_SERVER = "preview"; npm --prefix simulator-ui/v2 run test:e2e:qa:perf` |
| Только бюджеты, dev-сервер (срез: debug-only, не гейт) | `… run test:e2e:qa -- budgets.qa no-gpu-effects.qa` |

На production-сборке dev-хука нет, и три теста, читающие FX-состояние или открывающие поверхности через хук, пропускаются с причиной. Это «не измерено», а не «держится». Поэтому на production-сборке бюджетные файлы собирает только `qa-perf` (`e2e/playwright.qa.config.ts`, `BUDGET_FILES`): считаемый гейт идёт на dev-сервере, где не пропускается ничего, а любой пропуск в нём — отказ раннера.

В CI перф-проект идёт только по расписанию и вручную — job `simulator-qa-perf`, артефакт `simulator-qa-perf` (HTML-отчёты и JSON сводок). В обязательный гейт проект `qa-perf` не входит (бюджеты — входят, они в `qa-stand`): `quality-guard.qaperf.ts` идёт на реальном времени и требует от машины больше 24 fps на старте, а число настенных часов общего раннера не должно блокировать PR.

Чего перф-часть не видит:

- **«×4» — не процессор вчетверо медленнее.** Троттлинг CDP замедляет только главный поток; композитор и растр идут на скорости машины стенда.
- **«fps» стенда — частота проходов рендера продукта, а не показанных кадров.** Показ подтверждён разовым замером трассы, механизмом не держится.
- **Настоящий GPU, встроенная графика, Firefox и WebKit, живой бэкенд.**
- **Взаимодействие под нагрузкой** (перетаскивание, зум, ввод во время потока событий) и **графы больше 100 узлов**.
- **Счётчик команд** считает рисующие вызовы, но не видит построение путей и стоимость отдельного вызова.
- **Перечень CSS-эффектов — шесть состояний, не «вся страница».** Тосты, панели линии и клиринга, меню, метрики, история и оверлеи прочитаны по CSS, но не исполнены; псевдоэлементы перечень не смотрит.
- **Эвристика `data-gpu`:** ложное `'0'` при заблокированном WebGL на машине с GPU; ложное `'1'` на рендерерах, чьё имя стенду неизвестно.
- **Переносимость бюджетов между платформами** не обещана: константы записаны на одной; другие числа на другом раннере — вопрос о платформе храповика, а не повод двигать константу.

## 7. CI

- **Обязательный гейт.** Job `ui-smoke` (ubuntu, каждый PR), шаг «Run the Simulator UI QA stand, required subset»: `npm --prefix simulator-ui/v2 run test:e2e:qa:gate`, `timeout-minutes: 15`. Порогов по настенным часам в нём нет; дискретные бюджеты (счётчики на подменённых часах) в нём есть. HTML-отчёт шага загружается всегда (`if: always()` стоит только на шаге загрузки и результата шага гейта не меняет).
- **2026-10-18:** прогноз времени стенда берётся только из CI (шаг стенда в `ui-smoke` и длительности тестов из его отчёта), не из локальных прогонов: 2026-10-18 локальный прогноз 039 C занизил прирост вдвое.
- **По расписанию и вручную.** Job `simulator-qa-stand`: `test:e2e:qa:report`, затем `test:e2e:qa:video` (шаг идёт и после красного стенда, а его собственный отказ делает job красным); HTML-отчёт стенда с галереей, отчёт видео и сами ролики — одним артефактом `simulator-qa-stand-report-all-themes`. На PR видео не пишутся. Запуск на CI с роликами в артефакте на дату правки (2026-10-12) не исполнен — нужен `workflow_dispatch` на слитом SHA.
- Вне обязательного подмножества (метка `@extended`): галерея кадров и axe в двух темах (`saas`, `hud`); viewport 1920×1080 и 1024×640 для окон менеджера и поверхностей, поставленных одним CSS; измерение доли экрана под HUD; репродьюсер дефекта попапа линии (BACKLOG 037-4).
- Поимённый список `NOT_IN_GATE` в `e2e/qa/run-stand.mjs` (тест вне подмножества без метки, с причиной и датой) сейчас пуст.
