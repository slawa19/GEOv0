# Interact Mode — Руководство пользователя

> **Состояние на 2026-10-17 (программа [043](../../../../../specs/043-demo-screen-minimal/spec.md), S2–S3).** Отдельного режима Interact нет: ручные действия — часть единого экрана Simulator UI на источнике «Сервер». Нет ни сегмента «Interact», ни параметра `?ui=interact` (в старой ссылке он игнорируется), ни принудительной интенсивности 0 %. Вместо этого **любое явное ручное действие ставит прогон на паузу**, а возобновляет его только явный акт — «Поток» (кнопки Resume под «Подробнее» нет с 048 S1). Актуальное описание экрана — [`hud-user-guide.md`](hud-user-guide.md) §1, §3. Название «Interact Mode» ниже означает «ручные действия на единой странице»; панели, флоу и горячие клавиши (разделы 4–11) остаются в силе.
>
> **Слова интерфейса (046, 2026-10-19).** Экран двуязычный: язык выбирается под «Подробнее» (рядом с темой), `?lang=ru|en`, сохранённый выбор, затем язык браузера; словарь — `simulator-ui/v2/src/i18n/ru.ts` и `en.ts`. Руководство цитирует **русские** слова интерфейса; английская форма — в скобках там, где руководство прежде цитировало английскую. Инструменты разработчика под `?debug=1` (Analytics, «Источник», Quality, «Плейлист») не переводятся.

Ручные действия — интерактивная часть GEO Simulator UI: пользователь управляет графом взаимного кредита вручную — отправляет платежи, создаёт и редактирует trustlines, запускает клиринг.

---

## 1. Что такое Interact Mode

При открытии экран сам запускает живой прогон, и симулятор генерирует платежи с заданным темпом (по умолчанию 15 % у посетителя и 30 % у оператора с админским токеном — `hud-user-guide.md` §1). Первое же ручное действие **ставит прогон на паузу**, и граф «замирает» (подтверждение, отмена и закрытие панели прогон не возобновляют). Вы получаете полный контроль:

- **Отправка платежей** — выбираете отправителя, получателя и сумму вручную.
- **Управление trustlines** — создание, изменение лимита и закрытие кредитных линий.
- **Запуск клиринга** — инициирование поиска и схлопывания циклов долгов.

Все действия выполняются через реальный бэкенд (база данных PostgreSQL), поэтому результат отражается в графе в реальном времени через SSE‑стрим.

---

## 2. Предусловия

| Требование | Описание |
|---|---|
| Бэкенд запущен | GEO API сервер доступен и работает |
| Feature flag | На бэкенде включён `SIMULATOR_ACTIONS_ENABLE=1` |
| Режим real | UI работает в режиме `mode=real` (подключение к реальному бэкенду) |

Если feature flag не включён, кнопки действий будут неактивны («Действия отключены на сервере.»), а при попытке действия окно покажет «Действия в симуляторе отключены.» (ответ 403 `ACTIONS_DISABLED`).

---

## 3. Как войти в Interact Mode

Входа в режим нет — экран один. Откройте Simulator UI (источник «Сервер», он по умолчанию) и нажмите одно из трёх действий в первом ряду TopBar: **«Платёж»** (Send Payment), **«Линия доверия»** (Manage Trustline), **«Клиринг»** (Run Clearing).

> **Примечание.** Без прогона (например, источник «Снимок без сервера» или сервер без сценариев) действия недоступны и показывают причину. Если активного run нет, экран сам запускает живой прогон при открытии (одна попытка на загрузку страницы); если сервер отказал из‑за предела активных прогонов, в строке ошибки — читаемый текст и рядом кнопка повтора. Кнопки Start у посетителя нет (048 S2, 2026-10-19: ряд прогона — только с админским токеном); после любой другой остановки прогона путь назад — перезагрузка страницы: автостарт запустит новый прогон.

## 4. Интерфейс Interact Mode

На экране есть панель действий (первый ряд TopBar), панель системных метрик («Общий долг» — в нижней полосе, остальные значения — под «Подробнее») и лог истории. Автоматические платежи останавливаются первым ручным действием.

### 4.1 System Balance Bar — панель системных метрик

Компактный «Общий долг» — в нижней полосе справа; остальные показатели — под верхней панелью, пока включено «Подробнее». Показывает агрегированные показатели сети:

| Метрика | Описание |
|---|---|
| **«Общий долг»** (Total debt) | Суммарный объём использованных лимитов (задолженность) |
| **«Свободно по линиям»** (Free on lines; до 049 S2 — «Доступно для платежей») | Сумма свободных лимитов по всем линиям доверия; не обещает, что пройдёт любой платёж (определение — в `title` плашки) |
| **«Линии доверия»** (Trust lines) | Количество активных кредитных линий |
| **«Участники»** (Participants) | Количество активных участников |
| **«Занято лимитов»** (Limits in use) | Процент использования лимитов с прогресс-баром |

Бейджа «Clean» («система не имеет долгов») больше нет: он повторял «Общий долг 0.00» (удалён 048 S1). После клиринга над «Общим долгом» стоит строка «клиринг: было X → стало Y» (`hud-user-guide.md` §5.2).

Метрики обновляются автоматически при каждом изменении снимка графа.

### 4.2 Action Bar — панель действий

Горизонтальная панель с тремя кнопками:

| Кнопка | Назначение |
|---|---|
| **«Платёж»** (Send Payment) | Начать процесс отправки платежа |
| **«Линия доверия»** (Manage Trustline) | Начать процесс создания/редактирования/закрытия trustline |
| **«Клиринг»** (Run Clearing) | Начать процесс клиринга |

Активная кнопка подсвечивается акцентным цветом. Кнопки отключаются, когда:
- Выполняется операция (`interactBusy`).
- Активен другой flow (т.е. `phase !== 'idle'`) — сначала отмените текущий action.
- Бэкенд вернул 403 (feature flag отключён).
- Run остановлен или завершился с ошибкой.

Термины состояний:
- `interactBusy` — общий флаг «UI занят»: выполняется запрос/операция (платёж, операции с trustline, клиринг).
- `trustlinesLoading` — отдельный флаг загрузки/обновления списка trustlines (например, для NodeCard).

### 4.3 History Log — лог последних действий

Блок «Последние действия» (Recent actions) стоит справа над нижней полосой и показывает три последних выполненных действия (`SimulatorAppRoot.vue`, `OWN_LINES_SHOWN`; у компонента умолчание 8). С переключателем **«Показывать события»** (Show events; «Подробнее», по умолчанию выключен, запоминается как тема и язык; 049 S2) блок называется «События сети» (Network events) и показывает пять строк: свои действия с пометкой «вы» и события прогона из потока SSE — платёж «A → B: сумма», отказ «A → B: не прошёл — причина» (без суммы; при неизвестной причине — «платёж не прошёл», без диагноза), клиринг «Клиринг: общий долг −X; N кругов» (X — разница общего долга до/после, не `cleared_amount`), «После клиринга выросли лимиты доверия». Платежи (и отдельно отказы) за 2 секунды сводятся в одну строку «За 2 с: N платежей; последний — …». Свой платёж и свой клиринг при включённом переключателе видны одной строкой — строкой их события из потока (публикация best‑effort: если событие не дошло, результат остаётся в окне). Смена прогона или эквивалента очищает все строки, и свои тоже; переключатель очищает только строки событий (свои строки текущего прогона остаются). Длинная строка сокращается многоточием только в именах участников: сумма с единицей, причина отказа и цифры клиринга видны целиком (049, решение 9). Каждая запись содержит:
- Иконку действия (💸 — платёж, 🔗 — создание trustline, ✏️ — обновление, 🗑️ — закрытие, 🌀 — клиринг)
- Описание действия
- Время выполнения

Записи хранятся только в текущей сессии (до 20 в буфере). Самое свежее действие выделяется более ярким шрифтом.

## 5. Отправка платежа

### Пошаговый процесс

```
Шаг 1 — Нажмите «Платёж» (Send Payment) в панели действий
         → Откроется окно «Платёж» (Payment)
         → Курсор на графе изменится на перекрестие (crosshair)

Шаг 2 — Выберите отправителя («От кого», From)
         → Кликните по узлу на графе ИЛИ выберите из выпадающего списка «От кого» (пустое поле подсказывает «На графе или из списка»)
         → Доступные узлы подсвечиваются на графе
         → Выбрав отправителя в списке «От кого», вы сразу получаете открытый список «Кому» с фокусом внутри него (форма
           объявляет «Выберите получателя.»; EN: «Choose the recipient.»). Список сам не открывается, если отправитель пришёл не из вашего выбора
           в списке: обновление данных, восстановленный неразрешённый платёж, панель, открытая из ребра или карточки
           узла. Первый Esc закрывает список, следующий — обычный шаг назад панели; Tab и Shift+Tab не выходят из
           открытого списка

Шаг 3 — Выберите получателя («Кому», To)
         → Кликните по другому узлу ИЛИ выберите из списка «Кому»
         → Подсвечиваются узлы, до которых сервер нашёл маршрут платежа (`payment-targets`, в том числе
           через посредников); прямая линия не обязательна. Платёж `From → To` расходует ёмкость линии
           `To → From` (направление линии = creditor → debtor)

Шаг 4 — Введите сумму
         → Под полями — одна информационная строка (045 S2): прямая ёмкость «Напрямую» (Direct) с пометкой источника в
           скобках («сервер» — ответ сервера, «снимок, не подтверждено» — число из снимка, которое сервер не подтвердил), затем
           два числа ответа сервера для выбранного получателя: «Макс.» (Max; оценка максимума; «не оценено» — сервер не
           оценил, это не ноль; «ждём сервер» / «не получено» — состояние ответа) и число шагов
           кратчайшего пути («Кратчайший путь: N шагов»). Пояснения («Подсказка для одного шага…», «Маршрут выбирается при проведении платежа.») — во всплывающей
           подсказке (`title`) этих чисел. Это не подписи в каждой строке списка
         → Выбор получателя переводит фокус в поле «Сумма» (Amount) и ничего не отправляет
         → Кто кому платит — в заголовке окна («Платёж: Alice → Bob», имена; EN: «Payment: Alice → Bob»); сумма — в поле «Сумма»
         → Введите сумму в поле «Сумма»
         → Если сумма превышает оценку сервера (или прямую ёмкость, пока оценки нет) — появится предупреждение;
           оно не блокирует отправку: решает сервер

Шаг 5 — Подтвердите
         → Нажмите «Отправить» (Confirm; или Enter в поле суммы); запрос уходит с ключом идемпотентности намерения
         → При успехе панель остаётся на экране результата: идентификатор платежа, статус, сумма и маршрут(ы)
           по шагам с именами участников; в логе появится запись 💸. «Ещё платёж» (Another payment) возвращает к выбору
           получателя, «Закрыть» (Close) закрывает панель
         → Если ответа нет или он нечитаем, панель пишет «Результат неизвестен» (Result unknown) и предлагает «Проверить / повторить» (Check / repeat):
           повтор идёт с тем же ключом и тем же телом и не может заплатить дважды. Пока исход неизвестен,
           другой платёж отправить нельзя; выйти можно только явным сбросом «Сбросить и начать заново» (Discard and start over; два шага: «Сбросить» / «Продолжить проверку»)
           — первый платёж мог пройти. Запись о платеже сохраняется в `sessionStorage` вкладки ДО отправки: если
           браузер не даёт её сохранить (или хранилище нельзя прочитать), платёж не отправляется и панель
           объясняет почему. Запись переживает перезагрузку вкладки; закрытие вкладки сохранения не гарантирует.
           Вторая вкладка и другой браузер о неразрешённом платеже не знают, и новый платёж там получит новый ключ
```

Что делает форма при исправлениях и чего она не делает:
- Список «Кому» открывается сам и фокус уходит в «Сумма» только при ПЕРВОМ прохождении (получателя ещё не было). Это решается состоянием до вашего выбора, а не тем, что осталось после: смена отправителя на самого получателя очищает получателя, но это исправление, и список не открывается. Исправляя получателя или отправителя на шаге подтверждения, вы остаётесь на том контроле, которым пользовались (в «Сумма» уже есть сумма, а Enter в ней подтверждает).
- Удерживаемая клавиша никогда не подтверждает: автоповтор Enter (`repeat`) игнорируется и в «Сумма», и на кнопке «Отправить»; подтверждает только свежее нажатие.
- Пока исход платежа неизвестен, заголовок панели описывает ЗАМОРОЖЕННЫЙ платёж, а не поля, которые мог подставить другой вход (ребро, карточка узла).
- Известные ограничения (замечены, не исправлены): шаг подтверждения стал выше на 120 px, и окно менеджера подтягивается в экран за несколько кадров (виден небольшой скачок; тесты меряют установившееся состояние, не промежуточные кадры); защиты от очень быстрого второго касания по только что появившемуся списку нет (устройством не проверено).

### Валидация
- Сумма должна быть больше 0.
- Отправитель и получатель не могут совпадать.
- Превышение ёмкости или оценки сервера не блокирует «Отправить» (предупреждение; решает сервер).

### Отмена
- Нажмите **«Отмена»** (Cancel) в панели — или — нажмите **ESC** на клавиатуре.

## 6. Управление Trustlines

### 6.1 Создание нового trustline

```
Шаг 1 — Нажмите «Линия доверия» (Manage Trustline) в панели действий
         → Откроется окно «Линия доверия» (Trustline)
         → Курсор на графе — перекрестие

Шаг 2 — Выберите кредитора («Кто доверяет», From)
         → Кликните по узлу или выберите из выпадающего списка

Шаг 3 — Выберите заёмщика («Кому», To)
         → Кликните по другому узлу или выберите из списка
         → Если между «Кто доверяет» и «Кому» уже есть активный trustline — автоматически
           откроется режим редактирования (см. 6.2)
         → Если нет — откроется форма создания

Шаг 4 — Введите лимит
         → Введите значение в поле «Лимит» (Limit; должен быть > 0)

Шаг 5 — Нажмите «Создать» (Create)
         → При успехе панель закроется, в логе — запись 🔗
```

### 6.2 Редактирование существующего trustline

Открыть редактирование можно двумя способами:
- **Через панель действий**: нажмите «Линия доверия», затем выберите пару «Кто доверяет» → «Кому», у которой уже есть trustline.
- **Через клик по ребру на графе**: кликните по ребру — откроется EdgeDetailPopup с кнопками действий и одновременно TrustlineManagementPanel переключится в режим редактирования.
- **Через выпадающий список «Линия»** (Existing): в окне «Линия доверия» выберите существующий trustline из списка.

В режиме редактирования отображаются:
- **«Долг»** (Used) — использованная часть лимита (текущий долг).
- **«Лимит»** (Limit) — текущий лимит.
- **«Доступно»** (Available) — свободная ёмкость; при долге выше лимита вместо неё — «Сверх лимита на …».

Одной строкой: «Долг … · Лимит … · Доступно …» (EN: «Used … · Limit … · Available …»).

Действия:
- **«Сохранить»** (Update): введите новый лимит в поле «Лимит» (New limit) и нажмите **«Сохранить»**. Новый лимит должен быть ≥ используемой суммы («Долг») и > 0.
- **«Закрыть линию»** (Close line; прежде Close TL): закрытие trustline (см. 6.3).

### 6.3 Закрытие trustline (двойное подтверждение)

Закрытие — деструктивная операция с защитой от случайного нажатия:

1. Нажмите кнопку **«Закрыть линию»** — кнопка перейдёт в «вооружённое» состояние, текст сменится на **«Точно закрыть»** (Confirm close).
2. Нажмите **«Точно закрыть»** — trustline будет закрыт.

Для отмены:
- Нажмите **«Не закрывать»** (Cancel close) — или — нажмите **ESC**.

У линии с долгом первая кнопка — **«Запросить закрытие»** (Request close): это запрос, а не закрытие — лимит станет 0, линия закроется, когда долг будет погашен («Закрытие запрошено: …»).

> **Важно.** ESC в режиме «вооружённого» подтверждения снимает arming, а не отменяет весь flow.

## 7. Запуск клиринга

Клиринг — процесс поиска циклов долгов в графе и их взаимного зачёта.

```
Шаг 1 — Нажмите «Клиринг» (Run Clearing) в панели действий
         → Откроется окно «Клиринг» с указанием текущего эквивалента

Шаг 2 — Нажмите «Запустить» (Confirm)
         → Бэкенд выполнит поиск циклов и зачёт

Шаг 3 — Просмотрите результат («Итог клиринга», Clearing result)
         → Панель остаётся на экране, пока вы не нажмёте «Закрыть» (Close; или Esc): таймера нет, и клик по пустому месту
           холста её не снимает (так же держатся отказ и результат платежа); клик по ребру, пока результат открыт,
           игнорируется — сначала закройте результат
         → «Погашено циклов» (Cycles cleared) и «Сумма по циклам» (Total over cycles) — сумма сумм циклов в эквиваленте ответа (не сумма
           списанных долгов: цикл из трёх рёбер на 7 уменьшает обязательства на 21, а в итоге даёт 7); эквивалент
           в заголовке — эквивалент этого результата, а не выбранный сейчас
         → По каждому циклу — его сумма и строки по рёбрам с ИМЕНАМИ участников:
           «Alice → Bob: долг уменьшен на 7.00 UAH» (EN: «Alice → Bob: debt reduced by 7.00 UAH»; кредитор → должник, как у линии и её окна). Ребро ответа идёт от кредитора к должнику
           (`from` — кому должны, `to` — кто должен), поэтому это уменьшение долга, а не платёж от Alice к Bob
         → «До → после» по ребру не показывается: ответ его не несёт
         → Следующий клиринг заменяет результат; в памяти он остаётся и после закрытия панели
           (без архива и без сохранения между перезагрузками)

Шаг 4 — На графе (отдельный от панели эффект)
         → На графе появится золотая пульсация (gold pulse) на рёбрах циклов
         → В логе — запись 🌀 (тоста успеха нет с 049 S2: результат — в окне и в строке истории)
```

Если циклов не найдено, панель пишет «Ничего не погашено: замкнутых цепочек долгов не найдено.» (Nothing was cleared: no cycle of debts was found.; это не успех, тоста нет;
в логе «Клиринг: замкнутых цепочек долгов нет»). Если сервер отказал (например, шаг клиринга мельче долга), панель остаётся открытой
с текстом отказа (код запроса — только в `data-request-id` и в консоли, на экране его нет с 049 S2) и рабочим «Закрыть»: текст отказа — состояние окна, он не пропадает сам; тоста ошибки нет (048 S3).

## 8. Работа с графом

### 8.1 Клик на узел — NodeCard

Двойной клик по узлу открывает расширенную карточку. В Interact Mode карточка содержит дополнительные элементы:

- **Кнопка «Платёж»** (Pay; прежде «💸 Send Payment») — начинает платёжный flow с этого узла в качестве отправителя (From).
- **Кнопка «Новая линия»** (New line; прежде «＋ New Trustline») — начинает создание trustline с этого узла в качестве кредитора (From).
- **Список trustlines** узла в двух группах — «Доверяет (N)» (исходящие) и «Доверяют (N)» (входящие; EN: Trusts / Trusted by) — с показателями «долг / лимит» и колонкой «доступно X» (при долге выше лимита — «сверх лимита на X»).
- **Кнопка «Изменить»** (Edit; прежде «✏️») рядом с каждым trustline — переход к редактированию этого trustline.
- **Loading state**: пока данные trustlines загружаются, отображается текст «Линии доверия загружаются…» (Loading trustlines…; флаг `trustlinesLoading`).

### 8.2 Hover на ребро — EdgeTooltip

При наведении курсора на ребро графа появляется всплывающая подсказка (с 043 S1 — и при просмотре, не только в ручных действиях). Это две фразы в эквиваленте линии:

| Фраза | Описание |
|---|---|
| «A доверяет B до {лимит}» (EN: A trusts B up to …) | Кредитор → должник и лимит trustline |
| «долг B перед A — {использовано} · доступно {доступно}» (EN: B owes A … · available …) | Использованная часть и свободная ёмкость; при долге выше лимита вместо «доступно» — «сверх лимита на …» |

Без единой цифры линии остаётся заголовок «A → B» и строка сумм «от: … / до: …». Строки «Status» в подсказке больше нет (удалена 048 S1: английское слово под русской фразой).

### 8.3 Клик на ребро — EdgeDetailPopup

Клик по ребру в Interact Mode открывает всплывающее окно с действиями:

- **«Заплатить A»** (Pay A; A — кредитор линии, платёж идёт ему; без имени — «Заплатить») — начинает платёж из этого ребра. Линия доверия идёт от кредитора к должнику, а платит должник кредитору, поэтому отправитель и получатель в панели платежа стоят «наоборот» относительно стрелки линии. Popup и панель платежа, открытая из ребра, говорят это одной фразой («Почему направление обратное?»: «Линия доверия идёт от кредитора к должнику, а платёж, начатый с линии, идёт от должника к кредитору. Часть, отправленная напрямую, сначала гасит встречный долг, и только остаток увеличивает долг должника в пределах лимита этой линии; этот долг она не погашает. Сервер может провести часть платежа или весь платёж через других участников.»; `payment.lineDirectionNote` словаря; EN: «This line runs from creditor to debtor; Pay starts a payment from debtor to creditor. …»; `docs/ru/02-protocol-spec.md`, ёмкость хопа). Фраза живёт, пока оба участника те же, что пришли из ребра, как бы они ни менялись; у панели, открытой обычным путём, её нет.
- **«Изменить»** (Change limit) — переводит фокус на поле «Лимит» (New limit) в окне «Линия доверия».
- **«Закрыть»** (Close line) — закрытие trustline с двойным подтверждением (аналогично 6.3).
- **Закрытие окна** (доступное имя «Закрыть окно») — закрыть popup без действий.

Заголовок окна — «A → B» (кредитор → должник), под ним строка «A доверяет B до лимита — столько B может быть должен A.».

Popup позиционируется рядом с точкой клика.

## 10. Обработка ошибок

### 10.1 Уведомление об успехе (toast)

**Тоста успеха нет** — он удалён 049 S2 (2026-10-20): результат действия остаётся в окне и в строке истории (тост был третьей записью того же события). **Тоста ошибки нет** — он удалён 048 S3 (2026-10-19): отказ действия показывается блоком ошибки в самом окне (§10.2), который не гаснет через 4 секунды и не дублируется тостом.

### 10.2 Inline‑ошибки в панелях

Каждое окно (платёж, линия доверия, клиринг; и окно линии при «Закрыть» из него) отображает ошибку непосредственно внутри себя в виде красного блока `ds-alert--err` (`role="alert"`): одно предложение «что случилось → что сделать» на языке интерфейса; код запроса — в атрибуте `data-request-id` блока и в строке консоли (на экране его нет с 049 S2, решение владельца 2026-10-20), по нему случай ищут в логе сервера; слов «Error», «HTTP», «Reference» в блоке нет (048 S3), технические идентификаторы и коды — в `title`. Ту же форму имеет строка ошибки прогона в верхней панели. Ошибка очищается при начале нового действия.

### 10.3 Actions Disabled (HTTP 403)

Если бэкенд возвращает 403 с кодом `ACTIONS_DISABLED`, все кнопки в Action Bar блокируются. Это происходит, когда feature flag `SIMULATOR_ACTIONS_ENABLE` не включён на сервере.

### 10.4 Run остановлен

Если run перешёл в состояние `stopped` или `error`, кнопки действий также блокируются. Причина стоит в подсказке кнопок — «Действиям нужен идущий прогон. Если прогон завершился, перезагрузите страницу — начнётся новый.» — и в верхней строке: «Прогон остановлен. Чтобы запустить снова, перезагрузите страницу.» (или «Демо остановилось из-за сбоя. Перезагрузите страницу, чтобы начать новый прогон.» — код ошибки в `title` строки и в консоли, 049 S2). Режимов Auto-Run и Interact больше нет (043), возвращаться некуда: путь назад — перезагрузка страницы, автостарт запускает новый прогон (у админа есть ещё «Старт» под «Подробнее»).

## 11. Горячие клавиши

| Клавиша | Действие |
|---|---|
| **ESC** | Отменить текущий flow (вернуться в idle) — **кроме времени, пока операция выполняется** (запрос ушёл на сервер, панель действий показывает, что операция идёт): тогда ESC ничего не делает — окно не закрывается, flow не отменяется, вопроса нет; операция завершится сама. Если активно «вооружённое» подтверждение закрытия trustline — снимает arming, не отменяя весь flow. В полях ввода (input/select) ESC ведёт себя стандартно |
| **Enter** | В поле суммы платежа — подтвердить отправку |

## 12. Как вернуть автоматические платежи

Выхода из режима нет. Чтобы платежи пошли снова, нажмите **«Поток»** (▶; подсказка «Возобновить автоматические платежи») в первом ряду. Чтобы посмотреть офлайн‑снимок без сервера — «Источник» → «Снимок без сервера» под «Подробнее» (только с `?debug=1`; страница перезагрузится с `?mode=fixtures`; активный flow при этом отменяется).

## 13. Ограничения и особенности

| Ограничение | Описание |
|---|---|
| Пауза на ручное действие | Ручное действие ставит прогон на паузу; темп автоплатежей (поле «Темп автоплатежей, %» в ряду своего прогона под «Подробнее» — он только у админа) не меняется. Возобновляет только «Поток» |
| Один flow за раз | Пока `phase !== 'idle'` (активен flow), Action Bar не позволяет запускать новые действия. Для смены действия сначала отмените текущий flow («Отмена»/ESC). Пока операция выполняется, ESC и щелчок по пустому месту холста не действуют — дождитесь, пока она завершится |
| Нет отката (undo) | Выполненные действия необратимы — нет возможности отменить платёж или восстановить закрытый trustline |
| Сессионная история | Лог действий хранится только в памяти — при перезагрузке страницы он очищается |
| Привязка к run | Ручные действия используют run. Если активного run нет, экран при открытии сам запускает живой прогон (`clearing-demo-10`, если сценарий ещё не выбран и каталог его предлагает). Если run остановится, действия станут недоступны |
| Feature flag | Для работы необходим `SIMULATOR_ACTIONS_ENABLE=1` на бэкенде |
| Только источник «Сервер» | При источнике «Снимок без сервера» ручные действия недоступны (нет прогона) |

## 14. Типичный сценарий использования

1. Откройте Simulator UI: живой прогон стартует сам.
2. Дождитесь формирования графа (10–20 тиков).
3. Осмотрите граф: наведите на рёбра для просмотра ёмкостей, дважды кликните по узлам для деталей (двойной клик по участнику уже ставит прогон на паузу).
4. Создайте новый trustline между двумя участниками.
5. Отправьте платёж по этому trustline.
6. Запустите клиринг и наблюдайте за зачётом циклов.
7. Повторите при необходимости.
8. Нажмите «Поток» (▶), чтобы продолжить автоматическую симуляцию.
