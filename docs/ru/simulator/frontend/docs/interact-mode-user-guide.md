# Interact Mode — Руководство пользователя

> **Состояние на 2026-10-17 (программа [043](../../../../../specs/043-demo-screen-minimal/spec.md), S2–S3).** Отдельного режима Interact нет: ручные действия — часть единого экрана Simulator UI на источнике «Сервер». Нет ни сегмента «Interact», ни параметра `?ui=interact` (в старой ссылке он игнорируется), ни принудительной интенсивности 0 %. Вместо этого **любое явное ручное действие ставит прогон на паузу**, а возобновляет его только явный акт — «Поток» или Resume под «Подробнее». Актуальное описание экрана — [`hud-user-guide.md`](hud-user-guide.md) §1, §3. Название «Interact Mode» ниже означает «ручные действия на единой странице»; панели, флоу и горячие клавиши (разделы 4–11) остаются в силе.

Ручные действия — интерактивная часть GEO Simulator UI: пользователь управляет графом взаимного кредита вручную — отправляет платежи, создаёт и редактирует trustlines, запускает клиринг.

---

## 1. Что такое Interact Mode

При открытии экран сам запускает живой прогон, и симулятор генерирует платежи с заданной интенсивностью (30 % по умолчанию). Первое же ручное действие **ставит прогон на паузу**, и граф «замирает» (подтверждение, отмена и закрытие панели прогон не возобновляют). Вы получаете полный контроль:

- **Отправка платежей** — выбираете отправителя, получателя и сумму вручную.
- **Управление trustlines** — создание, изменение лимита и закрытие кредитных линий.
- **Запуск клиринга** — инициирование поиска и схлопывания циклов долгов.

Все действия выполняются через реальный бэкенд (база данных PostgreSQL), поэтому результат отражается в графе в реальном времени через SSE‑стрим.

---

## 2. Предусловия

| Требование | Описание |
|---|---|
| Бэкенд запущен | GEO API сервер доступен и работает |
| Feature flag | На бэкенде включён `SIMULATOR_ACTIONS_ENABLE=1` |
| Режим real | UI работает в режиме `mode=real` (подключение к реальному бэкенду) |

Если feature flag не включён, кнопки действий в Interact Mode будут неактивны, а при попытке действия появится ошибка HTTP 403.

---

## 3. Как войти в Interact Mode

Входа в режим нет — экран один. Откройте Simulator UI (источник «Сервер», он по умолчанию) и нажмите одно из трёх действий в первом ряду TopBar: **Send Payment**, **Manage Trustline**, **Run Clearing**.

> **Примечание.** Без прогона (например, источник «Снимок без сервера» или сервер без сценариев) действия недоступны и показывают причину. Если активного run нет, экран сам запускает живой прогон при открытии (одна попытка на загрузку страницы); если сервер отказал из‑за предела активных прогонов, в строке ошибки — читаемый текст, а повторить можно кнопкой Start под «Подробнее».

## 4. Интерфейс Interact Mode

На экране есть панель действий (первый ряд TopBar), панель системных метрик («Общий долг» — в нижней полосе, остальные значения — под «Подробнее») и лог истории. Автоматические платежи останавливаются первым ручным действием.

### 4.1 System Balance Bar — панель системных метрик

Расположена по центру сверху (под TopBar). Показывает агрегированные показатели сети:

| Метрика | Описание |
|---|---|
| **Clean** | Бейдж «Clean» — система не имеет долгов |
| **Total Debt** | Суммарный объём использованных лимитов (задолженность) |
| **Available Capacity** | Суммарное свободное пространство для новых платежей |
| **Trustlines** | Количество активных кредитных линий |
| **Participants** | Количество активных участников |
| **Utilization** | Процент использования сети с прогресс-баром |

Метрики обновляются автоматически при каждом изменении снимка графа.

### 4.2 Action Bar — панель действий

Горизонтальная панель с тремя кнопками:

| Кнопка | Назначение |
|---|---|
| **Send Payment** | Начать процесс отправки платежа |
| **Manage Trustline** | Начать процесс создания/редактирования/закрытия trustline |
| **Run Clearing** | Начать процесс клиринга |

Активная кнопка подсвечивается акцентным цветом. Кнопки отключаются, когда:
- Выполняется операция (`interactBusy`).
- Активен другой flow (т.е. `phase !== 'idle'`) — сначала отмените текущий action.
- Бэкенд вернул 403 (feature flag отключён).
- Run остановлен или завершился с ошибкой.

Термины состояний:
- `interactBusy` — общий флаг «UI занят»: выполняется запрос/операция (платёж, операции с trustline, клиринг).
- `trustlinesLoading` — отдельный флаг загрузки/обновления списка trustlines (например, для NodeCard).

### 4.3 History Log — лог последних действий

Отображается в правом нижнем углу и показывает последние 8 выполненных действий. Каждая запись содержит:
- Иконку действия (💸 — платёж, 🔗 — создание trustline, ✏️ — обновление, 🗑️ — закрытие, 🌀 — клиринг)
- Описание действия
- Время выполнения

Записи хранятся только в текущей сессии (до 20 в буфере). Самое свежее действие выделяется более ярким шрифтом.

## 5. Отправка платежа

### Пошаговый процесс

```
Шаг 1 — Нажмите «Send Payment» в Action Bar
         → Откроется панель Manual Payment
         → Курсор на графе изменится на перекрестие (crosshair)

Шаг 2 — Выберите отправителя (From)
         → Кликните по узлу на графе ИЛИ выберите из выпадающего списка «From»
         → Доступные узлы подсвечиваются на графе
         → Выбрав отправителя в списке «From», вы сразу получаете открытый список «To» с фокусом внутри него (форма
           объявляет «Choose the recipient.»). Список сам не открывается, если отправитель пришёл не из вашего выбора
           в списке: обновление данных, восстановленный неразрешённый платёж, панель, открытая из ребра или карточки
           узла. Первый Esc закрывает список, следующий — обычный шаг назад панели; Tab и Shift+Tab не выходят из
           открытого списка

Шаг 3 — Выберите получателя (To)
         → Кликните по другому узлу ИЛИ выберите из списка «To»
         → Подсвечиваются узлы, до которых сервер нашёл маршрут платежа (`payment-targets`, в том числе
           через посредников); прямая линия не обязательна. Платёж `From → To` расходует ёмкость линии
           `To → From` (направление линии = creditor → debtor)

Шаг 4 — Введите сумму
         → Под полями — одна информационная строка (045 S2): прямая ёмкость «Direct» с пометкой источника в
           скобках («server» — ответ сервера, «snapshot…» — число из снапшота, которое сервер не подтвердил), затем
           два числа ответа сервера для выбранного получателя: «Max» (оценка максимума; «not estimated» — сервер не
           оценил, это не ноль; «waiting for the server» / «not received» — состояние ответа) и число шагов
           кратчайшего пути. Пояснения («1-hop hint…», «маршрут выбирается при исполнении») — во всплывающей
           подсказке (`title`) этих чисел. Это не подписи в каждой строке списка
         → Выбор получателя переводит фокус в поле «Amount» и ничего не отправляет
         → Кто кому платит — в заголовке панели («Manual payment: Alice → Bob», имена); сумма — в поле «Amount"
         → Введите сумму в поле «Amount»
         → Если сумма превышает оценку сервера (или прямую ёмкость, пока оценки нет) — появится предупреждение;
           оно не блокирует отправку: решает сервер

Шаг 5 — Подтвердите
         → Нажмите «Confirm» (или Enter в поле суммы); запрос уходит с ключом идемпотентности намерения
         → При успехе панель остаётся на экране результата: идентификатор платежа, статус, сумма и маршрут(ы)
           по шагам с именами участников; в логе появится запись 💸. «Another payment» возвращает к выбору
           получателя, «Close» закрывает панель
         → Если ответа нет или он нечитаем, панель пишет «Result unknown» и предлагает «Check / repeat»:
           повтор идёт с тем же ключом и тем же телом и не может заплатить дважды. Пока исход неизвестен,
           другой платёж отправить нельзя; выйти можно только явным сбросом «Discard and start over» (два шага)
           — первый платёж мог пройти. Запись о платеже сохраняется в `sessionStorage` вкладки ДО отправки: если
           браузер не даёт её сохранить (или хранилище нельзя прочитать), платёж не отправляется и панель
           объясняет почему. Запись переживает перезагрузку вкладки; закрытие вкладки сохранения не гарантирует.
           Вторая вкладка и другой браузер о неразрешённом платеже не знают, и новый платёж там получит новый ключ
```

Что делает форма при исправлениях и чего она не делает:
- Список «To» открывается сам и фокус уходит в «Amount» только при ПЕРВОМ прохождении (получателя ещё не было). Это решается состоянием до вашего выбора, а не тем, что осталось после: смена отправителя на самого получателя очищает получателя, но это исправление, и список не открывается. Исправляя получателя или отправителя на шаге подтверждения, вы остаётесь на том контроле, которым пользовались (в «Amount» уже есть сумма, а Enter в нём подтверждает).
- Удерживаемая клавиша никогда не подтверждает: автоповтор Enter (`repeat`) игнорируется и в «Amount», и на кнопке «Confirm»; подтверждает только свежее нажатие.
- Пока исход платежа неизвестен, заголовок панели описывает ЗАМОРОЖЕННЫЙ платёж, а не поля, которые мог подставить другой вход (ребро, карточка узла).
- Известные ограничения (замечены, не исправлены): шаг подтверждения стал выше на 120 px, и окно менеджера подтягивается в экран за несколько кадров (виден небольшой скачок; тесты меряют установившееся состояние, не промежуточные кадры); защиты от очень быстрого второго касания по только что появившемуся списку нет (устройством не проверено).

### Валидация
- Сумма должна быть больше 0.
- Отправитель и получатель не могут совпадать.
- Превышение ёмкости или оценки сервера не блокирует «Confirm» (предупреждение; решает сервер).

### Отмена
- Нажмите **Cancel** в панели — или — нажмите **ESC** на клавиатуре.

## 6. Управление Trustlines

### 6.1 Создание нового trustline

```
Шаг 1 — Нажмите «Manage Trustline» в Action Bar
         → Откроется панель Trustline Management
         → Курсор на графе — перекрестие

Шаг 2 — Выберите кредитора (From)
         → Кликните по узлу или выберите из выпадающего списка

Шаг 3 — Выберите заёмщика (To)
         → Кликните по другому узлу или выберите из списка
         → Если между From и To уже есть активный trustline — автоматически
           откроется режим редактирования (см. 6.2)
         → Если нет — откроется форма создания

Шаг 4 — Введите лимит
         → Введите значение в поле «Limit» (должен быть > 0)

Шаг 5 — Нажмите «Create»
         → При успехе панель закроется, в логе — запись 🔗
```

### 6.2 Редактирование существующего trustline

Открыть редактирование можно двумя способами:
- **Через Action Bar**: нажмите «Manage Trustline», затем выберите пару From → To, у которой уже есть trustline.
- **Через клик по ребру на графе**: кликните по ребру — откроется EdgeDetailPopup с кнопками действий и одновременно TrustlineManagementPanel переключится в режим редактирования.
- **Через выпадающий список «Existing»**: в панели Trustline Management выберите существующий trustline из списка.

В режиме редактирования отображаются:
- **Used** — использованная часть лимита (текущий долг).
- **Limit** — текущий лимит.
- **Available** — свободная ёмкость.

Действия:
- **Update**: введите новый лимит в поле «New limit» и нажмите **Update**. Новый лимит должен быть ≥ используемой суме (Used) и > 0.
- **Close TL**: закрытие trustline (см. 6.3).

### 6.3 Закрытие trustline (двойное подтверждение)

Закрытие — деструктивная операция с защитой от случайного нажатия:

1. Нажмите кнопку **«Close TL»** — кнопка перейдёт в «вооружённое» состояние, текст сменится на **«Confirm close»**.
2. Нажмите **«Confirm close»** — trustline будет закрыт.

Для отмены:
- Нажмите **«Cancel close»** — или — нажмите **ESC**.

> **Важно.** ESC в режиме «вооружённого» подтверждения снимает arming, а не отменяет весь flow.

## 7. Запуск клиринга

Клиринг — процесс поиска циклов долгов в графе и их взаимного зачёта.

```
Шаг 1 — Нажмите «Run Clearing» в Action Bar
         → Откроется панель Clearing с указанием текущего эквивалента

Шаг 2 — Нажмите «Confirm»
         → Бэкенд выполнит поиск циклов и зачёт

Шаг 3 — Просмотрите результат (Clearing result)
         → Панель остаётся на экране, пока вы не нажмёте «Close» (или Esc): таймера нет, и клик по пустому месту
           холста её не снимает (так же держатся отказ и результат платежа); клик по ребру, пока результат открыт,
           игнорируется — сначала закройте результат
         → Количество зачтённых циклов и «Total over cycles» — сумма сумм циклов в эквиваленте ответа (не сумма
           списанных долгов: цикл из трёх рёбер на 7 уменьшает обязательства на 21, а в итоге даёт 7); эквивалент
           в заголовке — эквивалент этого результата, а не выбранный сейчас
         → По каждому циклу — его сумма и строки по рёбрам с ИМЕНАМИ участников:
           «Bob’s debt to Alice reduced by 7.00 UAH». Ребро ответа идёт от кредитора к должнику
           (`from` — кому должны, `to` — кто должен), поэтому это уменьшение долга, а не платёж от Alice к Bob
         → «До → после» по ребру не показывается: ответ его не несёт
         → Следующий клиринг заменяет результат; в памяти он остаётся и после закрытия панели
           (без архива и без сохранения между перезагрузками)

Шаг 4 — На графе (отдельный от панели эффект)
         → На графе появится золотая пульсация (gold pulse) на рёбрах циклов
         → В логе — запись 🌀, при найденных циклах — тост «Clearing done»
```

Если циклов не найдено, панель пишет «Nothing was cleared: no cycle of debts was found.» (это не успех, тоста нет;
в логе «Clearing: no cycles found»). Если сервер отказал (например, шаг клиринга мельче долга), панель остаётся открытой
с текстом отказа (со ссылкой на запрос) и рабочим «Close»: текст отказа — состояние панели и не пропадает вместе
с всплывающим сообщением об ошибке.

## 8. Работа с графом

### 8.1 Клик на узел — NodeCard

Двойной клик по узлу открывает расширенную карточку. В Interact Mode карточка содержит дополнительные элементы:

- **Кнопка «💸 Send Payment»** — начинает платёжный flow с этого узла в качестве отправителя (From).
- **Кнопка «＋ New Trustline»** — начинает создание trustline с этого узла в качестве кредитора (From).
- **Список trustlines** узла (входящие ← и исходящие →) с показателями used/limit и колонкой **available** (формат `used / limit (avail: X)`).
- **Кнопка «✏️»** рядом с каждым trustline — переход к редактированию этого trustline.
- **Loading state**: пока данные trustlines загружаются, отображается текст «Loading trustlines…» (флаг `trustlinesLoading`).

### 8.2 Hover на ребро — EdgeTooltip

При наведении курсора на ребро графа появляется всплывающая подсказка. В Interact Mode она показывает расширенную информацию:

| Поле | Описание |
|---|---|
| Заголовок | Имена участников: From → To |
| Amount | Текущий used |
| Limit | Лимит trustline |
| Used | Использованная часть |
| Avail | Свободная ёмкость |
| Status | Статус trustline |

### 8.3 Клик на ребро — EdgeDetailPopup

Клик по ребру в Interact Mode открывает всплывающее окно с действиями:

- **Pay …** — начинает платёж из этого ребра. Линия доверия идёт от кредитора к должнику, а платит должник кредитору, поэтому отправитель и получатель в панели платежа стоят «наоборот» относительно стрелки линии. Popup и панель платежа, открытая из ребра, говорят это одной фразой («This line runs from creditor to debtor; Pay starts a payment from debtor to creditor. For the part sent directly, any reverse debt is offset first, and only the remainder increases the debtor’s debt under this line’s limit; it does not repay that debt. The server may route some or all of the payment through other participants.» — то есть: линия идёт от кредитора к должнику, а «Pay» начинает платёж от должника к кредитору; в той части, что идёт напрямую, встречный долг сначала зачитывается, и только остаток увеличивает долг должника в пределах лимита этой линии; платёж не гасит этот долг; сервер может провести платёж частично или целиком через других участников; `docs/ru/02-protocol-spec.md`, ёмкость хопа). Фраза живёт, пока оба участника те же, что пришли из ребра, как бы они ни менялись; у панели, открытой обычным путём, её нет.
- **Change limit** — переводит фокус на поле «New limit» в панели Trustline Management.
- **Close line** — закрытие trustline с двойным подтверждением (аналогично 6.3).
- **Close** — закрыть popup без действий.

Popup позиционируется рядом с точкой клика.

## 9. Визуальные подсказки

| Подсказка | Когда появляется |
|---|---|
| **Курсор‑перекрестие** (crosshair) | Во время фаз выбора узла: picking‑payment‑from, picking‑payment‑to, picking‑trustline‑from, picking‑trustline‑to |
| **Подсветка доступных узлов** | При выборе получателя UI использует backend-кандидатов маршрутизации и может показывать multi-hop достижимость; наличие прямой trustline не является общим требованием. При выборе отправителя подсвечиваются допустимые участники |
| **Затемнение недоступных узлов** | При выборе отправителя или получателя недоступные узлы затемняются (`globalAlpha = 0.25`), а доступные остаются яркими. Реализовано через параметр `dimmedNodeIds` в render pipeline ([`baseGraph.ts`](../../../../../simulator-ui/v2/src/render/baseGraph.ts)) |
| **Искра по циклу клиринга** | После успешного клиринга одна оранжевая искра обходит каждый цикл за 1.2 с; узел цикла подсвечивается контуром, когда искра его покидает (программа 039, срез C, 2026-10-18; до этого — вспышки до 40 узлов разом, `kind: 'clearing'`, 2.8 с, и полноэкранная вспышка — удалены) |
| **Пульсация линий клиринга** | После обхода — линии циклов пульсируют 1.6 с и угасают, цикл подсвечен на графе, появляется сумма. Линии, которые не замыкаются в цикл при восстановлении из набора линий, пульсируют вместе с ними, без искры |
| **Акцентная подсветка кнопки** | Активная кнопка в Action Bar подсвечивается акцентным цветом |
| **Анимация появления панелей** | Панели платежей, trustlines и клиринга появляются с анимацией slide |
| **Подсказки в панелях** | Подсказка выбора живёт в пустом поле «From»/«To»: «Pick on the canvas or choose» (045 S2). Отдельная строка под полями — только причина отказа или предупреждение, и только когда они есть. Кнопка действия («Confirm», «Create») стоит в ряду `[Cancel][Confirm]` с первого шага и до готовности отключена; почему — сказано в её подсказке (`title`) |

## 10. Обработка ошибок

### 10.1 Toast‑уведомления

Ошибки, возникающие при выполнении действий, отображаются в виде красного toast‑уведомления внизу экрана (по центру). Toast автоматически исчезает через 4 секунды или может быть закрыт кнопкой «✕».

### 10.2 Inline‑ошибки в панелях

Каждая панель (Payment, Trustline, Clearing) отображает ошибку непосредственно внутри себя в виде красного блока `ds-alert--err`. Ошибка очищается при начале нового действия.

### 10.3 Actions Disabled (HTTP 403)

Если бэкенд возвращает 403 с кодом `ACTIONS_DISABLED`, все кнопки в Action Bar блокируются. Это происходит, когда feature flag `SIMULATOR_ACTIONS_ENABLE` не включён на сервере.

### 10.4 Run остановлен

Если run перешёл в состояние `stopped` или `error`, кнопки действий также блокируются. Для продолжения работы необходимо вернуться в Auto‑Run, запустить новый run и снова войти в Interact Mode.

## 11. Горячие клавиши

| Клавиша | Действие |
|---|---|
| **ESC** | Отменить текущий flow (вернуться в idle). Если активно «вооружённое» подтверждение закрытия trustline — снимает arming, не отменяя весь flow. В полях ввода (input/select) ESC ведёт себя стандартно |
| **Enter** | В поле суммы платежа — подтвердить отправку |

---

## 12. Как вернуть автоматические платежи

Выхода из режима нет. Чтобы платежи пошли снова, нажмите **«Поток»** (▶) в первом ряду или Resume под «Подробнее». Чтобы посмотреть офлайн‑снимок без сервера — «Источник» → «Снимок без сервера» под «Подробнее» (страница перезагрузится с `?mode=fixtures`; активный flow при этом отменяется).

## 13. Ограничения и особенности

| Ограничение | Описание |
|---|---|
| Пауза на ручное действие | Ручное действие ставит прогон на паузу; интенсивность (поле в ряду сценария под «Подробнее») не меняется. Возобновляет только «Поток» или Resume |
| Один flow за раз | Пока `phase !== 'idle'` (активен flow), Action Bar не позволяет запускать новые действия. Для смены действия сначала отмените текущий flow (Cancel/ESC) |
| Нет отката (undo) | Выполненные действия необратимы — нет возможности отменить платёж или восстановить закрытый trustline |
| Сессионная история | Лог действий хранится только в памяти — при перезагрузке страницы он очищается |
| Привязка к run | Ручные действия используют run. Если активного run нет, экран при открытии сам запускает живой прогон (`clearing-demo-10`, если сценарий ещё не выбран и каталог его предлагает). Если run остановится, действия станут недоступны |
| Feature flag | Для работы необходим `SIMULATOR_ACTIONS_ENABLE=1` на бэкенде |
| Только источник «Сервер» | При источнике «Снимок без сервера» ручные действия недоступны (нет прогона) |

## 14. Типичный сценарий использования

1. Откройте Simulator UI: живой прогон стартует сам.
2. Дождитесь формирования графа (10–20 тиков).
3. Осмотрите граф: наведите на рёбра для просмотра ёмкостей, дважды кликните по узлам для деталей (двойной клик по участнику уже ставит прогон на паузу).
4. Создайте новый trustline между двумя участниками.
5. Отправьте платёж по этому trustline.
6. Запустите клиринг и наблюдайте за зачётом циклов.
7. Повторите при необходимости.
8. Нажмите «Поток» (▶), чтобы продолжить автоматическую симуляцию.
