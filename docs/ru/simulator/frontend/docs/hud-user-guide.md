# Simulator UI v2 — HUD: инструкция пользователя (RU)

Документ объясняет, **что делает каждый элемент HUD** в Simulator UI v2 и как им пользоваться.

Экран один (программа [043](../../../../../specs/043-demo-screen-minimal/spec.md), срезы S1–S3, 2026-10-16/17): режимов Sandbox / Auto‑Run / Interact и переключателя между ними больше нет. По умолчанию виден только первый взгляд; всё служебное прячется за одной кнопкой **«Подробнее»** и не отрисовывается, пока она выключена. Реестр терминов экрана — «Поток», «Подробнее», «Источник» — взят из самого интерфейса (`TopBar.vue`, `BottomBar.vue`); словарь RU/EN с переключателем (П6 программы 034) появится в 034 S9, до него язык страницы — русский (`index.html` `lang="ru"`).

## 1) Как открыть

- Full stack: `http://localhost:5176/` — источник по умолчанию **сервер**: при открытии экран сам запускает живой прогон (см. ниже).
- Параметры URL (необязательные):
  - `mode=fixtures` — офлайн‑снимок без сервера («Источник» → «Снимок без сервера»); то же задаёт `VITE_API_MODE=fixtures`, и это делает `scripts/run_simulator_ui.ps1 -Mode fixtures` (он печатает адрес с `&debug=1`, 048 S1);
  - `debug=1` — вход разработчика (048 S1, 2026-10-18): только с ним в «Подробнее» есть «Источник», Quality, бейдж SSE, кнопка Analytics (правый док аналитики, 048 S2) и на офлайн‑снимке — верстак плейлистов (§4); смена источника параметр сохраняет;
  - `mode=real` — источник сервер (он и так по умолчанию, `useSimulatorApp.ts` `apiMode`);
  - `ui=interact` и `ui=demo` в старой ссылке **игнорируются**: открывается тот же экран (с 043 S2/S3).

**Открытие — живой прогон.** Когда открытие закончено (сцена на экране), экран делает **одну попытку на загрузку страницы** запустить живой прогон существующим `startRun`: интенсивность из хранилища, а если её нет — темп экрана по умолчанию: 15 % у посетителя (нет админ-токена; публичное демо), 30 % у оператора (админ-токен), без паузы (044 стадия 2, `defaultIntensityPercentFor`). Темп 0, введённый вручную, не запускает и не применяется: в строке ошибки — подсказка «Темп 0 — прогон без платежей: укажите темп от 1 до 100. Остановить платежи — пауза.» Живой прогон, найденный на сервере (в том числе на паузе), остаётся как есть; остановленный человеком прогон заново не запускается (`useInteractAutoBootstrapRun.ts`, `autostartDecision`). Если у сервера исчерпан предел активных прогонов (409 `conflict_kind: global_active_limit`), в строке ошибки — читаемый текст на языке интерфейса с числом мест из ответа сервера (`details.max_active_runs`), например «Сейчас заняты все 10 мест: демо смотрят 10 человек. Попробуйте через минуту.», и кнопка «Повторить» / «Try again», запускающая прогон снова (046 волна 1, 2026-10-18; `utils/runErrorClassification.ts`, `startRunErrorText`, `isGlobalLimitRefusal`).

## 2) Базовые действия на сцене

- **Панорамирование/зум** — управляется “камерой” (мышь/тачпад в зависимости от окружения).
- **Выбор узла**: один клик по узлу выделяет его.
- **Карточка узла (Node Card)**: двойной клик по узлу открывает карточку.
- **Снятие выделения**: клик по пустому месту снимает выделение.
- **Подсказки по рёбрам (Edge tooltip)**: появляются при наведении на рёбра (см. описание Edge Tooltip ниже; есть ограничения по режимам).

## 3) Верхняя панель — TopBar

TopBar — основной HUD для режимов и управления запуском.

Примечание про тестовый режим: бейдж `TEST MODE` при `VITE_TEST_MODE=1` удалён 048 S1 (2026-10-18); сам флаг остаётся.

### 3.1 Первый взгляд (первый ряд)

«Подробнее» выключено (так по умолчанию; выбор запоминается в браузере, ключ `geo.sim.v2.details.open`). В первом ряду:

- имя сети и состояние сети текстом;
- **«Поток»** — кнопка ⏸/▶ рядом с состоянием: ⏸ ставит живой прогон на паузу, ▶ возобновляет приостановленный. Показывается только для прогона в состоянии `running` или `paused` (`TopBar.vue`, `flowState`);
- три действия **Send Payment / Manage Trustline / Run Clearing** (ActionBar, см. §5.1);
- **«Подробнее»** (▾/▴) — открывает служебные ряды.

В нижней полосе (§4) — легенда, компактный «Общий долг» и Reset view. Одна подсказка‑онбординг (статическая строка до тура 034 S9) исчезает после первого действия и не возвращается (`geo.sim.v2.onboarding.dismissed`). Плашка **Stall** («все платежи отклонены») — тоже на первом взгляде, пока платежи стоят (`consec_all_rejected_ticks` достиг порога; с 048 S1, раньше была под «Подробнее»).

### 3.2 Пауза при ручном действии

Любое явное ручное действие ставит прогон на паузу (`POST …/pause`): начало действия (Send Payment, Manage Trustline, Run Clearing, карточка участника, окно линии), выбор участника или линии, выбор отправителя, получателя, кредитора, должника (`useSimulatorApp.ts`, обёртка входов `interactMode`, `noteManualAction`). **Подтверждение, отмена, Escape и закрытая панель поток не возобновляют.** Возобновляет только явный акт — **«Поток»** (▶); кнопки Pause / Resume служебного ряда удалены 048 S1. Выбор, сделанный загрузкой (ссылка `?focus=`), актом не считается.

### 3.3 «Подробнее»: служебный верхний ряд

Появляется под первым рядом, пока «Подробнее» включено (`data-testid="top-details-row"`):

- **Theme** — тема интерфейса (`saas` по умолчанию, `hud`), под ней язык;
- выбор сценария, `Start` / `Stop`, интенсивность (проценты) и `Apply`, строка «No scenarios» — только при источнике «Сервер» **и с admin‑токеном** (048 S2, 2026-10-19: посетитель прогоном не управляет — автостарт сам берёт сценарий, паузу делает «Поток», остановленный сервером прогон запускается заново перезагрузкой страницы);
- статусы: причина остановки — всем, пассивным текстом; бейдж TX (`TX ok a/b · p%`; слова «Платежи: a из b» — 046 W1) — только с admin‑токеном (048 S2); бейдж SSE и кнопка **Analytics** (правый док аналитики, спека 007) — только с `?debug=1` (048 S1 и S2; без `?debug=1` док не показывается и не опрашивается, что бы ни помнил браузер). Бейдж Run state удалён 048 S1: состояние говорит первый ряд;
- меню **Admin ▾** упразднено 048 S2 (2026-10-19): список прогонов, Attach, Stop, Stop all и файлы прогона — только через API, «где и что смотреть» — `docs/ru/simulator/backend/real-mode-runbook.md`, раздел 6.7. Кнопки обновления каталога сценариев (↻) в интерфейсе нет (слово владельца 2026-10-19): каталог читается при загрузке страницы, после загрузки сценария — перезагрузить страницу;
- полные метрики системы (§5.2).

Отдельного меню «Advanced» больше нет (удалено 043 S3, 2026-10-17): интенсивность и `Apply` — прямо в ряду сценария и управления прогоном. Выбора режима прогона (строка Pipeline: real / sandbox) в меню тоже нет — убран 2026-10-16 (программа 042, стадия 2): клиент всегда создаёт прогон в режиме `real`, а ранее сохранённый выбор в браузере сбрасывается при загрузке. Сохранённая интенсивность `0` (её держал удалённый режим Interact) при чтении отбрасывается и заменяется на 30 (`useSimulatorApp.ts`, 043 S3).

## 4) Нижняя панель — BottomBar

BottomBar отвечает за настройки отображения и инструменты. На первом взгляде в нём одна полоса: легенда, компактный «Общий долг», Reset view. Служебный ряд (`data-testid="bottom-details-row"`) появляется над ней, пока включено «Подробнее».

### 4.1 View settings (под «Подробнее»)

- **EQ** (Equivalent): единица — текстом, когда вариант один, выбором, когда их больше (например `UAH`, `HOUR`, `EUR`).
- **Layout**: режим раскладки графа.
- **«Источник»** (только с `?debug=1`, 048 S1): «Сервер» (живой прогон) или «Снимок без сервера» (офлайн‑снимок на статических фикстурах; ни прогона, ни запросов к серверу). Смена перезагружает страницу с `?mode=` (и сохраняет `?debug=1`) — единственное переключение этого экрана, которое ещё делает навигацию (`SimulatorAppRoot.vue`, `setSource`); вход в ручное действие страницу не перезагружает.
- **Quality** (только с `?debug=1`, 048 S1): качество рендера.
- выбора **Labels** нет с 048 S2 (2026-10-19): подписи — по умолчанию `selection` (выбранный участник); сохранённый в браузере выбор (`geo.sim.labelsLod`) по-прежнему читается — так стенд включает `neighbors`.

Селектор **Scene** удалён 048 S1 (2026-10-18): у него не было читателя (офлайн‑снимок грузится по эквиваленту), `?scene=` в старой ссылке игнорируется.

### 4.2 Tools

Правая часть служебного ряда (под «Подробнее»):

- на офлайн‑снимке с `?debug=1`: верстак плейлистов («Плейлист», 042 `T4205`);
- **Inspect graph** (навигатор по графу).

048 S1 (2026-10-18): Refresh снимка удалён (обновление снимка остаётся путям восстановления), Analytics и Artifacts перенесены в «Admin ▾» верхней панели; 048 S2 (2026-10-19): «Admin ▾» упразднён, Analytics — в служебном ряду верхней панели с `?debug=1`, Artifacts — только через API (§3.3). Кнопки Dev Tools, Enter/Exit Demo UI и FX Debug удалены 043 S3 (2026-10-17); с 048 S1 у `?debug=1` снова есть читатель (`useSimulatorApp.ts`, `isDebugUi`). Reset view остаётся в нижней полосе первого взгляда.

## 5) Ручные действия (источник «Сервер»)

Ручные действия — часть единого экрана (отдельного режима Interact нет с 043 S2). Они действуют на идущий прогон и по §3.2 ставят его на паузу.

Подробнее про сценарии использования, предусловия (feature flag) и пошаговые флоу: см. [`interact-mode-user-guide.md`](interact-mode-user-guide.md).

### 5.1 ActionBar

ActionBar — панель ручных действий (первый ряд TopBar):

- **Send Payment** — ручной платёж (manual payment flow).
- **Manage Trustline** — создание/обновление/закрытие trustline.
- **Run Clearing** — запуск клиринга.

Состояния:
- Кнопки могут быть отключены, если UI занят (busy) или run в терминальном состоянии; без прогона все три выключены с указанием причины.

### 5.2 SystemBalanceBar

SystemBalanceBar показывает системные агрегаты. На первом взгляде — только компактный «Общий долг» в нижней полосе; остальные значения — в служебном ряду под «Подробнее»:

- Total Debt («Общий долг»)
- Available Capacity
- Trustlines
- Participants
- Utilization (progress)

Эти значения помогают понимать, есть ли «пространство» для новых платежей и как загружена сеть.

После клиринга над «Общим долгом» появляется «клиринг: было X → стало Y» — общий долг сети непосредственно до и после этого клиринга (039, срез D; решение советника 2026-10-19). Платежи эту строку не меняют: «Общий долг» под ней идёт дальше, а строка остаётся до следующего клиринга. Клиринг, ничего не погасивший, строку убирает; смена эквивалента, сценария, прогона и перезагрузка снимка — тоже. Оба числа — точные суммы долга по всем линиям показанного снимка, в его эквиваленте. Строка стоит над полосой, вне её потока, и размер полосы не меняет. Где это в коде: `src/composables/debtChange.ts` (снятие и условия показа), `realEventPipeline.ts` (место снятия — `clearing.done`), `SystemBalanceBar.vue` (вывод).

### 5.3 ManualPaymentPanel

Открывается при активном payment flow и ведёт по шагам:

1) **Pick From** — выберите отправителя кликом по узлу на сцене или в dropdown `From`.
2) **Pick To** — выберите получателя кликом по узлу или в dropdown `To`.
3) **Confirm** — введите сумму и нажмите `Confirm`.

Поля и валидация:
- Amount должен быть > 0.
- Если известна доступная capacity, UI показывает `Available` и предупреждает, если Amount её превышает.

Кнопки:
- `Confirm` — подтверждает платёж.
- `Cancel` — отменяет текущий payment flow.

### 5.4 TrustlineManagementPanel

Открывается при активном trustline flow.

Сценарии:

- **Create trustline**:
  1) Pick From
  2) Pick To
  3) Введите `Limit` и нажмите `Create`.

- **Edit trustline**:
  - Показывает Used / Limit / Available.
  - Введите `New limit` и нажмите `Update`.

- **Close trustline**:
  - Кнопка `Close TL` работает как «arming»:
    - первый клик — переводит в состояние подтверждения,
    - второй клик — подтверждает закрытие,
    - `Cancel close` или `ESC` снимает arm.

Dropdowns:
- `From` / `To` — выбор участников.
- `Existing` — выбор существующей trustline (если доступно).

### 5.5 EdgeDetailPopup (оверлей редактирования trustline)

Появляется при редактировании выбранной trustline (обычно после клика по ребру).

Возможности:
- Быстрый доступ к действию `Change limit` (переводит фокус на поле `New limit` в TrustlineManagementPanel).
- `Close line` — destructive действие, может требовать подтверждения.

### 5.6 ClearingPanel

Открывается при clearing flow:

- **Run clearing** (confirm): `Confirm` запускает clearing cycle.
- **Clearing preview**: показывает количество циклов и total cleared (и список циклов, если доступен).
- **Clearing running**: показывает состояние выполнения.

Кнопки:
- `Cancel`/`Close` — закрывает панель/отменяет flow.

## 6) Подсказки и оверлеи

### 6.1 EdgeTooltip

Появляется при наведении на trustline edge и показывает краткие значения (used/limit/available) в выбранном эквиваленте.

Ограничения/особенности:
- Поведение подсказок может отличаться в e2e/WebDriver режимах.

### 6.2 LabelsOverlayLayers

Слой подписей узлов и floating labels (например, суммы FX‑событий).

- Масштаб подписей адаптируется через CSS `--overlay-scale`.

### 6.3 NodeCardOverlay

Карточка выбранного узла (показывает имя/тип/метрики/баланс и т.п.).

- Открывается двойным кликом по узлу.
- Может поддерживать pin/unpin (в зависимости от режима и окружения).

### 6.4 DevPerfOverlay

Диагностический оверлей (включается параметром `perf=1`).

Показывает:
- WebGL vendor/renderer,
- предупреждения про software renderer,
- полезные метрики/текст для копирования.

## 7) Горячие клавиши

- `ESC`: отменяет активный flow.
- Если где-то включено destructive confirmation (arming), `ESC` сначала снимает arm (панель “consumes” ESC), и только если никто не “consumed” — выполняется глобальная отмена flow.
