# Simulator UI v2 — HUD: инструкция пользователя (RU)

Документ объясняет, **что делает каждый элемент HUD** в Simulator UI v2 и как им пользоваться.

Экран один (программа [043](../../../../../specs/043-demo-screen-minimal/spec.md), срезы S1–S3, 2026-10-16/17): режимов Sandbox / Auto‑Run / Interact и переключателя между ними больше нет. По умолчанию виден только первый взгляд; всё служебное прячется за одной кнопкой **«Подробнее»** и не отрисовывается, пока она выключена. Реестр терминов экрана — «Поток», «Подробнее», «Источник» — взят из самого интерфейса (`TopBar.vue`, `BottomBar.vue`); словарь RU/EN с переключателем — программа [046](../../../../../specs/046-ui-language/spec.md) (2026-10-18/19): язык выбирается под «Подробнее» (§3.3); приоритет — `?lang=ru|en` → сохранённый выбор (`geo.sim.v2.lang`) → первый язык браузера (`ru`/`uk`/`be` → русский, иначе английский) → английский (`src/i18n/locale.ts`). **Слова интерфейса в руководстве даны по-русски (словарь `simulator-ui/v2/src/i18n/ru.ts`); английская форма (`en.ts`) — в скобках там, где руководство прежде цитировало английскую.** Элементы под `?debug=1` (Analytics, «Источник», Quality, «Плейлист») не переводятся: это инструменты разработчика.

## 1) Как открыть

- Full stack: `http://localhost:5176/` — источник по умолчанию **сервер**: при открытии экран сам запускает живой прогон (см. ниже).
- Параметры URL (необязательные):
  - `mode=fixtures` — офлайн‑снимок без сервера («Источник» → «Снимок без сервера»); то же задаёт `VITE_API_MODE=fixtures`, и это делает `scripts/run_simulator_ui.ps1 -Mode fixtures` (он печатает адрес с `&debug=1`, 048 S1);
  - `debug=1` — вход разработчика (048 S1, 2026-10-18): только с ним в «Подробнее» есть «Источник», Quality, бейдж SSE, кнопка Analytics (правый док аналитики, 048 S2) и на офлайн‑снимке — верстак плейлистов (§4); смена источника параметр сохраняет;
  - `mode=real` — источник сервер (он и так по умолчанию, `useSimulatorApp.ts` `apiMode`);
  - `ui=interact` и `ui=demo` в старой ссылке **игнорируются**: открывается тот же экран (с 043 S2/S3).

**Открытие — живой прогон.** Когда открытие закончено (сцена на экране), экран делает **одну попытку на загрузку страницы** запустить живой прогон существующим `startRun`: интенсивность из хранилища, а если её нет — темп экрана по умолчанию: 15 % у посетителя (нет админ-токена; публичное демо), 30 % у оператора (админ-токен), без паузы (044 стадия 2, `defaultIntensityPercentFor`). Темп 0, введённый вручную, не запускает и не применяется: в строке ошибки — подсказка «Темп 0 — прогон без платежей: укажите темп от 1 до 100. Остановить платежи — пауза.» Живой прогон, найденный на сервере (в том числе на паузе), остаётся как есть; остановленный человеком прогон заново не запускается (`useInteractAutoBootstrapRun.ts`, `autostartDecision`). Если у сервера исчерпан предел активных прогонов (409 `conflict_kind: global_active_limit`), в строке ошибки — читаемый текст на языке интерфейса с числом мест из ответа сервера (`details.max_active_runs`), например «Сейчас заняты все 10 мест: демо смотрят 10 человек. Попробуйте через минуту.», и кнопка «Повторить» / «Try again», запускающая прогон снова (046 волна 1, 2026-10-18; `utils/runErrorClassification.ts`, `startRunErrorText`, `isGlobalLimitRefusal`).

## 2) Базовые действия на сцене

- **Панорамирование/зум** — управляется “камерой” (мышь/тачпад в зависимости от окружения).
- **Выбор узла**: один клик по узлу выделяет его.
- **Карточка узла (Node Card)**: двойной клик по узлу открывает карточку.
- **Снятие выделения**: клик по пустому месту снимает выделение.
- **Подсказки по рёбрам (Edge tooltip)**: появляются при наведении на рёбра (см. описание Edge Tooltip ниже; есть ограничения по режимам).

## 3) Верхняя панель — TopBar

TopBar — основной HUD для режимов и управления запуском.

Примечание про тестовый режим: бейдж `TEST MODE` при `VITE_TEST_MODE=1` удалён 048 S1 (2026-10-18); сам флаг остаётся.

### 3.1 Первый взгляд (первый ряд)

«Подробнее» выключено (так по умолчанию; выбор запоминается в браузере, ключ `geo.sim.v2.details.open`). В первом ряду:

- имя сети и состояние сети текстом;
- **«Поток»** — кнопка ⏸/▶ рядом с состоянием: ⏸ ставит живой прогон на паузу, ▶ возобновляет приостановленный. Показывается только для прогона в состоянии `running` или `paused` (`TopBar.vue`, `flowState`);
- три действия **«Платёж» / «Линия доверия» / «Клиринг»** (Send payment / Trust line / Clear mutual debts; ActionBar, см. §5.1);
- **«Подробнее»** (▾/▴) — открывает служебные ряды.

В нижней полосе (§4) — легенда, компактный «Общий долг» и «Показать всю сеть» (Fit network). Одна подсказка‑онбординг (статическая строка; называет три действия словами протокола, `onboarding.*` словаря) исчезает после первого действия и не возвращается (`geo.sim.v2.onboarding.dismissed`). Плашка «Последние платежи не проходят. Попробуйте клиринг или увеличьте лимит нужной линии.» (Stall; EN: «Recent payments are not going through. Try clearing or increase the relevant trustline's limit.»; мягче прежнего «лимиты исчерпаны» — детектор причину не доказывает, 049 S2) — тоже на первом взгляде, пока платежи стоят (`consec_all_rejected_ticks` достиг порога; с 048 S1, раньше была под «Подробнее»).

### 3.2 Пауза при ручном действии

Любое явное ручное действие ставит прогон на паузу (`POST …/pause`): начало действия («Платёж», «Линия доверия», «Клиринг», карточка участника, окно линии), выбор участника или линии, выбор отправителя, получателя, кредитора, должника (`useSimulatorApp.ts`, обёртка входов `interactMode`, `noteManualAction`). **Подтверждение, отмена, Escape и закрытая панель поток не возобновляют.** Возобновляет только явный акт — **«Поток»** (▶); кнопки Pause / Resume служебного ряда удалены 048 S1. Выбор, сделанный загрузкой (ссылка `?focus=`), актом не считается.

### 3.3 «Подробнее»: служебный верхний ряд

Появляется под первым рядом, пока «Подробнее» включено (`data-testid="top-details-row"`):

- **«Тема»** (Theme) — «Спокойная» (`saas`, по умолчанию) или «Контрастная» (`hud`; EN: Calm / Contrast (HUD)), под ней **«Язык»** — переключатель RU/EN (046);
- **«Сценарий»** (выбор), **«Старт»** / **«Стоп»**, **«Темп автоплатежей, %»** и **«Применить»**, строка «Сценарии не загрузились — попробуйте позже» (Scenario / Start / Stop / Auto-payment tempo, % / Apply / «No scenarios could be loaded — try again later») — только при источнике «Сервер» **и с admin‑токеном** (048 S2, 2026-10-19: посетитель прогоном не управляет — автостарт сам берёт сценарий, паузу делает «Поток», остановленный сервером прогон запускается заново перезагрузкой страницы);
- **«Темп»** посетителя — три ступени словами «медленно / обычно / быстро» (slow / normal / fast), только без admin‑токена и только на идущем или стоящем на паузе прогоне (049 S2, решение 10): ступень ставит темп прогона тем же запросом, что «Применить» у админа; отмечена ступень, на которой прогон идёт (темп вне трёх ступеней ничего не отмечает); проценты ступеней — в `docs/ru/simulator/backend/real-mode-runbook.md`. По умолчанию у посетителя «обычно»;
- **«Показывать события»** (Show events) — переключатель ленты событий сети в истории (049 S2, решение 5; см. `interact-mode-user-guide.md`, §4.3), всем при источнике «Сервер»;
- статусы: причина остановки (подпись «Остановка», например «остановлен кнопкой «Стоп»») — всем, пассивным текстом; бейдж платежей «Платежи: a из b прошли» (при b = 0 — «Платежей ещё не было»; процента нет — прежний `TX ok a/b · p%` заменён 046 W1 по слову 048 §G; EN: «Payments: a of b went through» / «No payments yet») — только с admin‑токеном (048 S2); бейдж SSE и кнопка **Analytics** (правый док аналитики, спека 007) — только с `?debug=1` (048 S1 и S2; без `?debug=1` док не показывается и не опрашивается, что бы ни помнил браузер). Бейдж Run state удалён 048 S1: состояние говорит первый ряд;
- меню **Admin ▾** упразднено 048 S2 (2026-10-19): список прогонов, Attach, Stop, Stop all и файлы прогона — только через API, «где и что смотреть» — `docs/ru/simulator/backend/real-mode-runbook.md`, раздел 6.7. Кнопки обновления каталога сценариев (↻) в интерфейсе нет (слово владельца 2026-10-19): каталог читается при загрузке страницы, после загрузки сценария — перезагрузить страницу;
- полные метрики системы (§5.2).

Отдельного меню «Advanced» больше нет (удалено 043 S3, 2026-10-17): интенсивность и `Apply` — прямо в ряду сценария и управления прогоном. Выбора режима прогона (строка Pipeline: real / sandbox) в меню тоже нет — убран 2026-10-16 (программа 042, стадия 2): клиент всегда создаёт прогон в режиме `real`, а ранее сохранённый выбор в браузере сбрасывается при загрузке. Сохранённая интенсивность `0` (её держал удалённый режим Interact) при чтении отбрасывается и заменяется на 30 (`useSimulatorApp.ts`, 043 S3).

## 4) Нижняя панель — BottomBar

BottomBar отвечает за настройки отображения и инструменты. На первом взгляде в нём одна полоса: легенда, компактный «Общий долг», «Показать всю сеть» (Fit network). Служебный ряд (`data-testid="bottom-details-row"`) появляется над ней, пока включено «Подробнее».

### 4.1 View settings (под «Подробнее»)

- **«Эквивалент»** (Equivalent; прежняя подпись EQ): единица — текстом, когда вариант один, выбором, когда их больше (например `UAH`, `HOUR`, `EUR`).
- **«Раскладка»** (Layout): режим раскладки графа — «облако», «группы», «по балансу», «по типу», «по статусу» (EN: cloud / groups / by balance / by type / by status).
- **«Источник»** (только с `?debug=1`, 048 S1): «Сервер» (живой прогон) или «Снимок без сервера» (офлайн‑снимок на статических фикстурах; ни прогона, ни запросов к серверу). Смена перезагружает страницу с `?mode=` (и сохраняет `?debug=1`) — единственное переключение этого экрана, которое ещё делает навигацию (`SimulatorAppRoot.vue`, `setSource`); вход в ручное действие страницу не перезагружает.
- **Quality** (только с `?debug=1`, 048 S1): качество рендера.
- выбора подписей (Labels) нет с 048 S2 (2026-10-19): подписи — по умолчанию `selection` (выбранный участник); сохранённый в браузере выбор (`geo.sim.labelsLod`) по-прежнему читается — так стенд включает `neighbors`.

Селектор **Scene** удалён 048 S1 (2026-10-18): у него не было читателя (офлайн‑снимок грузится по эквиваленту), `?scene=` в старой ссылке игнорируется.

### 4.2 Tools

Правая часть служебного ряда (под «Подробнее»):

- на офлайн‑снимке с `?debug=1`: верстак плейлистов («Плейлист», 042 `T4205`);
- **«Найти на графе»** (Find on graph; навигатор по графу): списки «Участник» и «Линия» с кнопками «Открыть участника» / «Открыть линию».

048 S1 (2026-10-18): Refresh снимка удалён (обновление снимка остаётся путям восстановления), Analytics и Artifacts перенесены в «Admin ▾» верхней панели; 048 S2 (2026-10-19): «Admin ▾» упразднён, Analytics — в служебном ряду верхней панели с `?debug=1`, Artifacts — только через API (§3.3). Кнопки Dev Tools, Enter/Exit Demo UI и FX Debug удалены 043 S3 (2026-10-17); с 048 S1 у `?debug=1` снова есть читатель (`useSimulatorApp.ts`, `isDebugUi`). «Показать всю сеть» (Reset view до 046) остаётся в нижней полосе первого взгляда.

## 5) Ручные действия (источник «Сервер»)

Ручные действия — часть единого экрана (отдельного режима Interact нет с 043 S2). Они действуют на идущий прогон и по §3.2 ставят его на паузу.

Подробнее про сценарии использования, предусловия (feature flag) и пошаговые флоу: см. [`interact-mode-user-guide.md`](interact-mode-user-guide.md).

### 5.1 ActionBar

ActionBar — панель ручных действий (первый ряд TopBar):

- **«Платёж»** (Send payment) — ручной платёж (manual payment flow); подсказка кнопки: «Сумма дойдёт до получателя по цепочке доверия.»
- **«Линия доверия»** (Trust line) — создание/обновление/закрытие trustline; подсказка: «Задаёт, сколько один участник может быть должен другому.»
- **«Клиринг»** (Clear mutual debts) — запуск клиринга; подсказка: «Долги, идущие по кругу, взаимно гасятся — у каждого участника круга долг уменьшается.»

Состояния:
- Кнопки могут быть отключены, если UI занят (busy) или run в терминальном состоянии; без прогона все три выключены с указанием причины.

### 5.2 SystemBalanceBar

SystemBalanceBar показывает системные агрегаты. На первом взгляде — только компактный «Общий долг» в нижней полосе; остальные значения — в служебном ряду под «Подробнее»:

- «Общий долг» (Total debt)
- «Свободно по линиям» (Free on lines; до 049 S2 — «Доступно для платежей», прежде Available Capacity); краткие определения показателей — в `title` их плашек
- «Линии доверия» (Trust lines)
- «Участники» (Participants)
- «Занято лимитов» (Limits in use; прежде Utilization): процент и полоса

Эти значения помогают понимать, есть ли «пространство» для новых платежей и как загружена сеть.

После клиринга над «Общим долгом» появляется «клиринг: было X → стало Y» — общий долг сети непосредственно до и после этого клиринга (039, срез D; решение советника 2026-10-19). Платежи эту строку не меняют: «Общий долг» под ней идёт дальше, а строка остаётся до следующего клиринга. Клиринг, ничего не погасивший, строку убирает; смена эквивалента, сценария, прогона и перезагрузка снимка — тоже. Оба числа — точные суммы долга по всем линиям показанного снимка, в его эквиваленте. Строка стоит над всей нижней полосой справа, вне её потока, и размер полосы не меняет; при открытом «Подробнее» — выше кнопки «Найти на графе» (039 D-fix, 2026-10-19: над одной панелью «Общего долга» она ложилась на легенду, когда ряд переносится, и на служебный ряд). Строка появляется и после автоматического клиринга: тик публикует `clearing.done` раньше роста доверия (`docs/ru/simulator/scenarios-and-engine.md`, §2.11). Где это в коде: `src/composables/debtChange.ts` (снятие и условия показа), `realEventPipeline.ts` (место снятия — `clearing.done`), `SystemBalanceBar.vue` (вывод).

### 5.3 ManualPaymentPanel

Открывается при активном payment flow и ведёт по шагам:

1) **Отправитель** — кликом по узлу на сцене или в списке «От кого» (From); пустое поле подсказывает «На графе или из списка».
2) **Получатель** — кликом по узлу или в списке «Кому» (To); форма говорит «Выберите получателя.».
3) **Подтверждение** — введите сумму и нажмите «Отправить» (Confirm).

Поля и валидация:
- «Сумма» (Amount) должна быть больше нуля («Введите сумму больше нуля.»).
- Информационная строка показывает «Напрямую» (доступное по прямой линии) и «Макс.» (оценка сервера); если сумма больше, — предупреждение «Сумма может быть больше доступного по прямой линии (…)» или «Сумма больше оценки сервера для максимума (…); решает сервер.». Отправку оно не блокирует.

Кнопки:
- «Отправить» (Confirm) — подтверждает платёж.
- «Отмена» (Cancel) — отменяет текущий payment flow.

### 5.4 TrustlineManagementPanel

Открывается при активном trustline flow.

Сценарии:

- **Создание** (Create trustline):
  1) выберите «Кто доверяет» (From)
  2) выберите «Кому» (To)
  3) введите «Лимит» (Limit) и нажмите «Создать» (Create).

- **Изменение** (Edit trustline):
  - Показывает «Долг … · Лимит … · Доступно …» (Used / Limit / Available); при долге выше лимита — «Сверх лимита на …».
  - Введите новый «Лимит» (New limit) и нажмите «Сохранить» (Update).

- **Close trustline**:
  - Кнопка «Закрыть линию» (Close line; у линии с долгом — «Запросить закрытие» / Request close: лимит станет 0, линия закроется, когда долг будет погашен) работает как «arming»:
    - первый клик — переводит в состояние подтверждения («Точно закрыть» / Confirm close),
    - второй клик — подтверждает закрытие,
    - «Не закрывать» (Cancel close) или `ESC` снимает arm.

Dropdowns:
- «Кто доверяет» / «Кому» (From / To) — выбор участников.
- «Линия» (Existing) — выбор существующей trustline (если доступно).

### 5.5 EdgeDetailPopup (оверлей редактирования trustline)

Появляется при редактировании выбранной trustline (обычно после клика по ребру).

Возможности:
- Заголовок — «A → B» (кредитор → должник) и строка «A доверяет B до лимита — столько B может быть должен A.».
- «Заплатить A» (Pay; имя — кредитор линии, платёж идёт ему; без имени — «Заплатить») — платёж из этой линии.
- «Изменить» (Change limit) — переводит фокус на поле «Лимит» в TrustlineManagementPanel.
- «Закрыть» (Close line) — destructive действие, может требовать подтверждения.

### 5.6 ClearingPanel

Открывается при clearing flow:

- **«Клиринг»** (Run clearing, подтверждение): «Запустить» (Confirm) запускает clearing cycle.
- **«Идёт клиринг…»** (Running clearing…): состояние выполнения.
- **«Итог клиринга»** (Clearing result): «Погашено кругов» (Cycles cleared), «Сумма по кругам» (Total over cycles) и по каждому кругу — «Круг n из m: сумма»; без кругов — «Ничего не погашено: долгов, идущих по кругу, не найдено.».

Кнопки:
- «Отмена» / «Закрыть» (Cancel / Close) — закрывает панель/отменяет flow.

## 6) Подсказки и оверлеи

### 6.1 EdgeTooltip

Появляется при наведении на trustline edge и показывает две фразы в выбранном эквиваленте: «A доверяет B до {лимит}» и «долг B перед A — {использовано} · доступно {доступно}» (при долге выше лимита — «сверх лимита на …»; EN: «A trusts B up to …» / «B owes A … · available …»).

Ограничения/особенности:
- Поведение подсказок может отличаться в e2e/WebDriver режимах.

### 6.2 LabelsOverlayLayers

Слой подписей узлов и floating labels (например, суммы FX‑событий).

- Масштаб подписей адаптируется через CSS `--overlay-scale`.

### 6.3 NodeCardOverlay

Карточка выбранного узла (показывает имя/тип/метрики/баланс и т.п.): «Доверяет:» / «Доверяют:» (суммы лимитов), группы «Доверяет (N)» / «Доверяют (N)», кнопки «Платёж», «Новая линия», «Изменить», «Закрепить» / «Открепить».

- Открывается двойным кликом по узлу.
- Может поддерживать pin/unpin (в зависимости от режима и окружения).

### 6.4 DevPerfOverlay

Диагностический оверлей (включается параметром `perf=1`).

Показывает:
- WebGL vendor/renderer,
- предупреждения про software renderer,
- полезные метрики/текст для копирования.

## 7) Горячие клавиши

- `ESC`: отменяет активный flow.
- Если где-то включено destructive confirmation (arming), `ESC` сначала снимает arm (панель “consumes” ESC), и только если никто не “consumed” — выполняется глобальная отмена flow.
