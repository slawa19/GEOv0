# GEO Simulator Frontend — Performance & Quality Policy (software-only / low FPS)

Статус: Active
Область: simulator/frontend
Последнее обновление: 2026-10-11 (раздел 7 и пометки «Критерий» — программа 038, срез S3; прежний текст разделов 0–6 сохранён)

Цель: сделать UI симулятора **устойчивым к окружениям без GPU-ускорения**, не меняя семантику визуализации и контрактов данных.

Контекст: при включении software-only рендера в Chrome (например, `Microsoft Basic Render Driver`) стоимость каждого кадра (Canvas 2D + композитинг) может вырасти на порядки. Поэтому сравнение с SimpleBrowser VS Code не всегда корректно: SimpleBrowser может работать через реальный GPU, а Chrome — через софт.

## 0) Термины

- **GPU-ускорение доступно**: браузер использует аппаратный рендеринг для compositing/canvas (обычно через реальный GPU).
- **software-only**: браузер рендерит через софт (CPU), часто с `WebGL`/compositing в режиме software.

## 1) Диагностика (для разработчиков)

- Встроенный оверлей диагностики: открыть симулятор с `?perf=1`.
- Браузерный уровень: `chrome://gpu` (ищем `Software only` и признаки `Microsoft Basic Render Driver`).

## 2) Heuristic: определение software-only

UI выполняет «лёгкую» проверку доступности GPU-ускорения:

1) Пытаемся получить WebGL контекст (не для рендера, а для диагностики/идентификации).
2) Если доступно расширение `WEBGL_debug_renderer_info`, читаем `UNMASKED_RENDERER_WEBGL`.
3) Если renderer указывает на software-рендер (например, `Microsoft Basic Render Driver`, `SwiftShader`, `llvmpipe`) — считаем режим software-only.

Важно:
- Это **эвристика**, а не криптографически точная проверка.
- Политика деградации должна быть safe-by-default: лучше «слегка ухудшить визуал», чем получить ~1 FPS и неработоспособный UI.

## 3) Политика качества (авто-деградация)

### 3.1 Базовое правило (software-only)

Если режим распознан как software-only, UI автоматически:

- выбирает `quality=low` как безопасный дефолт (если пользователь не успел вручную переключить качество вскоре после старта),
- отключает дорогие UI-эффекты типа `backdrop-filter` через признак окружения (см. CSS gating).

### 3.2 Safety net на старте ("1 FPS сразу после открытия")

Если на стартовом экране измеренный FPS очень низкий (порядка < ~12 за короткое окно) и пользователь не успел вручную переключить качество, UI также переводит качество в `low`.

Это отдельная защита на случай, когда WebGL-эвристика не сработала/недоступна, но baseline кадр уже слишком дорогой.

**Критерий (2026-10-11).** «Порядка < ~12» — это `fps < 12` за первые 1800 мс после монтирования (`simulator-ui/v2/src/composables/useQualityAutoguards.ts`). Поведение держит `simulator-ui/v2/e2e/qa/quality-guard.qaperf.ts`: при WebGL «в наличии» и около 8 fps на старте качество становится `low`; при частоте дисплея остаётся `med`; под WebDriver страж выключен намеренно. Базовое правило 3.1 держит `e2e/qa/probes.qa.ts` (software-рендер → `low`).

## 4) Политика рендера (Canvas)

Принцип: деградируем **только визуальные эффекты/LOD**, не меняем данные, направление trustlines, семантику цветов/толщин.

### 4.1 Shadow blur

Per-object `shadowBlur` на Canvas 2D — один из самых дорогих эффектов в software-only режиме.

- В `quality=low` blur выключается.
- В software-only режиме glow для нод рисуется через **pre-baked sprite** (см. ниже), чтобы сохранить эстетичный glow без per-frame blur.

### 4.2 Pre-baked glow sprites (software-only fallback)

В software-only режиме glow слои (bloom/rim) рисуются как кэшированные спрайты (генерируются один раз и переиспользуются через `drawImage`).

Это сохраняет «приятный» glow-вид, но резко снижает стоимость кадра по сравнению с `shadowBlur`.

**Критерий (2026-10-11).** Число присваиваний ненулевого `shadowBlur` контексту экранной канвы за период нагрузки — бюджет `ONSCREEN_SHADOW_BLUR_SETS_NO_GPU` (`simulator-ui/v2/e2e/qa/budgets.ts`).

## 5) CSS gating (DOM/UI)

Дорогие CSS эффекты (например, `backdrop-filter`) отключаются не только по `quality`, но и по признаку окружения (software-only), чтобы избежать композитинга blur в «плохих» окружениях.

**Критерий (2026-10-11).** Число элементов с вычисленным `backdrop-filter` под нагрузкой без открытых окон — бюджет `ELEMENTS_WITH_BACKDROP_FILTER_NO_GPU`.

**Известный пробел (2026-10-11, измерен; не исправлен).** Gating не покрывает `filter: drop-shadow(...)` у плавающих меток сумм (`.floating-label-inner`, `simulator-ui/v2/src/App.css`): фильтр снят только под WebDriver. На software-композитинге каждая такая метка фильтруется заново на каждом кадре. Текущее состояние записано бюджетом-долгом `PEAK_LABELS_WITH_CSS_FILTER_NO_GPU` (цель — 0); измеренная цена — в разделе 7.3. Правка меняет вид меток без GPU и требует решения владельца.

## 6) Где реализовано (код)

- Политика качества + эвристика GPU: `simulator-ui/v2/src/composables/useSimulatorApp.ts`
- Оверлей диагностики: `simulator-ui/v2/src/components/DevPerfOverlay.vue`
- CSS gating: `simulator-ui/v2/src/App.css`
- Pre-baked glow sprites cache: `simulator-ui/v2/src/render/glowSprites.ts`
- Использование спрайтов в рендере нод: `simulator-ui/v2/src/render/nodePainter.ts`

## 7) Измеримые критерии (2026-10-11, программа 038, срез S3)

Словесные критерии разделов 3–5 («устойчив», «резко снижает», «порядка») проверяются стендом `simulator-ui/v2/e2e/qa/` на Chromium без GPU (`--disable-gpu --disable-accelerated-2d-canvas --disable-gpu-compositing`), в пользовательском режиме (без тест-режима, `navigator.webdriver = false`). Числа здесь не дублируются: владелец значения — константа или файл отчёта.

### 7.1 Дискретные бюджеты — норматив

Константы — `simulator-ui/v2/e2e/qa/budgets.ts`; проверка — `e2e/qa/budgets.qaperf.ts`. Это счётчики на подменных часах (`page.clock`), от скорости машины они не зависят. Храповик двусторонний: тест падает и при ухудшении, и при незаписанном улучшении; каждое движение значения — датированная строка с причиной в `budgets.ts`.

| Что обещает политика | Бюджет |
|---|---|
| В покое UI не тратит CPU на отрисовку | `DRAWS_IN_2S_DEEP_SLEEP`, `RAF_CALLS_IN_2S_DEEP_SLEEP` |
| Событие будит цикл сразу и рисуется один раз за кадр | `DRAWS_IN_48MS_AFTER_EVENT`, `DRAWS_IN_ONE_PERIOD_OF_LOAD` |
| Цикл бодрствует не дольше эффекта | `DRAWS_FOR_ONE_PAYMENT_FROM_SLEEP` |
| При низком FPS бюджет эффектов опускается, лимит частиц соблюдается | `FX_BUDGET_SCALE_X1000_AT_SUSTAINED_10_FPS`, `MAX_PARTICLES_AT_SUSTAINED_10_FPS`, `MAX_PARTICLES_AT_60_FPS`, `FRAMES_WITH_LIVE_FX_ABOVE_THE_CAP` |
| Число DOM-меток ограничено | `LIVE_LABELS_CAP` |
| После потока событий ничего не остаётся жить | `LIVE_FX_AFTER_THE_STREAM`, `LIVE_LABELS_AFTER_THE_STREAM` |
| Названная нагрузка действительно показана (меньше рисовать — не улучшение) | `PEAK_SPARKS_IN_ONE_PERIOD`, `PEAK_EDGE_PULSES_IN_ONE_PERIOD`, `PEAK_NODE_BURSTS_IN_ONE_PERIOD`, `PEAK_LABELS_IN_ONE_PERIOD` |
| Без GPU нет per-frame blur на канве и `backdrop-filter` в DOM | `ONSCREEN_SHADOW_BLUR_SETS_NO_GPU`, `ELEMENTS_WITH_BACKDROP_FILTER_NO_GPU` |
| Долг: CSS-фильтр меток без GPU | `PEAK_LABELS_WITH_CSS_FILTER_NO_GPU` |

Команда (PowerShell, из корня репозитория; порт — свой):

```powershell
$env:PW_E2E_PORT = "5281"
npm --prefix simulator-ui/v2 run test:e2e:qa:perf -- budgets.qaperf quality-guard.qaperf
```

На production-сборке (`$env:QA_STAND_SERVER = "preview"`) бюджеты, читаемые из FX-состояния, не измеряются (dev-хука нет) — тест помечает их пропущенными с причиной; счётчики отрисовок и меток измеряются на обеих сборках.

### 7.2 Время кадра — диагностика, не норматив

Время кадра, fps, JS-работа за кадр и рост heap — свойство машины. Они измеряются (`e2e/qa/frame.qaperf.ts`), записываются в `qa-perf-summary-<dev|preview>.json` выходного каталога Playwright вместе с машиной, ОС, версией Chromium, сборкой, троттлингом и разбросом десяти окон, и **не являются порогом**: тест падает только на пустом измерении (нет кадров продукта, нагрузка доставлена не целиком, метки не анимируются). Нагрузка — названная и детерминированная: `S3-MIXED-V1` (`e2e/qa/perf-load.ts`), её отпечаток закреплён константой `LOAD_FINGERPRINT`.

```powershell
$env:PW_E2E_PORT = "5281"; $env:QA_STAND_SERVER = "preview"
npm --prefix simulator-ui/v2 run test:e2e:qa:perf
```

Сравнивать два прогона можно только на одной машине и только если разница больше записанного в отчёте разброса (`spreadPct`, `noiseX4`). На раннеры CI числа не переносятся.

### 7.3 Датированный результат (не норматив)

2026-10-11, production-сборка, AMD Ryzen 7 7700, Windows 11, Chromium 143.0.7499.4 без GPU, 1280×720, 100 узлов / 348 линий, качество `low`, нагрузка `S3-MIXED-V1`; медиана трёх прогонов (min..max). Команда — в 7.2; разбор кадра — `npm --prefix simulator-ui/v2 run test:e2e:qa:perf -- frame-breakdown.qaperf`.

Два замера в один день на одной машине (параллельно на ней шли другие прогоны Playwright; расхождение замеров — мера шума, а не изменение продукта):

| Троттлинг CPU (только главный поток) | fps, замер 1 | fps, замер 2 | p95 кадра, мс (1 / 2) | p95 JS за кадр, мс (1 / 2) |
|---|---|---|---|---|
| ×1 | 16.1 (13.1..16.4) | 13.9 (13.8..15.1) | 115.8 / 140.4 | 2.7 / 2.9 |
| ×4 | 8.7 (8.2..10) | 8.0 (8..8.8) | 167.5 / 177.5 | 15.1 / 13.5 |
| ×8 | 4.2 (4..4.3) | 3.7 (3.4..3.7) | 345 / 426.3 | 33.8 / 34.6 |

Разброс десяти окон ×4 подряд в одной странице: fps 7.7 (7.4..7.9) и 8.4 (8..8.7); p95 кадра 188.7 (172.6..210.9) и 173.1 (159.9..222.3) — различие двух прогонов меньше примерно 15 % по fps и 35 % по p95 кадра ничего не значит.

Куда уходит кадр (трасса и вычитание, тот же день):

- **Без троттлинга кадр ограничен не JS и не канвой, а композитором дисплея:** около 59 мс на кадр занимает `SoftwareRenderer::DoDrawQuad` — софтверная отрисовка слоёв меток с `filter: drop-shadow`. Те же метки без фильтра — 60 fps вместо 17; без `text-shadow` — 18; без самой CSS-анимации (метки стоят) — 17: дорог фильтр, а не движение.
- **При ×4 основное время главного потока — отложенная растеризация команд Canvas 2D** (`CanvasResourceProviderSharedImage::ProduceCanvasResource`, около 76–80 мс на кадр) при 13–16 мс скрипта; стиль, лэйаут, запись paint и GC вместе — менее 7 мс. Это и есть «остаток кадра вне JS-колбэков». Четверть пикселей (640×360) даёт +11 % fps: цена — в числе команд рисования (348 рёбер и 100 узлов перерисовываются каждый кадр), а не в площади.
- Скрытие HUD и FX-канвы, `deviceScaleFactor: 2` (канва при `low` остаётся 1280×720) — в пределах шума.

Чего эти числа не говорят: троттлинг CDP замедляет только главный поток рендерера, композитор и растровые потоки идут на полной скорости 16-поточной машины — на настоящем слабом процессоре без GPU композитор будет медленнее, чем здесь; встроенная графика, другие браузеры и живой бэкенд не измерялись (`docs/ru/simulator/frontend/docs/qa-stand.md`).
