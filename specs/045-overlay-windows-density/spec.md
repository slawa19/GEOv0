## Problem

Окна закрывают холст — главный объект демо (043: холст ≥ 85 %). На шаге выбора окно платежа занимает 440×240 px при полезном содержимом «два поля и кнопка»; на шаге подтверждения по коду ≈ 495 px высоты ради одного нужного числа (доступная сумма). Карточка участника при полном списке линий ≈ 445 px при 40 px мёртвой полосы. Причины — не дизайн-решения, а накопившиеся значения токенов и локальные правила: рельса подписей 110 px под слово «From», контролы 34 px, шаг стека 14 px, подсказка без размера шрифта (наследует 15 px тела — крупнее подписи), служебный текст в заголовке, кнопка отмены отдельным рядом, семь информационных строк на подтверждении. Денежной потери нет; потеря — читаемость главного демо и место на холсте.

## Решения

1. **Одна шкала на существующих токенах, без новых имён.** Ширина окна 360 (панели действий) / 320 (карточка, окно линии); паддинг 10; контрол и кнопка 28; рельса подписей 72; шаг 8; три размера шрифта — 13 (заголовок), 12 (подпись, контрол, кнопка, значение, подсказка), 10.5 (meta). *(2026-10-17, уточнено замером S1: для 10.5 в списке токенов S1 токена нет — размер переносится в S2/S3.)* Механизм — уже существующий `[data-density='compact']` (`tokens.css:467-482`, сейчас включён только в dev-демо), выставленный на контейнер окон `.wm-layer`; HUD-полосы остаются `comfortable`. Внутри шелла панель занимает всю ширину (`.ws-shell .ds-ov-panel{max-width:100%}`); карточка — `auto`.
2. **Размещение внутри окна — правила для всех пяти:** подсказка живёт в `placeholder` поля, отдельная строка — только причина отказа/предупреждение и только когда есть; заголовок = действие + пара, без «(ESC to close)» (Escape — в `title`/`aria-keyshortcuts`, обработка уже в WM); подтверждение и отмена в одном ряду `[Cancel][Primary]`, primary `disabled` до валидности вместо появления; одна информационная строка на окно (значения через « · », источник серым); эмодзи в кнопках → текст; `ds-alert` только для ошибок сервера и неизвестного исхода платежа.
3. **Порядок полей по сценарию.** Платёж: From → To → Amount [UAH] → «Available 88 UAH · 2 hops · server» → причина → [Cancel][Confirm]; результат — таблица на рельсе 72, [Close][Another]. Доверие: From → To → Limit → [Cancel][Create]; правка: Existing → «Used 12 / Limit 100 · avail 88» → New limit → причина → [Cancel][Close TL][Update]. Клиринг: заголовок «Run clearing · UAH», одна строка, [Cancel][Confirm]; результат одной строкой + список. Карточка: шапка одной строкой, статистика одной строкой, `[Pay][New line]`, строки линий 20 px без третьей колонки (avail — в `title`), список ≤ 5 строк и скролл. Окно линии: «Alice → Bob», строка «Used / Limit · avail · active» + бар, предупреждения `.ds-help`, один ряд кнопок `--sm`.
4. **Чистка кода** по F-045-13: safe delete — `--legacy-positioned`, `ds-text-secondary`, `rootClass`, дубли `justify-content`, пять локальных margin, `--ds-mpp-min-h`/`--ds-cp-min-h`; verify first — инлайновые `position:static` вместе с `position:absolute`-правилами и двумя гардами, «(ESC to close)» вместе с тремя текстовыми гардами (§11 — тесты формулировок), `forceHidden` (8 тестов), `.ds-controls*`, снапшоты `legacyReference` (снять — 041 F-041-9 уже назвал); keep — framed-режим `WindowShell` (WM не переписывается; записать как runtime-dead), константы `DEFAULT_WM_*` (долг «два источника» в BACKLOG), телефонные `@media`, темы.
5. **Полы высоты убрать**, `--ds-wm-interact-minh` → 0 (или ≤ 120), иначе после диеты невидимый шелл перекрывает холст (F-045-12).

Цель по числам (оценка по CSS, подтверждается измерением DOM в S1/S2): окно платежа 440×240 → 360×≈190 (выбор), ≈495 → ≈240 (подтверждение); карточка 360/320 → 320, ≈445 → ≈250 при пяти строках.

## Non-goals

- Не менять алгоритмы и константы WM, не чинить плотность инлайновыми px или `!important`, не заводить новых per-компонентных токенов (образец расползания — 29 `--ds-nco-*` на одну карточку).
- Не удалять телефонные блоки, framed-режим WM, замороженные темы.
- Не менять тексты причин отказа и сообщений сервера (их держат тесты и 034 S9 словарь); не вводить иконки/библиотеку компонентов.
- Не добавлять текстовых гардов на новые формулировки: поведение держится `data-testid`.
