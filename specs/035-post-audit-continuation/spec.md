## Problem

Волна 017–033 решила свою задачу: один писатель долгов, одна транзакция платежа, одна модель изоляции, админка сокращена честно. Цели 032/033 подтверждены по коду (24 обещания — все на месте; из «−117 тыс. строк» код — около 25 тыс., остальное фикстуры). Класс 1 аудит не нашёл: путей записи долга мимо `Book` нет, нулевая сумма проверяется на обоих писателях.

Следующий слой проблем другой — **стоимость сопровождения и проверки**, и у него есть наблюдаемый вред:

- любой аутентифицированный участник может надолго заблокировать event loop процесса диагностическим `GET /clearing/cycles` (F-035-1);
- `GET /trustlines` на 200 строк делает порядка 800 запросов (F-035-2);
- запись аудита целостности теряется молча под `except Exception: pass` (F-035-4);
- у backend-тира нет счёта собранных элементов, и удаление модуля тестов пройдёт незамеченным (F-035-14);
- AGENTS.md и документация описывают несуществующее как текущее, и агенты принимают это за правду (F-035-17, F-035-18);
- обязательный `required-backend` вырос с 7–10 до 15–18 минут при тестах в 2,9 раза больше кода (F-035-15).

Всё — класс 2 по §19.5. Основание для рефакторинга без потери — П2.

## Current / Intended / Optimal

- **Current.** Ядро корректно по деньгам, но чтение и диагностика тащат копии правил и механизмов до 023; тир тестов в 2,9 раза больше кода, 63 % — файлы-протоколы ревью по номерам программ; процессные документы несут устаревшие утверждения, которым агенты верят.
