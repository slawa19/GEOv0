## Problem

Волна 017–033 решила свою задачу: один писатель долгов, одна транзакция платежа, одна модель изоляции, админка сокращена честно. Цели 032/033 подтверждены по коду (24 обещания — все на месте; из «−117 тыс. строк» код ≈25 тыс., остальное фикстуры). Класс 1 аудит не нашёл; `T3500` подтвердил `CLASS-1-COUNT: 0` с оговоркой read-only evidence («не доказательство отсутствия»).

Следующий слой проблем — **стоимость сопровождения и проверки**, и у него есть наблюдаемый вред:

- любой аутентифицированный участник может надолго занять event loop процесса диагностическим `GET /clearing/cycles` (F-035-1);
- `GET /trustlines` на 200 активных линий делает ≈801 запрос сервиса (F-035-2);
- запись аудита целостности при ошибке подготовки теряется молча (F-035-4);
- у backend-тира нет счёта собранных элементов — удаление модуля тестов пройдёт незамеченным (F-035-14);
- AGENTS.md и документация описывают несуществующее как текущее, и агенты принимают это за правду (F-035-17, F-035-18);
- обязательный `required-backend` идёт 15–18 минут при тестах в 2,9 раза больше кода (F-035-15) — **причина не измерена**, сравнение с SQLite-тиром 2026-09-07 причинным не является (`T3500`).

Всё — класс 2 по §19.5. Основание для рефакторинга без потери — П2; без него идут F-035-1, F-035-2, F-035-4, F-035-14 и срез D как дефекты доступности, честности проверки и записи с репродьюсерами.
