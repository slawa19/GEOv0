## Problem

Владелец хочет, чтобы агенты довели Simulator UI до состояния «без явных косяков и тормозов» **до** ручного тестирования, чтобы человек тратил время на вкус и движение, а не на поиск дефектов. Сегодняшний автоматический стенд этого сделать не может, потому что **он не видит ровно те четыре вещи, о которых спросил владелец**:

1. **Анимацию.** Все Playwright-прогоны идут с `VITE_TEST_MODE=1` (`playwright.config.ts:40-41`, `e2e/playwright.phase5.config.ts:34-35`), а в этом режиме под WebDriver спавн искр и вспышек — пустая операция (`render/fxRenderer/spawn.ts:19`, `realFx/useRealTxFx.ts:181-184`, `useRealClearingFx.ts:199,215` ✓); снимки сцен снимаются с `animations: 'disabled'` (`e2e/scenes.spec.ts:11`). Ни один тест не читает пиксели канвы, не управляет часами (`page.clock`) и не утверждает ни одного свойства движения. «Scene D — Tx burst» и «Scene E — Clearing» зелёные на заглушках `e2eTxOnce`/`e2eClearingOnce`, которые лишь подсвечивают ребро на 1500 мс (F-034-D5).
2. **Взаимодействие.** В тест-режиме отключены перетаскивание узлов (`useAppDragToPinAndPreview.ts:36`), pointer-пан и зум камеры (`useCamera.ts:372,476`), pointerdown на канве (`useCanvasInteractions.ts:131,155`), физика (`useSimulatorApp.ts:1275`), hover рёбер (`useEdgeHover.ts:30`). Единственный юнит-тест перетаскивания проверяет снятие pointer capture (`useDragToPinInteraction.test.ts:19`); перенос узла на дельту мыши с учётом камеры не утверждается нигде.
3. **Производительность.** В тест-режиме цикл рендера **никогда не засыпает** (`useRenderLoop.ts:573` ✓ `if (deps.isTestMode()) return true`), лимит частиц и запись `__lastFps`/`__fxBudgetScale` пропускаются (`:501` ✓), DPR-кламп выключен (`:432`). Политика деградации без GPU (`docs/ru/simulator/frontend/docs/performance-and-quality-policy.md`, `09-decisions-and-defaults.md` §1.9) существует с января 2026, но **ни одно её число не измеряется тестом**: нет замера кадра, нет проверки остановки цикла в покое, нет прогона на software-only Chromium. «0 измерений» сегодня неотличимо от «0 проблем» (AGENTS.md §1).
4. **Окна и меню.** Каталог поверхностей `ui-kit/overlaySurfaceCatalog.ts:160-350` перечисляет 16 типов (окна WM, HUD-выпадающие, `OverlaySelect`, тосты, попапы, тултип, оверлеи), но ни один тест не перебирает каталог целиком: проверяются отдельные панели 037 и два HUD-случая (`hud-qa-postfix.spec.ts`). Проверки доступности (axe) нет; видимость обеих тем не утверждается.

При этом в обязательном CI-гейте Playwright представлен одним файлом: `ui-smoke` вызывает `test:e2e:smoke` = `playwright test console-guard` (`quality.yml:769` ✓); полный `test:e2e` идёт только по расписанию (`simulator-visual-e2e`, `:954` ✓).

Наблюдаемый вред — не денежный. Это (а) часы ручного тестировщика на поиск того, что измеримо машиной, и (б) дефекты, которые уже лежат в коде и не могут быть замечены стендом. Один такой найден при подготовке спеки: **цифра платежа удаляется из DOM через 1900 мс (`useRealTxFx.ts:225`), а её CSS-анимация выцветания длится 2600 мс (`App.css:160`, токен `--ds-app-floating-label-float-dur: 2.6s`, `designSystem.tokens.css:341`) с opacity 1 до 60 % пути — метка исчезает рывком примерно на 73 % траектории при непрозрачности около 0.65**; у подписи клиринга то же: TTL 3800 мс против анимации 4200 мс (`useRealClearingFx.ts:134`, токен `:347`). Это F-038-2 ниже.

## Что уже есть и переиспользуется

- **Детерминированный вход для анимации без бэкенда:** `normalizeSimulatorEvent` + `realEventPipeline` — тот же путь, что у SSE (решение П5 034); события можно подавать из теста через dev-хук `window.__geoSim` (`src/dev/geoSimDevHook.ts:81-117`, ставится при `isDev()`, то есть под Vite dev-сервером стенда). Записанные события в форме SSE — `simulator-ui/v2/public/simulator-fixtures/**` (029 S4) и `community-story-10` (036 C).
- **Инъекция времени уже есть в части слоёв:** `useOverlayState` принимает `deps.nowMs` (`:76`), `useRealTxFx` — `deps.nowMs` (`:100`), `useRenderLoop` читает `globalThis.window` на каждом вызове (`:24-42`), поэтому `page.clock.install()` Playwright (подменяет `Date`, таймеры, `requestAnimationFrame`, `performance.now`) управляет циклом рендера **без правок продукта**. Это и есть основа детерминированных тестов движения.
- **Рендер-цикл уже умеет засыпать и просыпаться:** `IDLE_DELAY_MS=3000`, `IDLE_FPS=4`, глубокий сон без планирования (`useRenderLoop.ts:213-215,602-607` ✓), `wakeUp()` (`:656-679`), `isAnimating` из физики/демо-холда (`simulatorIsAnimating.ts:10-14`). Стенд это **измеряет**, а не строит.
- **Бюджет FX уже адаптивный:** `updateFxBudgetScale` (EMA FPS, пороги 22/28/34/44, кламп 0.3–1, `:337-368`), pre-baked glow-спрайты и отключение `shadowBlur`/`backdrop-filter` в software-only (`render/glowSprites.ts`, политика §4). Одноразовый страж FPS < 12 → `low` (`useQualityAutoguards.ts:98-121`). Стенд даёт этим механизмам измеримые критерии.
- **Каталог поверхностей** `ui-kit/overlaySurfaceCatalog.ts` — единственный источник перечня окон и меню; стенд перебирает **его**, а не рукописный список (anti-vacuum: поверхность без рецепта открытия — красный тест).
- **Политики окон уже записаны кодом:** `escBehavior`, `closeOnOutsideClick` на тип окна (`windowManager/useWindowManager.ts:461-530`), фокус-ловушка только для `interact-panel` (`WindowShell.vue:83,124-135,212-243`), кламп `reclamp` с pad 12 и snap 8 (`useWindowManager.ts:681-776`), CSS-клампы дропдаунов и тостов (`designSystem.overlays.css:297,356-364`). Стенд проверяет, что **объявленная** политика исполняется для каждого экземпляра.
- **Инфраструктура запуска:** Playwright 1.50 с Chromium, `PW_E2E_PORT`, выходной каталог `.local-run/playwright/simulator/` (`playwright.config.ts:15-16`); тест-режим снимков остаётся нетронутым (его baseline — `e2e/scenes.spec.ts-snapshots/*-win32.png`).
- **Приёмочный путь владельца** (2026-10-10): платёж от любого участника на живом бэкенде → анимация → изменившиеся долги. Для живого бэкенда есть `scripts/verify_admin_e2e.ps1` (одноразовая БД, сид, uvicorn) — образец для симуляторного аналога, но живой прогон остаётся **milestone**, а не циклом стенда (AGENTS.md §1).

## Чего нет вообще

- Playwright-проекта, где продукт работает **как у пользователя** (FX, физика, перетаскивание, сон цикла включены), а недетерминизм снят **часами**, а не отключением поведения. Сегодня один флаг `isTestMode` выключает 17 поведений разом (инвентаризация агента, раздел 3) — стенд снимков и стенд поведения склеены в один режим.
- Чтения состояния канвы из теста: координаты узлов/рёбер в экранных пикселях, список активных искр и меток с их фазой, счётчик кадров. Дев-хук отдаёт `fxState` и камеру, но не геометрию layout.
- Измерений производительности в тестах: p95 времени кадра, число кадров в покое, рост heap, число `requestAnimationFrame` за окно, поведение при CPU-троттлинге и без GPU.
- Проверки доступности и единообразия окон: axe, размер целей, контраст, видимость в обеих темах, возврат фокуса после закрытия, поведение при ресайзе окна браузера.
- Галереи для человека: кадров каждой поверхности в каждой теме и видео трёх движений (искра, выцветание, перетаскивание), собираемых прогоном.
- Документа «что стенд не видит» (AGENTS.md §12: инструмент, проверяющий правило, документирует свои слепые зоны).

## Целевое поведение — конечный результат программы

Программа завершена, когда на HEAD `main` выполняются **все** пункты, и каждый подтверждён командой, exit code и артефактом:

1. **Одна команда стенда:** `npm --prefix simulator-ui/v2 run test:e2e:qa` запускает Playwright-проект `qa-stand` (`e2e/playwright.qa.config.ts`) на Chromium **без GPU** (`--disable-gpu --disable-accelerated-2d-canvas --disable-gpu-compositing`, software-рендер) и проходит зелёным; число собранных тестов печатается и сверяется с ожидаемым (нулевой отбор — отказ).
2. **Движение искры доказано пикселями:** для платежа по маршруту из 3 рёбер (событие `tx.updated` с `edges[]`, поданное через хук) при шаге часов `page.clock.runFor(16)` стенд читает fx-канву и утверждает: светлый пиксель встречается в полосе ±4 px вдоль геометрии **каждого** ребра маршрута, в порядке рёбер, и не встречается на прямой src→dst вне маршрута; искра исчезает к концу `durationMs`. Красен на `44056c6a` (спавн выключен; при включении — спрямление D4).
3. **Выцветание цифры непрерывно:** opacity метки (computed style под `page.clock`) монотонно не возрастает после 60 % и достигает 0 **до** удаления элемента из DOM; элемент не удаляется при opacity > 0.05. Красен на `44056c6a` (F-038-2). Для клиринга — то же правило.
4. **Перетаскивание верно при любой камере:** при `zoom ∈ {0.6, 1, 1.8}` и ненулевом `pan` drag мыши на (dx, dy) переносит узел на (dx/zoom, dy/zoom) в мировых координатах с точностью 0.5 px, узел закреплён (`fx/fy` заданы), после `relayout` позиция сохранена (`reapplyPinnedToLayout`), клик после перетаскивания не открывает карточку; картинка узла на канве совпадает с позицией DOM-превью в пределах 1 px. Красен на `44056c6a` (drag выключен в тест-режиме).
5. **Производительность без GPU измерима и в бюджете** (константы в `e2e/qa/budgets.ts`, храповик §6 AGENTS.md, двусторонний):
   - **покой:** через 3 с после последней активности число вызовов `requestAnimationFrame` за следующие 2 с равно 0 (глубокий сон); событие `tx.updated` пробуждает цикл за ≤ 1 кадр; красен на `44056c6a` (в тест-режиме цикл не спит);
   - **кадр:** на снимке 100 узлов (`realistic-v2` или фикстура сравнимого размера), при CPU-троттлинге ×4 через CDP `Emulation.setCPUThrottlingRate` и 20 одновременных искрах p95 длительности кадра ≤ константа (стартовое значение измеряется `T3801` и записывается с датой; порог блокирующий только в детерминированной части — число операций отрисовки за кадр, а wall-clock кадра — храповик в scheduled job по медиане трёх прогонов);
   - **память:** рост `performance.memory.usedJSHeapSize` за 60 с анимации при периодическом GC не превышает константу; число живых меток ≤ `MAX_FLOATING_LABELS`;
   - **деградация:** при искусственно низком FPS (троттлинг ×8) `fxBudgetScale` опускается ниже 1 и число частиц ограничивается — утверждается положительно, не «нет ошибки».
6. **Все окна и меню перебраны по каталогу:** для каждого типа из `overlaySurfaceCatalog.ts` стенд имеет рецепт открытия (отсутствие — красный тест), и для каждого открытого экземпляра при viewport 1366×768 и 1920×1080, в светлой и тёмной теме: rect внутри viewport с учётом pad; Escape ведёт себя по объявленной политике (`close` / `back-then-close`); клик вне — по `closeOnOutsideClick`; фокус после закрытия возвращается на открывший контрол; Tab не покидает `interact-panel`; axe (`@axe-core/playwright`, правила WCAG 2.1 A/AA) — ноль нарушений уровня `serious`/`critical` (исключения — поимённо, с причиной и датой); интерактивные цели ≥ 24×24 CSS px; ресайз окна браузера до 1024×640 переклампливает окна без ухода за край.
7. **Галерея для человека:** прогон оставляет `.local-run/playwright/simulator/qa-gallery/index.html` со скриншотом каждой поверхности в каждой теме и тремя видео (искра по маршруту, выцветание, перетаскивание) с живого прогона на фикстурах; CI загружает галерею артефактом job. Человек-тестировщик начинает с галереи, а не с пустого приложения.
