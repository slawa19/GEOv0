## 0. Blocker → v2 decision
- Guard looked at current, not committing, transaction → registry keyed by Core RootTransaction; refusal in Core commit / release_savepoint events which name the real target; 10 bypass/control scenarios prototyped (§1).
- Completion inside foreign descendant; stale handle → completion only when bound Core chain AND bound Session nesting are innermost and the record is still registered (§1.4).
- Poison lifecycle; Session.close drops poison → registry lives with the DB transaction, cleared only by real DB rollback; machinery failures poison root; orphaned ops refuse (§1.5).
- SQLite BEGIN/savepoint → separate prerequisite T1525, already corrupts money in existing code, reproduced through PaymentEngine.commit (§3).

## 1. Transaction contract
### 1.1 v1 bypasses reproduced
(a) direct commit of saved root with descendant open, observed events: begin, savepoint, S.before_commit (innermost_nested) twice, release_savepoint sa_savepoint_1, commit. Session-level guard cannot tell root commit from descendant release (SA/orm/session.py:1217-1231, :1253-1263); Core events can (release_savepoint(name) vs commit(conn)).
(b) rollback_only close: external conn.begin() + Session default conditional_savepoint join → rollback_only (session.py:1162-1179). close → S.after_transaction_end child, root; core only begin; conn.in_transaction True; external outer.commit() persisted [20]. Session ends root without DB rollback (:1361, :1377): session.info lost while DB tx lives.
(c) create_savepoint join: Session commit appears at Core as release_savepoint x2, no commit. engine.begin() exit: Core commit only.
### 1.2 Refusal inside a Core event
_commit_impl dispatches commit before do_commit (SA/engine/base.py:1123-1138). If the commit event raises, RootTransaction._do_commit deactivates and keeps it current (:2720-2746); later rollback() skips DB rollback because is_active False (:2698-2712). Probe with Connection-bound session (shape of clearing work_session clearing/service.py:1573): raise_only → dbapi in_transaction True after refusal and after session.rollback(); LEGACY no-BEGIN raise_only refused-then-next-commit persisted [1, 2] (refused row committed later); rollback_then_raise → dbapi in_transaction False, next commit ok, persisted [2]. Release: raise_only then root commit persisted the savepoint's row; rollback_to_then_raise excluded it.
Rule: refusal inside a Core transaction event first ends the refused scope at DB level, then raises: root commit → dialect.do_rollback; release → do_rollback_to_savepoint + root poison; if that rollback fails → conn.invalidate(). PG proof obligation: after refused commit, asyncpg adapter holds no open transaction (pg_stat_activity.state='idle') and fresh connection sees no rows (C10-P).
### 1.3 Mechanism
Class-level ConnectionEvents on Engine (apply to engines created before registration, sync and async — probed pysqlite and aiosqlite). _REGISTRY: WeakKeyDictionary[RootTransaction, _TxJournalState{ops, poison}]. Not session.info (dies with session, 1.1b); not Connection.info (pool record dict survives checkouts); not SessionTransaction (under join modes the Session root is a Core savepoint).
_OpRecord: id, kind, identity, generation, state, root (Core RootTransaction), chain (Core savepoint names root→bound from NestedTransaction._savepoint/_previous_nested SA/engine/base.py:2780-2790), session_ref weakref, session_boundary (Session get_nested_transaction() at open or None), scope, intent_equivalent_ids.
Core events: commit(conn) → if poisoned or any op not COMPLETED: rollback + raise DebtOperationIncomplete. release_savepoint(conn, name) → any op whose chain contains name not COMPLETED: rollback to savepoint, poison root, raise. rollback_savepoint(conn, name) → drop ops whose chain contains name; root poison KEPT. rollback(conn) → drop whole state. before_execute → write guard (§6.3).
Prototype (pysqlite with explicit BEGIN): 1 direct root commit with descendant REFUSED []; 2a complete inside descendant (SQL issued) REFUSED; 2b root commit after descendant rollback REFUSED []; 2c complete with Session descendant no SQL yet REFUSED; 3 rollback_only close then outer.commit REFUSED []; 4 legit savepoint op completed, released, root commit ALLOWED [1, 9]; 5 stale handle after rollback/reopen REFUSED; 6 create_savepoint session.commit with OPEN op REFUSED (release); 7 engine.begin() exit with OPEN op REFUSED []; 8 descendant release under OPEN ancestor (_apply_flow shape) ALLOWED [1, 2, 3].
Private attributes used, pinned to 2.0.25: NestedTransaction._savepoint, NestedTransaction._previous_nested, Session._flushing, Connection._execution_options. Guard test fails on SA version change (R2-1).
### 1.4 Lifecycle OPENING → OPEN → COMPLETING → COMPLETED, plus POISONED, DISCARDED
Open: conn = (await session.connection()).sync_connection (materialises pending Session savepoint, session.py:888-890, :1157-1158); refuse if AUTOCOMMIT isolation, SQLite without T1525 control, root poisoned, any non-COMPLETED op in this root (no nesting/concurrent ops), orphaned op, Debt pending in new/dirty/deleted; register OPENING before any I/O; flush pending parents; envelope INSERT under internal grant; OPEN.
Complete (block exit) only if: record still registered (same object, same generation); conn.get_transaction() is record.root; current Core chain == record.chain; session.get_nested_transaction() is record.session_boundary; state OPEN. Else DebtOperationIncomplete + root poison. Then COMPLETING → flush → read this op's entries from DB, sort (flush_ordinal, eq.bytes, debtor.bytes, creditor.bytes) → write debt_operation_equivalents → UPDATE envelope WHERE state='OPEN' rowcount 1 → COMPLETED.
### 1.5 Poison / failure classes
Hook refusal (no op, key mutation, missing history, unstorable, scope, write guard) → root poison until DB rollback; survives descendant rollback. Exception/cancellation during OPENING/COMPLETING I/O, in __aenter__/__aexit__ → root poison (__aenter__ handles its own failure). Exception/cancellation in block body (business failure) → op POISONED, no I/O; dropped if its own bound savepoint rolls back; else any commit/release covering it refused (a staged payment rejected in its per-action savepoint real_payments_executor.py:384 must not kill sibling payments). StaleDataError inside _apply_flow savepoint (engine.py:1429, :1492-1505) → no journal effect (after_flush never ran), ordinal gap. Orphan (session closed while DB tx lives) → any op open, Debt flush, commit or release on that root refused.

## 4. Money precision rule
SQLite Numeric binds as float, reads via to_decimal_processor_factory(Decimal, 8) (SA/sql/sqltypes.py:568-586). Analytically every scale-8 |v| < 2^26 round-trips exactly; empirically 300k random below 2^26: 0 lost; last 200k atoms below 2^26 exhaustive: 0 lost; first 200k atoms from 2^26: 65,782 lost; [1e8,1e9): 83,170/100k lost.
Rules: 1 PG is money-acceptance tier; expectations int atoms from literals; exact compare; no tolerance. 2 SQLite tests only |v| < 2^26 via helper asserting real DB round-trip; SQL aggregates on SQLite not money evidence. 3 hook storability: finite, v == v.quantize(1E-8), |v| < 10^12, and result_processor(bind_processor(v)) == v for the session's actual dialect (PG identity; SQLite refuses values it would change). Every ORM write checked → in-memory history equals stored value for journaled changes. Limit: a raw writer not bumping version under READ COMMITTED can make amount_before stale; prod PG SERIALIZABLE; residual shows as per-edge continuity break in step 6.
