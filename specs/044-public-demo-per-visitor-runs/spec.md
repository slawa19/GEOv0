## Problem

Публичное демо с одним активным прогоном на сервер непригодно: второй посетитель видит ошибку вместо сети. Поднять лимит без остального нельзя: (а) прогон, брошенный посетителем, живёт дальше — тикает, пишет платежи в базу и держит записи; на публичном сервере это накопление без границы (BACKLOG 043-2); (б) каждый прогон — живой процесс с тиком раз в секунду (`SIMULATOR_TICK_MS_BASE=1000`), до 20 действий за тик, клиринг каждые 25 тиков, запись артефактов каждые 5 с — нагрузка на одну базу растёт линейно с числом прогонов; (в) граница по ресурсам сейчас — только число активных прогонов и число SSE-соединений (50 всего, 10 на прогон).

**Наблюдаемая потеря (§19.2 п. 1):** публичное демо не показывается второму человеку (потеря смысла главного демо), и ресурсы сервера расходуются на прогоны без зрителя. Денежной потери нет; изоляция прогонов по периметру участников — предмет стадии 0 (не предполагать, а показать).

## Решения владельца (терминальные, 2026-10-17)

1. **У каждого посетителя свой прогон.** Один активный прогон на владельца (`SIMULATOR_MAX_ACTIVE_RUNS_PER_OWNER=1` — уже есть), общий лимит поднимается до измеренного значения `N` (стадия 0 называет число по замеру нагрузки, не наугад). Чужой прогон остаётся закрытым.
2. **Брошенный прогон останавливается сам.** Прогон без ни одного SSE-подписчика дольше `T` минут переводится в `stopped` с причиной `idle_no_subscribers`; данные и артефакты не удаляются (исключение 2026-10-10 по диску остаётся). Это новая сущность — шесть вопросов §19.2 ниже.
3. **Исчерпание общего лимита — человеческий текст и повтор** («Сейчас демо смотрят N человек, попробуйте через минуту»), без сырого 409.
4. **Сначала ревизия, потом реализация.** Код жизненного цикла прогонов (owner surface) проверяется на мусор, устаревшие ветви и дубли **до** правки; найденное удаляется отдельными коммитами с доказательством (grep, вызовы, история), по §14.

## §19.2 — шесть вопросов к новой сущности «остановка по простою»

1. **Потеря:** прогоны без зрителя тикают и пишут в базу неограниченно долго; на публичном сервере это гарантированное исчерпание лимита `N` брошенными прогонами (второй посетитель снова видит ошибку) и рост нагрузки. Воспроизводится: открыть демо, закрыть вкладку, через `T` минут `GET /simulator/runs` (admin) показывает `running` без подписчиков — репродьюсер стадии 2.
2. **Протокол:** не требует; это требование публичного демо, не протокола GEO.
3. **Противник:** нет; это гигиена ресурсов, не безопасность.
4. **Дешевле:** (а) ручная остановка оператором — не покрывает публичный вход без оператора; (б) остановка при закрытии вкладки (`beforeunload`) — ненадёжно (сеть, краш, мобильный браузер) и не покрывает уже брошенные; (в) не поднимать лимит — противоречит решению владельца. Остановка по отсутствию подписчиков — минимальный автоматический вариант: счётчик подписчиков уже ведётся в `sse_broadcast.py`, нужен только порог времени и один проход в существующем тике/планировщике, без нового фонового процесса.
5. **Цена, числом:** 0 новых таблиц и endpoint'ов; 1 ключ конфигурации; одна проверка в существующем цикле (тик или `run_persist`); причина остановки — новое значение существующего поля; ≈ 60–120 строк продукта; тесты — 3–5 на Postgres-тире (без `sleep`: управляемые часы). Записать фактическое число в Changelog стадии 2.
6. **Крайние случаи:** переподключение SSE в пределах `T` (не останавливать — считать по последнему отключению, не по первому); пауза без подписчика (останавливать — пауза не держит прогон живым для зрителя, которого нет); прогон оператора через Admin ▾ (тот же закон; оператор держит подписку или перезапускает); прогон стенда/тестов (`T` настраивается, тесты ставят большой `T` или управляют часами); несколько вкладок одной cookie (одна подписка достаточно). Гипотетические пути без входа в приложении — не покрывать.

## Non-goals

- Не открывать чужие прогоны для чтения и не делать «один общий прогон» (решение владельца — путь 1).
- Не удалять артефакты на диске и записи прогонов автоматически (исключения 2026-10-10 остаются; `scripts/cleanup_simulator_runs.py` — ручной путь).
- Не трогать тик, денежный путь, `allowed_participant_pids`, SSE-формы, OpenAPI кроме текста 409 и нового значения причины остановки.
- Не вводить очередь ожидания, приоритеты, аутентификацию посетителей.
