# 008 — Сплошное код-ревью трёх поверхностей

- **Date:** 2026-08-11
- **Status:** AUTHORIZED — фаза I (разведка), волна 1 в работе
- **Status authority:** метка описательная; завершённость устанавливают success criteria и записанные evidence, а не поле статуса.
- **Owner surface:** фаза I — весь продуктовый код `app/`, `admin-ui/src/`, `simulator-ui/v2/src/` и `tests/` **read-only**. Фаза II (правки) — только `clean`/`delete`-класс вне денежного ядра; см. «Owner surface» ниже.
- **Origin:** запрос владельца 2026-08-11 и четыре его решения того же дня (глубина, режим денежного ядра, темп, судьба тестов) — раздел «Решения владельца».
- **Почему одна программа:** предмет один — качество кода как таковое, а не поведение отдельной подсистемы. Разрезать по поверхностям нельзя: половина находок (дубли mock/real, разошедшиеся форматтеры, контракт, увиденный тремя реализациями по-разному) видна только при сопоставлении реестров разных треков.

## Problem

Программа 001 закрыта, 002–006 специфицированы. Все они искали **дефекты поведения**: деньги,
конкурентность, периметр, честность гейтов. **Ни одна не читала код сплошняком.** Качество самого
кода — мёртвое, дублируемое, непереиспользуемое, размазанное по God-файлам — известно только
точечно, и то как побочный улов чужих аудитов.

Измеренный масштаб непокрытого (2026-08-11, HEAD `ea9cde9`, продуктовый код без тестов):

| Поверхность | Файлы | LOC |
|---|---|---|
| `app/` | 123 | 30 914 |
| `simulator-ui/v2/src` | 266 | 29 742 |
| `admin-ui/src` | 111 | 21 671 |
| **Итого** | **500** | **≈ 82 300** |

Плюс 31 224 строки тестов двух UI и 165 тестовых файлов бэкенда.

**Наблюдаемый вред, а не «хотелось бы чище».** Находки этого класса уже подтверждены — но найдены
попутно, поиском их никто не занимался, поэтому неизвестно, сколько их ещё:

- два параллельных источника правды одного контракта расходятся семантически:
  порог bottleneck считается во float в SQL и точным decimal в моке — KPI на границе различается
  между режимами (`specs/BACKLOG.md`, «Bottleneck-порог»);
- ~240 строк политики вместимости продублированы в `engine.prepare` и `engine.prepare_routes`
  (`app/core/payments/engine.py:359-580` против `:582-822`);
- мёртвые экспорты живут в обеих поверхностях (`router.find_paths`, `restartRun`,
  `bestEffortTotal`);
- одноимённые функции с разными телами в трёх лаунчерах.

Стоимость измеряется в синхронных касаниях: правка одного правила требует найти и изменить N мест,
и цена ошибки — молчаливое расхождение режимов, а не падение.

## Owner surface

**Фаза I — разведка, read-only.** Читается всё: `app/**`, `admin-ui/src/**`,
`simulator-ui/v2/src/**`, `tests/**`. Ни одной правки.

**Фаза II — правки, разрешено только после триажа владельца:**

- разрешено: `clean` и `delete` вне денежного ядра — мёртвый код, дубли внутри файла, удаления
  после reference scan;
- **запрещено полностью:** `app/core/payments/`, `app/core/clearing/`, `app/core/recovery.py` —
  owner surface неавторизованных программ 002/003/004. Находки там дописываются в те спеки, а не
  правятся здесь (решение владельца 2026-08-11);
- вне периметра: `simulator-ui/v1/`, любые `archive/`, `_audit/`, `_audit_xfer/`, применённые
  migrations, generated fixture copies, `plans/`;
- `merge` и `rewrite` требуют отдельного решения владельца по каждому случаю — они не входят в
  «дешёвые правки».

## Current / Intended / Optimal

**Current.** Сплошного покрытия нет. Качество кода известно точечно, из побочного улова аудитов
поведения. Ни для одного файла из 500 нет записи «прочитан, вердикт такой-то», поэтому
непрочитанный файл неотличим от чистого.

**Intended.** AGENTS.md §2 требует high-leverage изменений и прямо запрещает overengineering:
новая абстракция допустима только против подтверждённого дублирования, не «на будущее». §14
запрещает удалять файл по одному пустому grep. §11 задаёт качество тестов. То есть контракт на
чистку уже написан — не выполнена именно инвентаризация.

**Optimal.** Каждый файл трёх поверхностей имеет явный вердикт `keep`/`clean`/`merge`/`rewrite`/
`delete` с датой и HEAD. Дешёвые правки применены пакетами по одному классу. Дорогие — оценены и
лежат в BACKLOG с ценой, а не с эмоцией. **Ни одной новой абстракции не введено.**

## Verification plan

**Разведка (фаза I) проверяется полнотой, а не прогоном.**

1. **Полнота покрытия — машинно проверяемый критерий.** Число строк в файлах инвентаря волны
   обязано совпадать со списком файлов её owner surface: `git ls-files <surface>` против таблицы.
   Расхождение — незакрытая волна, а не мелочь. Файл без строки вердикта считается непрочитанным.
2. **Каждая находка проходит adversarial-опровержение** (AGENTS.md §16.4) отдельным агентом с
   чистым контекстом: `CONFIRMED` / `REFUTED` (с контр-evidence) / `NEEDS-RUNTIME`. Оркестратор
   вручную воспроизводит каждый P1/P2 по коду до внесения в реестр.
3. **Внешнее независимое ревью** батчем по поверхности перед закрытием фазы I: оркестратор —
   Claude Code, значит ревьюер — Codex (`docs/external-review-runbook.md` §3). Подаётся реестр
   находок с вопросом «что ложное, что пропущено», а не «посмотри код».

**Правки (фаза II) проверяются репродьюсером.**

1. **Репродьюсер, падающий на `ea9cde9`,** обязателен для каждой находки класса **B** и **C** до
   её починки. Зелёный до правки тест ничего не доказывает.
2. **Класс D (удаление) доказывается иначе:** reference scan по AGENTS.md §14 (package scripts,
   dynamic imports, docs, generators, runtime entrypoints, `git log -- <path>`), затем контрпроверка
   — targeted gates зелёные **после** удаления. Пустой grep сам по себе доказательством не является.
3. **Класс R (дубли):** правка обязана убрать дублирование, а не спрятать его за абстракцией.
   Контрпроверка — число синхронных касаний при гипотетической правке правила стало меньше,
   и это показано перечислением call-sites до/после.
4. **Инварианты, обязанные выжить:** защищённые контракты §8 AGENTS.md — `api/openapi.yaml`, SSE
   имена и wire shapes, алиасы `from`/`to`, decimal-семантика денег, направление trustline
   `creditor -> debtor`, идемпотентность по `tx_id`.
5. **Существующие селекторы, обязанные остаться зелёными** (называются поимённо в каждом слайсе):
   `.\scripts\verify_local.ps1 -TaskSlug <slug> -BackendOnly`,
   `npm --prefix admin-ui run test`, `npm --prefix admin-ui run build`,
   `npm --prefix simulator-ui/v2 run typecheck`, `npm --prefix simulator-ui/v2 run test:unit`,
   `npm --prefix simulator-ui/v2 run build`.

**Явно запрещённые способы проверки** (дают ложное доказательство):

- считать утверждение агента «файл прочитан» покрытием без строки инвентаря;
- принимать находку по памяти агента без `path:line`, существующего на замороженном HEAD;
- удалять код по одному пустому `git grep`;
- засчитывать «0 находок» там, где волна не запускалась;
- чинить дубль введением новой абстракции и называть это упрощением.
