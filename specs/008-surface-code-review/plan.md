# 008 — План: метод, разбиение на волны, протокол возобновления

Контракт программы — [`spec.md`](spec.md). Здесь механика: как устроена одна волна, где границы
слайсов, куда пишутся артефакты и **как продолжить работу в новой сессии** после переполнения
контекста. Скорректирован 2026-08-12 по [`plan-audit-2026-08-12.md`](plan-audit-2026-08-12.md)
(F-PA-1…F-PA-11); правка авторизована владельцем.

## 0. Протокол возобновления (читать первым в новой сессии)

Новая сессия начинается не с чтения кода, а с восстановления состояния — по порядку:

1. `spec.md` — контракт, решения владельца, verification plan, находки P2 со статусами.
2. `tasks.md` — **фактические статусы слайсов**. Это источник ответа «что делать дальше».
3. [`manifest.md`](manifest.md) — разбиение «файл → ровно один слайс» на frozen HEAD.
4. [`evidence-index.md`](evidence-index.md) — tracked-индекс закрытых волн: счёт, вердикты,
   ID находок, непроверенное. Machine-local каталог `plans/review-2026-08-11-three-surfaces/`
   хранит полные реестры, но восстановимость программы от него не зависит (F-PA-7).
5. `git log --oneline -15` и `git status --short` — что реально доставлено.

Базы: **`ea9cde9`** — исторический baseline закрытой волны 1;
**`7cb5149eb03c902977ac0d740d73a933a54e372e`** — frozen HEAD волн 2–6. Если HEAD ушёл вперёд до
старта волны: перегенерировать манифест по правилам из него же (проверка: 0 UNASSIGNED, счёт строк
= счёт файлов scope), перепроверить незакрытые P2 — статусы `LIVE / FIXED_EXTERNALLY / CHANGED /
REFUTED / UNVERIFIED`, как это сделал аудит A1. Находка не переносится в работу только потому, что
была `CONFIRMED` на старом HEAD.

Правило приоритета: `tasks.md` важнее любой сводки в чате и любого прошлого утверждения агента.

## 1. Анатомия одной волны — проходы R0–R4

Именование R* — чтобы не путать проходы с severity P1/P2/P3 (F-PA-11).

### R0 — машинная развёртка

Даёт **сигналы, а не находки**: куда смотреть в первую очередь.

- Python: `.\.venv\Scripts\python.exe -m ruff check --select F401,F811,F841,ARG,C901 <файлы>`;
  файлы > 400 строк; модули без входящих ссылок.
- TS/Vue: экспорты без импортёров (обязательно проверив dynamic import, `<template>` и package
  scripts — §14 AGENTS.md); неиспользуемые i18n-ключи и SFC.
- Дубли и размер — **эвристики ранжирования, не условия истинности** (F-PA-10): «блок ≥ 20 строк»
  и «≥ 3 места» сортируют очередь внимания. Дубль в двух копиях тоже находка, если доказано
  расхождение контракта или сокращение синхронных касаний (пример: две реализации порога
  bottleneck).

### R1 — чтение файл за файлом

Читается **каждый** файл слайса по манифесту, большие — кусками по 400–500 строк. На каждый файл —
строка инвентаря:

| Файл | LOC | Вердикт | ID находок | Комментарий |
|---|---|---|---|---|

Вердикты: **keep** · **clean** (локальная чистка) · **merge** (дублирует соседа) · **rewrite**
(обязательны две оценки: починить vs заново, и чем ловится регрессия) · **delete** (обязателен
reference scan и `git log -- <path>`).

«keep, прочитано, чисто» — обязательная запись. Вердикты не назначаются заранее: слайс получает
**нейтральные вопросы** («каков источник истины?», «есть ли runtime-импорты?», «кто owner?»), а
вердикт появляется только после evidence (F-PA-9 — урок `src/demo/patches.ts`, который выглядел
мёртвым, но используется в real mode).

**Материальные тесты читаются вместе с source-слайсом** (F-PA-4): success/rejection/failure/retry/
recovery/cancellation-тесты его call-paths, contract/serialization-тесты для API/SSE,
component-тесты реального DOM/state-эффекта, Playwright spec при утверждении пользовательского
эффекта или safe delete, policy guard, читающий изменяемый файл. В инвентаре фиксируется, **какой
эффект тесты доказывают, а какой нет** — без этого нельзя утверждать «регрессия поймается».
Suite-wide аудит тестов остаётся волной 5.

### R2 — сверка с контрактами и идеей проекта

- backend: `api/openapi.yaml` (авторитет №1) — путь, метод, коды, поля, пагинация; §8 AGENTS.md —
  SSE-имена и wire shapes, алиасы `from`/`to`, decimal вместо float, направление trustline
  `creditor -> debtor`, идемпотентность по `tx_id`, `model_dump(mode="json", by_alias=True)`;
- фронтенды: нормализация событий против фактических wire shapes; типы против схем бэкенда;
  **mock против real — расхождение это дефект, пока обратное не задокументировано**;
- обе UI: продуктовая идея — `docs/ru/01-concepts.md`, `02-protocol-spec.md`,
  `docs/ru/admin-ui/`, `docs/ru/simulator/`.

### R3 — самопроверка и перепроверка оркестратора

Без дублирования (F-PA-8), три несмешиваемых уровня:

1. **Self-refutation агента слайса**: перед записью каждой находки — попытка её убить (вызывающий,
   которого не заметил; тест; dynamic import; сознательное решение в docs). Отклонённое — в раздел
   «отклонено при самопроверке» с причиной.
2. **Оркестратор** вручную перепроверяет по коду каждый P1/P2 и существенную выборку P3.
3. **Единый fresh-context adversarial-проход — только T808**, по сведённым реестрам всех волн:
   пропущенное, братья багов, общее состояние. Отдельный clean-context агент на каждую волну не
   заводится.

Статусы находок: `CONFIRMED` / `REFUTED` (с контр-evidence) / `NEEDS-RUNTIME`. Каждый
`NEEDS-RUNTIME` порождает задачу в `tasks.md` с точным селектором и prerequisite (F-PA-11).

### R4 — внешнее ревью и триаж

T809: другая система и модель, механика — `docs/external-review-runbook.md`. Подаётся реестр
находок с вопросом «что ложное, что пропущено». Затем триаж владельца:
`fix now` / `в спеку` / `удалить` / `принято как есть`.

## 3. Контракт промпта агента слайса

- owner surface **по манифесту** и явный запрет на файлы параллельного слайса;
- frozen HEAD; запрет правок, прогонов и коммитов (read-only фаза I);
- ссылки на `AGENTS.md` §1, §2, §8, §9, §16 и этот план;
- строка инвентаря на **каждый** файл слайса из манифеста;
- материальные тесты слайса: прочитать, записать «что доказано / что нет» (R1);
- формат находки: ID, `path:line`, класс, severity, утверждение, наблюдаемое следствие,
  как проверить, статус самопроверки;
- дедупликация против `specs/BACKLOG.md` и закрытых спек (`known: <источник>`);
- правила §4 дословно; обязательный раздел «что я НЕ проверял»;
- уникальный `-TaskSlug` при любом прогоне (AGENTS.md §7).

## 4. Правила против overengineering (дословно в каждый промпт)

1. **Дефолтный вердикт — «оставить как есть».**
2. **У находки обязана быть цена:** достижимый дефект, расхождение контракта или измеренная боль
   сопровождения (число синхронных касаний, два источника состояния).
3. **Приоритет действий: удалить > упростить > объединить > переписать.** Числовые пороги
   («≥ 20 строк», «≥ 3 места») — эвристики ранжирования, не условия допустимости: минимальный
   локальный extraction возможен и для двух копий при доказанном расхождении контракта.
4. **Никаких новых слоёв:** ни service layer, ни outbox, ни generic-обёрток, ни DI, ни «единого
   API-клиента ради симметрии».
5. **Стиль — не находка** (долг Ruff/Black закрыт шкалой 006; не переизмерять здесь).
6. **Не переоткрывать принятое** (раздел «принято» в BACKLOG терминален).
7. **Не находить заново известное** — дедупликация на входе волны.
8. **Сплошной codemod запрещён** (разбор M20 в BACKLOG).
9. **Вердикты не предрешаются** — только нейтральные вопросы до evidence (F-PA-9).

## 6. Гейты

Фаза I read-only: гейты не запускаются, кроме явных задач T803-RT* (репродьюсеры NEEDS-RUNTIME).

Фаза II — матрица «tier ↔ тип правки» (из аудита A4):

| Правка | Обязательный gate |
|---|---|
| Любой backend-пакет | `.\scripts\verify_local.ps1 -TaskSlug <slug> -BackendOnly -BackendSelector <targeted>` |
| API/schema/serialization | + `tests/contract/test_openapi_contract.py` |
| Admin UI | `npm --prefix admin-ui run test` + `build` |
| Simulator UI | `npm --prefix simulator-ui/v2 run typecheck` + `test:unit` + `build` |
| Слайс перед merge | полный `.\scripts\verify_local.ps1 -TaskSlug <slug>` (milestone) |
| Конкурентность/деньги | Postgres-гейт с `-BackendMarker postgres` и одноразовой DB |
| Пользовательский E2E-эффект | соответствующий Playwright smoke — как milestone, не как цикл отладки |

Дефолтный tier (`not slow and not e2e and not postgres`) не доказывает slow/Postgres/browser —
не заявлять их закрытыми без соответствующего гейта (маркерная ловушка §5 AGENTS.md).

Правки — по одному классу на revertable коммит; rollback — `git revert` пакета, полный SHA
фиксируется в evidence-index (обязательный baseline-тег не требуется — A6).
