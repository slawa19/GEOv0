### S1 — дефекты продукта, видимые пользователю

**F-028-1. Сид рана не помещается в колонку (№ 187, 101 частично).**
- *Current:* `seed = int.from_bytes(sha256(run_id)[:4], "big")` (`run_lifecycle.py:190-191`) — до 2³²−1; колонка `Integer` (`simulator_storage.py:30`, миграция 013). При сиде ≥ 2³¹ `upsert_run` падает, ошибка проглатывается (`storage.py:89-93`), строки `simulator_runs` нет. *Intended:* каждый ран сохраняется. *Optimal:* маска `& 0x7FFFFFFF` при генерации.
- §19.2: (1) примерно половина ранов без строки — нет истории ранов, а проверка изоляции периодического клиринга (`runner.py:465`) не видит такой real-ран; (2) хранилище ранов, решение 9 программы 023; (4) рассмотрена миграция на `BigInteger` — дороже (новая ревизия Alembic, §15 по миграциям) и ничего не добавляет: сид нигде не питает генератор, его читают только `storage.py:63` и `artifacts.py:76`; (5) 1 строка + тест ~30; (6) старые раны с большим сидом строк не имели — менять нечего; детерминизм от `run_id` сохраняется.
- *Репродьюсер:* `run_id` с первым байтом sha256 ≥ `0x80` → строка `simulator_runs` есть на PostgreSQL. Сегодня — строки нет.
- §8/§15: нет.

**F-028-2. `max_hop_usage` из `NaN` даёт 500, бесконечность хранится (№ 83).**
- *Current:* `Decimal('NaN') < 0` бросает `InvalidOperation` (`validation.py:614`) → 500 `E010`; `"Infinity"` проходит. *Intended:* нечисло — 400, как `daily_limit` (он `NaN`/`Infinity` отвергает). *Optimal:* `is_finite()` до сравнения, тот же 400.
- §19.2: (1) подписанный ввод даёт 500 вместо отказа; (2) канон: `max_hop_usage` — число; (4) альтернатив дешевле нет; (5) ~3 строки + тест; (6) `"0"`, `"0.5"`, `1` по-прежнему принимаются.
- *Репродьюсер:* `POST /trustlines` с `max_hop_usage: "NaN"` → 400. Сегодня 500. И `"Infinity"` → 400, сегодня 201.
- §15: да — вход политики, по которой решается посредничество (одно ревью с F-028-3).

**F-028-3. Политика из сценария мимо валидатора (№ 48, 140 = `F-011-8`).**
- *Current:* засев копирует `policy` как есть (`real_scenario_seeder.py:257-259`); `pair_rules` читает `bool(...)` (`capacity.py:53`): `can_be_intermediate: "false"` — **разрешение**, `null` — запрет, хотя API хранит `null` как «не задано». *Intended:* одна грамматика политики на всех входах. *Optimal:* засев прогоняет политику через `validate_trustline_policy`; невалидная — отказ засева с именем линии (не молчаливый пропуск: политика решает, кто посредник); в `pair_rules` ключ со значением `null` значит «не задано».
- §19.2: (1) сценарий может провести платёж через владельца линии, который посредничество запретил, — тот же класс, что `"0.0"`, признанный классом 1 решением владельца 2026-09-29; `null` с API даёт лишний отказ платежа; (2) протокол §6.3.1 «запрет — заявление владельца линии»; (4) рассмотрено: научить `pair_rules` разбирать строки — отвергнуто, дефект родился на входе, чинить стадию-владельца (§9); (5) ~25 строк + 2 теста; (6) все 2817 политик сценарных фикстур — `bool`, валидатор их пропускает; `blocked_participants` с не-pid строками валидатор не проверяет — вне программы (Non-goals).

## Вопросы владельцу

Простыми словами; рекомендация — моя, решение — ваше.

- **В-1. Что значит «заморожен»?** (№ 26, 191, 192, 201) Сейчас замороженный участник может быть посредником в чужом платеже: деньги идут через него, у него растёт долг. Админская заморозка трогает только участника, заморозка в симуляторе — ещё и его линии; изменить лимит замороженной линии можно. **Рекомендую:** замороженный участник не платит, не получает и не бывает посредником; отдельный статус линии `frozen` убрать из протокола. Если «да» — это денежный дефект, его починка заводится задачей с §15-ревью.
- **В-2. Суммы в разных валютах в одной цифре.** (№ 17, 40, 169) Профиль участника (`/participants/me`) складывает долги в гривнах и часах и округляет до двух знаков; сводка ликвидности без выбранной валюты тоже складывает. Экраны это уже прячут, видит только внешний клиент API. **Рекомендую:** в профиле — итоги по каждой валюте отдельно, общую сумму убрать; сводку без валюты оставить только со счётчиками (как делает экран); `total_available` не трогать — он описан честно.
