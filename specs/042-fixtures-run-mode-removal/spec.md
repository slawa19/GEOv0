## Problem

Симулятор — главное демо работы системы (слово владельца 2026-10-16). Режим (Б) достижим человеком: Auto-Run → ⚙ Advanced → Pipeline → «sandbox (topology-only)» → Start; выбор запоминается в браузере. Вспышки в нём неотличимы от настоящих платежей, а денег за ними нет. Для демо это ловушка: зритель принимает случайные события за работу протокола. Внешний клиент API, вызывающий preview без `mode`, молча получает `fixtures` (`Query("fixtures")`).

Это также второй источник событий защищённого SSE-контракта (§8 AGENTS): `tx.updated`/`clearing.*` рождаются не в ядре. Правило «любое событие о платеже родилось в ядре» после удаления становится единственным.

**Проверка §19.2:** программа ничего не строит — удаляет сущность; дешёвый вариант (убрать только пункт меню) владелец отклонил осознанно ради чистоты договора; цена названа в стадиях.

## Non-goals

- Не трогать (А): демо без сервера, статические снимки, кнопку «Sandbox», e2e на снимках.
- Не менять поведение режима `real`, тик, денежное ядро, SSE-формы событий.
- Не вводить замену: «быстрый прогон без базы» для тестов не строится заново; тесты либо переводятся на существующий путь `real` (на PostgreSQL, как весь тир), либо удаляются с доказательством, что проверяемое поведение исчезло вместе с режимом.
- Не переписывать миграцию `013`.

## Как работать над эффектами без серверного режима (вопрос владельца 2026-10-16)

Проверено по коду 2026-10-16. Способов увидеть анимацию платежей и клиринга три, живых — два:

1. **Настоящий прогон на локальном сервере** (`scripts/run_full_stack.ps1`, сид сообщества, Auto-Run → Start; темп — ползунок Intensity). Полная достоверность: каждая вспышка — реальный платёж из базы. Это и есть то, что будет показываться как демо. Остаётся и после 042.
2. **Демо без сервера на записанных событиях** — (А): снимки и плейлисты событий лежат в `simulator-ui/v2/public/simulator-fixtures/v1/<EQ>/events/`, валидатор есть (`src/fixtures.ts:332` `validateEvents`), но **потребителя у плейлистов в коде нет** (`grep -rn Playlist simulator-ui/v2/src` → только необязательный геттер в `simulatorIsAnimating.ts:8`; ревью 2026-10-08 назвало плейлисты мёртвыми с `179f85c4`). Это задуманный верстак для эффектов: детерминированные записанные события идут тем же путём, что и настоящие, без базы и без случайности. Сейчас не работает.
3. Кнопки «Single Tx» / «Run Clearing» в Dev Tools — только в режиме e2e-скриншотов и рисуют не эффект, а подсветку ребра/узлов (`useSimulatorApp.ts:753-776`). Для работы над эффектами непригодны.

Серверный режим (Б) был четвёртым способом: случайные вспышки по картинке сети без базы. Удаляя его, программа обязана вернуть владельцу способ 2, иначе работа над эффектами возможна только с поднятым сервером и базой.

**Решение (записано как допущение советника, владелец может изменить порядок):** стадия 1 (сервер) не ждёт способа 2 — пока он не готов, эффекты правятся на настоящем прогоне (способ 1). Оживление плейлистов — задача `T4205` этой программы, на стороне клиента, через тот же FX-путь, что и SSE-события; идёт после слияния 039 B2 (файлы корня — 039), до закрытия 042. Новая сущность не вводится: формат плейлистов и валидатор уже существуют, добавляется только проигрыватель к существующему пути событий; §19.2 — потеря, которую он закрывает, названа выше (невозможность работать над эффектами офлайн).
