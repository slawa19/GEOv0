## Problem

Simulator UI показывает, что **что-то движется и светится**, но не показывает **кто, кому, сколько и почему** — а именно это должен увидеть человек, оценивающий систему. По кадрам стенда 038 (`saas-scene-no-gpu-without-shadow.png`, `hud-clearing-gpu-with-shadow.png`, `hud-node-labels-scene-gpu-with-shadow.png`):

1. **Направление доверия не показано вообще.** В `src/render/` ноль маркеров направления (✓ `grep -i "arrow|chevron|marker"` пуст); все рёбра — одинаковые серые отрезки. Направление есть только текстом «b → c» в попапе линии.
2. **Легенды нет.** Снимок несёт `palette`, парсер его разбирает (`api/simulatorContracts.ts:616` ✓), но ни один `.vue` не читает (✓). Цвет узла смешивает в одном канале тип участника, корзину долга `debt-0…8` и статус (`vizMapping.ts:24-41` ✓); заморозка — ещё один оттенок оранжевого (`:28`). Подписи узлов красятся цветом узла (`LabelsOverlayLayers.vue`), отсюда нечитаемые цветные имена.
3. **Клиринг противоречит сам себе.** На кадре треугольник цикла с меткой «−48.00 UAH», а HUD уже пишет «System is clean — no debts, Total Debt 0.00». Нет «было → стало».
4. **Посредники платежа не видны, луч гаснет между звеньями.** Общее время `ttlMs` делится на число рёбер (`useRealTxFx.ts:197` ✓): при шести рёбрах по 200 мс на ногу с `easeOutCubic` на каждой (`renderFrame.ts:128` ✓).
5. **Цифра суммы исчезает рывком**: JS-TTL 1900 мс при CSS-выцветании 2600 мс, удаление при непрозрачности 0.11 (стенд 038 `label-fade.qa.ts`, измерено 2026-10-11; F-038-2). Для клиринга 3800 против 4200 мс.
6. **Треть экрана под панелями.** Три ряда сверху (режим и тема; шесть плашек баланса; три кнопки действий), плашка «Inspect graph» шириной до 520 px (`GraphNavigator.vue:136` ✓) всегда над графом, ряд снизу. Стенд измерил 31.7–33.7 % экрана вне холста, с развёрнутым навигатором 43–45.6 %. Окна Interact открываются поверх навигатора, попап линии перекрывает нижний ряд, тост закрывает узел (кадры `p038s2-report`).
7. **Четыре темы при одинаковой канве.** На восьми полных кадрах `*-scene-*.png` канва побайтно одинакова, различаются шрифт и рамки; `hud` и `shadcn` дают axe `color-contrast` уровня serious (`e2e/qa/surfaceBaseline.ts`). Для демо это налог на стенд и на контраст, а не ценность.
8. **Производительность без GPU ограничена одним дефектом рендера:** базовая канва перерисовывается каждый кадр по одному `stroke` на ребро, около 350 команд на кадр (`render/baseGraph.ts:111-148` ✓; BACKLOG 038-3 (а): ~11 fps при CPU ×4). Стек рендера при этом верный (см. Non-goals).
9. **Сопровождение:** проверка «тот же эквивалент» написана inline около 30 раз с разночтениями (`realEventPipeline.ts:236` обрезает пробелы с одной стороны) при правиле владельца «эквиваленты не смешивать никогда»; копия снимка в layout по ручному списку полей теряет `reverse_used` (`useSimulatorApp.ts:960-1014`, `types.ts:50` ✓); `useSimulatorApp.ts` — 2057 строк (✓), 9 неиспользуемых локалов; `eslint.config.js` без плагинов TS/Vue — рекомендуемые правила `typescript-eslint` + `vue essential` дают 35 находок (измерено на копии); ~150 строк мёртвого CSS (`ds-ov-layer*` без единого читателя ✓) и тесты на точный текст этого CSS; неиспользуемые экспорты (`fixtures.ts loadEvents`, `math.finiteOr`, `CLEARING_REFUSAL_REASONS`), осиротевший `tools/check_single_tx.mjs`, пятый конфиг `playwright.hud-qa.config.ts` без скрипта и CI (✓), динамический `import('../render/fxRenderer')` при пяти статических (`useSimulatorApp.ts:1842` ✓), `state.flash` в реактивном состоянии каждый кадр.
10. **Стенд 038 закрыт частично:** `test:e2e:qa` не считается (считаются `:gate`/`:report`); порядок ног луча проверяется числом общих кадров, а не интервалами; обещанный R3 отказ при зазоре хорды < 10 pt не реализован; детерминированные бюджеты лежат в scheduled `qa-perf` с тремя `skip` без счёта; геометрия и политики окон только в `hud`; отчёт гейта грузится в CI только при падении; галерея и три видео — в разных прогонах.

## Решения владельца 2026-10-12 (терминальные, датированные)

- **Р1 — темы.** Одна читаемая тема по умолчанию (`saas` или `library` — выбирается измерением, см. срез B), `hud` остаётся по выбору, `shadcn` **замораживается**: убирается из переключателя и из матрицы стенда, токены не удаляются (отдельный cleanup-срез позже при желании).
- **Р2 — выцветание цифры.** Время жизни метки равно длительности её CSS-анимации; цифра гаснет до нуля и только потом удаляется. Для платежа и клиринга.
- **Р3 — цветовой язык.** Четыре семантических цвета данных, одинаковые во всех темах, вместо пятнадцати: **должен**, **ему должны**, **заморожен**, **хаб** (хаб — размером/кольцом, не цветом). Подписи — цветом текста темы.
- **Р4 — компоновка.** Делегирована: «оставь оптимально для простого пользователя, который будет оценивать систему; предложи варианты». Варианты и рекомендация — раздел «Компоновка»; реализация среза E после выбора владельцем (П1).

## Чего нет вообще

Маркера направления на рёбрах; компонента легенды; семантической карты цветов, независимой от темы; «было → стало» общего долга; имён участников в результате клиринга и журнале Interact (там буквы A/B/C и идентификаторы); батчинга рёбер по стилю; измеримого критерия доли экрана под холстом; lint-плагинов TS/Vue; единственной функции сравнения эквивалентов.

## Целевое поведение — конечный результат

1. **Картинка читается без пояснений.** На кадре сцены при 1366×768: у конца-должника каждого ребра виден маркер направления; легенда из четырёх цветов и формы «хаб» видна постоянно (компактно, в нижнем ряду); узел-должник тёплого цвета, кредитор — холодного, замороженный — серый со штрихом; подписи узлов цветом текста темы с гало. Проверка — пиксельным сэмплером стенда (маркер у конца ребра) и DOM-ассертом легенды.
2. **Цвет данных не зависит от темы.** Карта `vizMapping.ts` отдаёт четыре семантических цвета из токенов `--ds-data-*`, одинаковых в каждой теме; тест на три темы утверждает равенство.
3. **Темы:** переключатель предлагает `<дефолт>` и `hud`; `shadcn` недоступен из UI; матрица стенда идёт по двум темам; у дефолтной темы axe `color-contrast` = 0 на всех 25 поверхностях (по `surfaceBaseline.ts`).
4. **Платёж:** луч проходит каждую ногу маршрута не быстрее 450 мс при постоянной скорости, easing только на последней ноге, без паузы между ногами; промежуточные узлы маршрута подсвечиваются на время прохода. Стенд 038 (`motion.qa.ts`, оракул P1–P5) остаётся зелёным; порядок ног проверяется интервалами (`firstLit` текущей ноги ≥ `lastLit − 1` предыдущей).
5. **Цифра суммы:** удаление из DOM при непрозрачности ≤ 0.05 и не раньше конца `--ds-app-floating-label-float-dur`; клиринг — то же (`label-fade.qa.ts` из измерения становится ассертом).
6. **Клиринг:** после `clearing.done` HUD показывает «Общий долг: было X → стало Y» до следующего события, не «0.00» мгновенно; в окне результата и журнале Interact — `display_name`, не A/B/C и не идентификаторы.
7. **Холст:** при 1366×768 с закрытым навигатором доля экрана под холстом ≥ 85 % (сегодня 66–68 %); ни одно окно WM, тост или попап не перекрывает верхний и нижний ряды и другие окна (матрица стенда, правило «rect не пересекает HUD»); навигатор по умолчанию свёрнут в кнопку.
8. **Без GPU:** число `stroke` базовой канвы на кадр при 348 рёбрах ≤ 20 (сегодня ≈350); разбор кадра при CPU ×4 в `qa-perf` показывает медиану кадра ниже 33 мс (сегодня ≈72–80 мс) — записывается как храповик в `e2e/qa/budgets.ts` с датой.
9. **Сопровождение:** `npm run lint` с `typescript-eslint` recommended и `eslint-plugin-vue` flat/essential — exit 0; `sameEquivalent` — единственная точка сравнения (grep inline-копий = 0 вне неё); копия снимка в layout переносит все поля; мёртвый CSS, экспорты, скрипт и конфиг удалены; `useSimulatorApp.ts` без неиспользуемых локалов, без динамического импорта и без `flash` в реактивном состоянии.
10. **Стенд 038 доведён:** отчёт гейта грузится всегда; детерминированные бюджеты в гейте; отказ R3 при зазоре хорды; галерея и три видео в одном артефакте scheduled job; `test:e2e:qa` либо считается, либо удалён из `package.json`.

## Компоновка — варианты для владельца (П1)

Принцип для всех трёх: **холст главный**, всё остальное — одна полоса сверху, одна снизу, инспектор по требованию. Все варианты собираются из существующих компонентов без нового док-менеджера.

**Вариант A — «две полосы и правая рельса» (рекомендуется).**

```
┌ [Sandbox|Auto-Run|Interact] [сценарий ▾] [▶ ⏸ ↺]        [● SSE] [RUN] [TX 1/1]  [⋯] ┐
│                                                                                      │
│                                 ХОЛСТ (≈88 % высоты)                 ┌─ окно ──────┐ │
│                                                                       │ карточка/   │ │
│                                                                       │ линия/платёж│ │
│                                                                       └─────────────┘ │
│                                                                           [тост]      │
├ ● должен ● ему должны ◌ заморожен ◎ хаб → направление │ Общий долг 48.00 → 0.00 UAH  ┤
└ [Send Payment] [Manage Trustline] [Run Clearing]      [Inspect graph ▾] [Reset view]  ┘
```

Верхний ряд: режим, сценарий и управление раном, статусы, одно меню «⋯» (тема, качество, раскладка, подписи, Admin, Dev). Нижний ряд: легенда и «общий долг было → стало» слева, три действия и навигатор-кнопка справа. Окна WM стыкуются в правую колонку (как сегодня карточка узла), максимум два, тосты в правый нижний угол над рельсой. **Плюсы:** всё находится с первого взгляда, минимальная правка (`TopBar`, `BottomBar`, `ActionBar`, `SystemBalanceBar compact`, якорь окон в `SimulatorAppRoot`), холст ≥ 88 %. **Минусы:** нижний ряд плотный на 1366 px — легенда в компактной форме (точки и слова).

**Вариант B — «левая колонка».** Все органы управления в колонке 260 px слева (режим, сценарий, ран, действия, легенда, общий долг), холст справа во всю высоту, окна WM стыкуются в нижнюю часть колонки. **Плюсы:** холст не прерывается по вертикали, панель растёт вниз, а не вширь. **Минусы:** холст уже на 260 px, перестройка трёх компонентов в один сайдбар (больше кода, ≈400 строк), на 1366 px холсту остаётся ≈80 % ширины.

**Вариант C — «минимум».** Холст во весь экран; одна плавающая «таблетка» внизу по центру с тремя действиями и управлением раном; легенда и «общий долг» — маленькая карточка слева сверху; всё остальное в «⋯». **Плюсы:** самый демонстрационный вид, холст ≈95 %. **Минусы:** статусы и сценарий спрятаны — оценивающему пользователю труднее понять, что происходит; больше новых стилей.

**Рекомендация: A.** Для человека, который оценивает систему, важнее найти всё с первого взгляда, чем выиграть ещё 7 % холста. B и C — если после взгляда на кадры A владелец захочет «чище». Реализуется срезом E после выбора; стенд измеряет долю холста и перекрытия, галерея отдаёт кадры «до/после» в обеих темах.

## Non-goals

- Не смена стека: Canvas 2D + DOM-оверлеи + d3-force остаются. Sigma.js, Cosmos, PixiJS — WebGL-first, без GPU это программная эмуляция, от которой защищается политика §1.9; Cytoscape/G6 — чужая модель данных при 38 тыс. строк своего кода и готовом стенде. Измеримой выгоды нет, потеря измерима.
- Не новый док-менеджер, не drag-and-drop панелей, не адаптивная сетка под телефон (симулятор — настольный браузер, решение 2026-10-10), не пятая тема.
- Не система профилей эффектов (FX_CONFIG уже удалён 034 S8); не анимированные «бегущие» стрелки на всех рёбрах (дорого на софт-рендере).
- Не удаление токенов `shadcn` (заморозка, не удаление); не изменение SSE/REST (П7); не тур и не лента событий (S9).
- Не полный рефакторинг `useSimulatorApp.ts` и четырнадцати `useApp*`-обёрток: только названные точечные правки; слияние пустых обёрток — при следующем касании файла.
- Не замена `scenes.spec.ts`/phase5 проектом `qa` (разные режимы); не тесты на заголовки документов.

## Проверка на переусложнение (§19.2)

1. **Наблюдаемая потеря.** Денежной нет. Потеря — цель владельца: оценивающий пользователь не читает с экрана направление, роли, «было → стало»; плюс ~11 fps без GPU при нагрузке и рывок цифры — оба измерены стендом 038 (`frame-breakdown`, `label-fade`). Ни одна правка не формулируется через свойства самого механизма.
2. **Протокол.** Показывается ровно то, что в `docs/ru/01-concepts.md`: линия доверия направлена от кредитора к должнику (§8 AGENTS.md), долг — `used` по линии, клиринг гасит циклы. Маркер направления рисует именно это.
3. **Противник.** Нет.
4. **Дешевле.** (а) Только легенда без направления — не отвечает «кто кому»; (б) направление цветовым градиентом без маркера — незаметно на тонких линиях при альфе 0.06–0.32 (`vizMapping.ts:44-56`); (в) подсветка маршрута без темпа — луч всё равно гаснет между ногами; (г) dirty-флаг без батчинга — не помогает во время платежа (подсветка на той же канве); **выбрано:** маркер + легенда + четыре цвета, батчинг рёбер первым шагом, dirty-ключ только если батчинг не даст 33 мс.
