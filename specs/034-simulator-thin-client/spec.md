## Problem

После 021 симулятор пишет деньги только через ядро, но остаётся самой крупной и самой слабо структурированной поверхностью репозитория: `app/api/v1/simulator.py` — 3078 строк с бизнес-логикой в хендлерах, `app/core/simulator/` — около 13 тыс. строк с двумя копиями оркестровки клиринга и сидинга, `simulator-ui/v2/src` — 36 тыс. строк продукта и 34 тыс. строк тестов при HTTP-клиенте без таймаута и корреляционного id.

Наблюдаемый вред — не денежный (писатель долгов один; `T3400` подтвердил: повтор `tx_id` с совпавшим отпечатком возвращает сохранённый результат **без** нового денежного эффекта, `payments/service.py:952`, `:1277`), а в честности экрана и стабильности рана:

- после рестарта рана платёж с совпавшей парой и суммой показывается как проведённый, хотя деньги не двигались (F-034-1);
- проглоченная ошибка PostgreSQL в построении визуального патча или в планировочном чтении долга/точности отравляет денежную транзакцию, и следующие платежи тика падают с `25P02`, уходя в бюджет ошибок рана (F-034-2);
- зависший REST-вызов из UI держит интерфейс в busy без предела, ошибку из UI нельзя найти в логе (F-034-15);
- артефакты не чистятся, потеря событий очереди не считается (F-034-8).

Всё это — класс 2 по §19.5. Авторизация рефакторинга без воспроизведённой потери требует явного продления исключения «упрощение ядра — цель» (решение владельца 2026-09-24, покрывало 018–021; `specs/README.md`, п. 4) на симулятор — вопрос П1. Узкие починки F-034-1, F-034-2, F-034-8, F-034-9, F-034-15 в продлении не нуждаются: у них наблюдаемый вред и репродьюсер.

### Демо-режим по цели владельца (2026-10-08)

Цель владельца, дословно: «наглядно показать посетителям, как проходят транзакции, как осуществляется клиринг, происходит списание долгов, взаимодействие между узлами и их роли, и дать пользователю понимание, как работает система взаимозачётов и списания взаимных долгов». Это **продуктовая** ось спеки, отдельная от сопровождаемости выше: находки здесь нумеруются `F-034-D*`, чтобы не пересекаться с нумерацией соседнего агента.

Источники (все на `b37f5ef8`): пять read-only агентов Opus (Sandbox по коду и данным; живые режимы по коду, событиям и фикстурам; ядро UI; оболочка и тесты; живые снимки экрана — Vite на порту 5191 с `VITE_DEMO_FIXTURES=1`, Playwright Chromium 1600×900 со скрытым `navigator.webdriver`), перепроверка несущих якорей оркестратором (Fable) и **независимое ревью Codex** по тому же заданию без подсказок (ledger — в Changelog). Codex вернул `VERDICT-DEMO-GOAL: PARTIAL`, `CODE-QUALITY: MIXED`; оркестратор по экрану по умолчанию (Sandbox) оценивает строже — **не выполнено**, по живым режимам — **частично**. Расхождение объяснимо: Codex оценивал сумму режимов, оркестратор — то, что посетитель видит первым. Пометки: ✓ — перепроверено оркестратором чтением кода; ◉ — наблюдалось на живом снимке; △ — чтение агента без перепроверки.

## Current / Intended / Optimal

- **Current.** Симулятор — клиент ядра по деньгам (021), но держит вторую копию оркестровки клиринга, сидинга и периметра в API-слое; строит визуальные патчи и планировочные чтения внутри денежной транзакции; при рестарте повторяет `tx_id`; UI-транспорт без таймаута и id.
- **Intended.** По 021 и `docs/ru/simulator/`: симулятор — демонстрационный клиент домена, все денежные эффекты — через публичные сервисы ядра, SSE — защищённый контракт (§8), runtime-артефакты — под `.local-run/simulator/` с TTL и лимитом (§12), логирование тика — счётчики (§12).
- **Optimal.** Денежная фаза тика содержит только деньги: патчи и планировочные чтения — вне транзакции (патчи после коммита на своей сессии, как клиринг); одна функция клиринга, одна `ensure_seeded`, один `run_perimeter` в core; ключ идемпотентности несёт эпоху рестарта; UI — один транспорт с таймаутом и `request_id`, один resolver выбранной линии в composable с сохранением всех состояний источника. Структурные упрощения (исполнитель, WM, физика, типы) — условные, каждое со своим обоснованием §19.2.
