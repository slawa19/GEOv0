## Problem

Внешнее ревью в проекте — одна система, Codex (`gpt-6-astra`), и один внутренний adversarial-проход агентом той же семьи, что оркестратор (Opus/Fable). Практика показывает, что ни один ревьюер не видит всего: в 039 `T3900` Codex нашёл инверсию ролей узлов в репродьюсере R3, которую пропустили два агента Opus и оркестратор Fable; в 009–010 три круга ревью пропускали посылку, и правильным оказывался третий механизм, которого никто не назвал (AGENTS.md §15). Когда Codex и внутренний adversarial расходятся, у оркестратора нет третьего независимого чтения, и вопрос решается либо стендом (правильно, но не всегда возможно), либо выбором стороны (неправильно). На важных и рискованных срезах (деньги, целостность, механизм проверки, финальная пачка) цена пропуска выше цены ещё одного ревью.

Наблюдаемая потеря — не денежная сейчас, а **риск пропуска класса 1** на защищённых поверхностях §8 и §15 и **расход кругов** на разногласия. Одновременно есть **риск обратной потери**: платный ревьюер, вызываемый по привычке, тратит деньги и время, не прибавляя находок. Поэтому Argon вводится **выборочно и с журналом**, который должен ответить числами, где он полезен, где дублирует, и оправдывает ли затраты.

## Когда вызывать Argon (правило, закрепляется в AGENTS.md §15)

Argon вызывается **только** при одном из трёх триггеров, и триггер записывается в журнал:

1. **Существенное разногласие** между Codex и внутренним adversarial-проходом (Opus/Fable) по находке P1/P2 или по вердикту `READY-*`, которое оркестратор не может разрешить чтением или стендом за разумное время.
2. **Важное и рискованное изменение**: защищённые контракты §8 (OpenAPI, migrations, wire aliases, SSE, денежная семантика), `app/core/payments/`, `app/core/clearing/`, `app/core/recovery.py`, границы транзакций, auth/deps/health/config, механизм проверки (`verify_local.ps1`, `.github/workflows/`, conftest, гарды).
3. **Финальное ревью крупной пачки**: закрытие программы или фазы, в которой изменено несколько модулей либо инвариант, на который опирается код за пределами пачки.

**Не вызывается:** при обычном §15-ревью среза, при мелких исправлениях, при docs-only, для консультации по спеке (если нет триггера 2), как замена Codex, как замена внутреннего adversarial, повторно по тому же fix-delta без нового триггера, из CI. Argon — **не модель по умолчанию**; Codex остаётся основным ревьюером. Решение «звать» принимает оркестратор и записывает причину **до** вызова.

## Консолидированное решение (правило)

При двух и более ревью одной пачки оркестратор составляет таблицу находок: находка → кто назвал (Codex / Opus-Fable / Argon) → воспроизведено ли оркестратором (`path:line`, тест, стенд) → решение (принять / отклонить с причиной / в BACKLOG). Решение принимается **по доказательствам**: находка, названная одним ревьюером и воспроизведённая, принимается; находка, названная тремя и не воспроизведённая, отклоняется. Большинство голосов не является аргументом; расхождение двух чтений — сигнал строить стенд (AGENTS.md §15 «Когда два ревьюера расходятся»). Таблица идёт в Changelog спеки среза и в журнал полезности.

## Журнал полезности ревьюеров (`docs/reviewer-usefulness-ledger.md`)

Версионируемый, одна строка на вызов Argon, заполняется **в том же PR**, где использован результат. Колонки: дата; программа/срез; `<BASE>..<HEAD>`; триггер (1/2/3) и причина одной фразой; модель запрошенная и модель из ответа API; находок Argon всего / сверх Codex и Opus-Fable / подтверждённых оркестратором / ошибочных; повлияло ли на решение (да: какое / нет); время прогона (из `meta.json`); стоимость — число из поля `usage.cost` ответа OpenRouter либо слово `unknown` (выдумывать и оценивать «на глаз» запрещено); токены prompt/completion. Ниже таблицы — раздел **«Текущая оценка»**, который переписывается после каждой записи: для каких задач Argon дал сверх остальных, где дублировал, оправдывает ли затраты; с явной оговоркой о числе наблюдений (при N < 5 — «вывод не делается, наблюдений N»). Следующие сессии читают этот раздел до решения «звать» (ссылка из AGENTS.md §15 и `codex-orchestrator-rule.md` §4.1). Владельцу кратко сообщается после каждого вызова: разница оценок, добавленная польза, итоговое решение.

## Целевое поведение — конечный результат

1. **Один скрипт, одна команда.** `scripts/argon_review.py --base <SHA> --head <SHA> --prompt <file> [--out <dir>]` берёт **замороженный** диапазон из локального git (оба SHA обязаны существовать и быть закоммичены; грязное дерево не участвует), собирает полезную нагрузку: текст промпта (файл копируется в каталог прогона как `prompt.txt` — заморозка промпта), `git diff <BASE>..<HEAD>`, полные файлы, затронутые диффом, на `<HEAD>` (`git show <HEAD>:<path>`), список коммитов диапазона; отправляет один запрос в OpenRouter `POST /api/v1/chat/completions` с моделью из `--model` (дефолт — константа `ARGON_MODEL`, значение подтверждается `T4001` по `GET /api/v1/models` без платы: владелец назвал `openrouter/google/gemini-4-argon`, в API OpenRouter идентификатор без префикса `openrouter/` — проверить и записать), `usage: {include: true}`, `temperature: 0`.
2. **Ключ — только из `OPENROUTER_API_KEY`**, никогда в аргументах, логах, `meta.json`, промпте или выводе; тест-гард подставляет ключ-маркер и проверяет его отсутствие во всех записанных файлах.
3. **Вывод отделён и проверяем:** `.local-run/argon-review/<id>/` содержит `prompt.txt`, `payload.json` (что отправлено, без ключа), `response.json` (сырой ответ), `final.md` (текст ответа), `meta.json` (модель запрошенная, модель из ответа, `id` генерации, `finish_reason`, токены, `usage.cost` или `"unknown"`, время стены, BASE/HEAD, размер нагрузки), `progress.log`. Файлы не коммитятся.
4. **`UNVERIFIED` — явный исход с ненулевым кодом:** HTTP-ошибка, таймаут, `finish_reason` ≠ `stop`, пустой `content`, отсутствие обязательных маркеров (`VERDICT-<TAG>: …`, `CLASS-1-COUNT: N`, `REVIEW-COMPLETE: YES`) в `final.md`. Скрипт печатает причину и `exit 2`; успешный прогон — `exit 0` с маркерами; отказ до отправки (ключ, SHA, размер, секреты) — `exit 3`.
5. **Нарушение целостности — гейт, не лог:** нагрузка больше константы `MAX_PAYLOAD_CHARS` → отказ с подсказкой сузить диапазон или список файлов (`--paths`), **никакого молчаливого усечения**; дифф, затрагивающий пути по шаблонам секретов (`.env*`, `*.pem`, `*.key`, `secrets*`) → отказ; незакоммиченные изменения в диапазон не попадают по построению.
6. **Read-only по построению:** API получает текст и не имеет доступа к файловой системе; скрипт не пишет ничего вне `--out`; ответ модели не исполняется и не применяется автоматически.
7. **Промпт-шаблон** в runbook §5: роль, границы (read-only, не правит), обязательные маркеры, формат находок (severity, `path:line`, repro), и обязательный блок «что уже измерено — оспорьте вывод, не повторяйте замер» (урок волны 012).
8. **Правила закреплены:** AGENTS.md §15 — абзац «Второй ревьюер — Gemini Argon, выборочно» с тремя триггерами, запретом по умолчанию, правилом консолидации по доказательствам и обязанностью вести журнал; строка в матрице «Оркестратор → ревьюер» с пометкой «дополнительно, по триггеру»; runbook §5 — механика; `codex-orchestrator-rule.md` §4.1 — ссылка на журнал как обязательное чтение перед вызовом.
9. **Журнал существует с первой записи «настройка, без вызова»** (дата, что сделано, стоимость 0) и разделом «Текущая оценка: наблюдений 0, вывод не делается».
10. **Тесты без сети** в `tooling-tests/portable/test_p040_argon_review.py`: отказ без ключа; отказ на несуществующем SHA; отказ на превышении размера (мутация «усечь» — красная); отказ на секретном пути; гард утечки ключа; режим `--dry-run` пишет `payload.json` и не делает запрос; режим `--verify-response <file>` на сохранённом ответе: с маркерами — `exit 0`, без маркеров — `exit 2`, `finish_reason: length` — `exit 2`; `meta.json` содержит `cost: "unknown"`, когда в ответе нет `usage.cost` (контрпроверка: с `usage.cost` — число). `EXPECTED_CASES.portable` поднят датированной строкой.

## Non-goals

- Не замена Codex и не изменение путей §2–§3 runbook; не автоматический вызов из CI или из гейтов; не «ревью каждого PR тремя моделями».
- Не агентный режим Argon (без tool-use, без доступа к дереву, без исполнения тестов): это платная **второе чтение**, его ограничения записываются в ledger как ограничения evidence (AGENTS.md §15, последний абзац).
- Не оценка качества моделей вообще: журнал фиксирует наблюдения по этому проекту и запрещает обобщения при малом N.
- Не хранение промптов и ответов в репозитории (только `.local-run/`), кроме строк журнала.
- Не новая зависимость Python; не SDK OpenRouter.
- Не автоматическое заполнение журнала скриптом (строку пишет оркестратор после проверки находок; скрипт лишь печатает готовую заготовку строки с числами из `meta.json`).

## Проверка на переусложнение (§19.2)

1. **Наблюдаемая потеря.** Пропуски ревью воспроизводимы по истории: инверсия R3 в 039 (`T3900`), посылки в 009 (AGENTS.md §15), половина находки F-009-2. Обратная потеря — деньги за бесполезный вызов — предотвращается триггерами и журналом.
2. **Протокол.** Не затрагивается.
3. **Противник.** Нет. Утечка: репозиторий публичный, секреты вне дерева; дополнительно — отказ на секретных путях (п. 5).
4. **Дешевле.** (а) Второй круг Codex — та же модель, те же слепые пятна; (б) `claude -p` — семья оркестратора, не независима (§15); (в) ничего не добавлять — оставляет разногласия без третьего чтения; (г) **выбрано:** один скрипт на stdlib + правила + журнал.
5. **Цена, числом.** Скрипт ≈ 200–280 строк; тесты ≈ 150–200; документация ≈ 120 строк; журнал ≈ 30 строк на старте. Деньги: 0 на настройку; за вызов — неизвестно до первого прогона, пишется из `usage.cost`.
6. **Крайние случаи.** Берутся: ответ без маркеров; обрыв по длине; нагрузка больше лимита; бинарные файлы в диффе (пропускаются поимённо с записью в `meta.json`, не молча); переименования. Не берутся: стриминг; повторные попытки с изменённым промптом (запрещены — заморозка); параллельные вызовы.

**Новые механизмы по §19.1:** 1 инструментальный (скрипт вызова) + журнал (документ). Продуктовых — 0.
